# リファクタリング実践ログ

`development_learning_curriculum.md` 第2部（実践）の続き。**KEM_DDENKI の saas/ を教材に、
リファクタリングを1回ずつ体で覚える**ための記録。

## 進め方

1回につき **座学1つ + 実践1つ + 数字での検証** をセットで行う。1回の差分は小さく保つ
（目安 400 行以下。カリキュラム 第1部 モジュール4 の「小さい PR の原則」）。

各回は次の順で進む。**この順番自体がリファクタリングの作法**なので、崩さない。

```
① 測る      … 直す前の数字を取る（テスト件数・対象箇所数・実行時間）
② 座学      … なぜその直し方が効くのか、原理を1つだけ学ぶ
③ 小さく直す … 1画面・1関数だけ直す
④ 突き合わせる … 直す前と後で、外から見た結果が変わっていないことを機械で確認する
⑤ 記録する   … 判断を ADR に、学びをここに残す
```

## 見つかっている「直しどころ」と、その大きさ

測った結果。**大きい順ではなく、危険が小さい順に着手する。**

| # | 対象 | 規模 | 危険度 | 状態 |
|---|---|---|---|---|
| 1 | フォーム1項目の手書き `form-group` | 401 箇所 / 95 ファイル | 低 | 着手中（第1回） |
| 2 | `<input>` を手書きしてフォーム定義から切れている | 96 箇所 | 低 | 未着手 |
| 3 | 80 行を超える関数 | 55 個（最長 272 行） | 中 | 未着手 |
| 4 | インライン `style=` | 1,835 箇所 | 中 | 未着手 |
| 5 | テンプレート内のインライン `<script>` | 29 ファイル / 6,367 行 | 中 | 未着手 |
| 6 | コメントアウトされたまま残っているコード | 75 箇所 | 低 | 未着手 |
| 7 | 権限判定の二重実装 | `workers/views.py` に6関数 | **高** | 調査のみ（直さない） |
| 8 | mypy strict が設定だけあって CI で動いていない | 3,793 エラー | 中 | 未着手 |

> **7 を直さない理由。** 権限判定は「誰が何を開けるか」そのものであり、寄せた瞬間に
> 開ける人が増減する。これはリファクタリング（振る舞いを変えない作業）ではなく
> **仕様判断**である。見つけた食い違いは報告し、直すかどうかは別途決める。
> — リファクタリングと仕様変更を同じコミットに混ぜない、が最初の規律。
