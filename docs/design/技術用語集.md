## アルファベット順

### A

**API（エーピーアイ）**
Application Programming Interface。アプリの部品同士が「会話」するための窓口。
例: スマホ画面が「今日の日報をちょうだい」とサーバーに頼むと、サーバーが「はいどうぞ」とデータを返す。この「頼む→返す」のルールがAPI。

**App Router（アップルーター）**
Next.jsの画面切替の仕組み。URLとフォルダ構造が一致する設計。
例: `/reports` にアクセスすると `src/app/reports/page.tsx` が表示される。

### B

**BullMQ（ブルエムキュー）**
バックグラウンド処理を管理するライブラリ。「後でやっておいて」リストのようなもの。
例: 「アラートメールを送って」→ リストに追加 → 順番に処理される。

### C

**CRUD（クラッド）**
Create（作成）、Read（読込）、Update（更新）、Delete（削除）の4つの基本操作。
データベース操作はほぼ全てこの4つに分類される。

**CSS（シーエスエス）**
Cascading Style Sheets。Webページの「見た目」を定義する言語。
色、フォント、レイアウト、アニメーション等を指定する。

### D

**DB（ディービー）**
Database（データベース）の略。データを整理して保存する仕組み。
Excelファイル全体に相当。中に複数のテーブル（シート）がある。

**Docker（ドッカー）**
アプリの実行環境を「箱」に詰めて、どこでも同じように動かせる技術。
例: 自分のPCで動いたアプリを、箱ごとサーバーに持っていけば、そのまま動く。

**Docker Compose（ドッカーコンポーズ）**
複数のDockerコンテナ（箱）をまとめて管理する仕組み。
例: PostgreSQL、Redis、MinIOの3つの箱を `docker compose up` の1コマンドで全部起動。

### E

**ER図（イーアールず）**
Entity-Relationship図。テーブル同士の関連を図示したもの。
「usersテーブルとdaily_reportsテーブルは、user_idで繋がっている」等。

### F

**FK（エフケー）/ 外部キー**
Foreign Key。「このカラムの値は、別のテーブルに実在するIDでなければならない」という制約。
例: daily_reports の site_id は sites テーブルに存在するIDでないとエラーになる。

**フロントエンド**
ユーザーが直接目にする部分。画面のデザイン、ボタン、フォーム等。
ブラウザ（Chrome等）の中で動く。

### G

**Git（ギット）**
ソースコードの変更履歴を管理するシステム。「いつ、誰が、何を変えたか」を全て記録。
Wordの「変更履歴」の超強力版。

**GitHub（ギットハブ）**
Gitの履歴をインターネット上で共有・管理するサービス。
コードの保管庫 + 共同開発の場。

**GPU（ジーピーユー）**
Graphics Processing Unit。元々は画像処理用だが、AI計算にも使われる。
AI推論を高速に行うために必要（なくても動くが遅い）。

### H

**HTTPS（エイチティーティーピーエス）**
暗号化された通信プロトコル。URLが `https://` で始まるサイトは通信が暗号化されている。
盗聴されてもデータの中身がわからない。

### I

**インデックス**
データベースの「目次」。検索を高速化するための仕組み。
本の索引と同じ。「PostgreSQL」を調べたい → 索引で「p.234」を見つける → 一発で開ける。

### J

**JSON（ジェイソン）**
JavaScript Object Notation。データを受け渡しするための軽量な形式。
```json
{ "name": "田中太郎", "age": 35, "site": "A現場" }
```
APIでのデータ交換に使われる。

### L

**Let's Encrypt（レッツエンクリプト）**
無料のSSL証明書を発行するサービス。HTTPSに必要な「証明書」を無料で取得・更新できる。

### M

**マイグレーション**
データベースの構造（テーブルやカラム）を変更する仕組み。
「usersテーブルにphoneカラムを追加する」という変更をコードとして記録し、どの環境でも同じ変更を再現できる。

**MinIO（ミニオ）**
ファイル（PDF、画像、Excel等）を保存するためのストレージサーバー。
Amazon S3と同じ仕組みを自社サーバーで動かせる。

**MVC / モジュール**
アプリを「機能の塊」に分割する考え方。
例: 日報管理、原価管理、材料管理 → それぞれが独立した「モジュール」。

### N

**Next.js（ネクストジェイエス）**
React（画面ライブラリ）をベースにした統合フレームワーク。
画面表示 + データ処理 + API を1つのプロジェクトで開発できる。

**Node.js（ノードジェイエス）**
JavaScriptをサーバー側で動かすためのランタイム（実行環境）。
ブラウザの外でもJavaScript/TypeScriptが動くようになる。

**正規化（せいきか）**
データの重複を排除するための設計技法。
「同じ情報は1箇所にだけ保存する」ルールに従ってテーブルを分割する。

### O

**Ollama（オラマ）**
AIモデルを自分のPC/サーバーで簡単に動かせるツール。
`ollama run llama3.1` でAIチャットが自分のマシン上で動く。

**ORM（オーアールエム）**
Object-Relational Mapping。SQLを直接書かずに、プログラミング言語のコードでデータベースを操作する仕組み。
PrismaはTypeScript用のORM。

### P

**pgvector（ピージーベクター）**
PostgreSQLの拡張機能。AI用のベクトル検索（類似検索）ができる。
「この入札案件に似た過去案件を探す」のような検索に使う。

**PostgreSQL（ポストグレスキューエル）**
無料で使えるリレーショナルデータベース。世界で最も高機能なオープンソースDB。
Instagram、Spotify等の大規模サービスでも使われている。

**PR（ピーアール）**
Pull Request。コードの変更を「レビューしてからマージ（統合）する」仕組み。
「この変更を入れていいですか？」と提案 → レビュー → 承認 → 統合。

**Prisma（プリズマ）**
TypeScript用のORM + マイグレーションツール。
テーブル定義をコードで書くと、自動でDBを更新＆型定義を生成する。

**PWA（ピーダブリューエー）**
Progressive Web App。Webサイトをアプリのように使える技術。
ホーム画面に追加可能、オフライン対応（一部）、プッシュ通知対応。

### R

**React（リアクト）**
Webの画面を作るためのJavaScriptライブラリ。Facebook（Meta）が開発。
世界で最も使われているフロントエンドライブラリ。

**Redis（レディス）**
メモリ上で動く超高速データストア。
キャッシュ（一時的なデータ保存）やジョブキュー（タスク待ち行列）に使う。

**レスポンシブ**
画面のサイズ（PC、タブレット、スマホ）に応じて、自動でレイアウトが変わるデザイン。
1つの画面を作れば、PC・スマホ両方で適切に表示される。

**REST API（レストエーピーアイ）**
Webでデータをやり取りする標準的な方法。
GET（取得）、POST（作成）、PUT（更新）、DELETE（削除）の4操作。

### S

**shadcn/ui（シャドシーエヌ ユーアイ）**
UIコンポーネントライブラリ（ボタン、フォーム、テーブル等の部品集）。
「コピペ方式」で自分のプロジェクトに取り込むため、完全にカスタマイズ可能。

**SQL（エスキューエル）**
Structured Query Language。データベースに命令を出すための言語。
```sql
SELECT * FROM daily_reports WHERE site_id = 'A現場' AND report_date = '2026-08-03';
```
（A現場の8/3の日報を取得する）

**SSR（エスエスアール）**
Server-Side Rendering。サーバー側で画面を事前に生成してからブラウザに送る技術。
初期表示が速くなる。

**SSL（エスエスエル）**
Secure Sockets Layer。通信を暗号化する仕組み。
HTTPS通信に必要。Let's Encryptで無料の証明書を取得可能。

### T

**Tailwind CSS（テイルウィンドシーエスエス）**
「ユーティリティファースト」のCSSフレームワーク。
`class="text-blue-500 font-bold p-4"` のように、クラス名で直接スタイルを指定する。

**テーブル**
データベース内の「表」。Excelのシートに相当。
カラム（列）= 項目名、レコード（行）= 1件のデータ。

**tRPC（ティーアールピーシー）**
TypeScript用のAPI通信ライブラリ。サーバーの型定義がクライアントに自動で伝わる。
「サーバーを変更したらクライアント側もすぐエラーが出る」ので、型のズレが起きない。

**TypeScript（タイプスクリプト）**
JavaScriptに「型」を追加した言語。Microsoft開発。
「このデータは数値」「このデータは文字列」と宣言することで、バグを事前に防ぐ。

### U

**UI（ユーアイ）**
User Interface。ユーザーが操作する画面の見た目と操作方法。
ボタン、フォーム、メニュー、アイコン等の総称。

**UX（ユーエックス）**
User Experience。ユーザーがアプリを使った時の体験全体。
「使いやすい」「迷わない」「サクサク動く」等。

**UUID（ユーユーアイディー）**
Universally Unique Identifier。世界で一意の識別子。
`a3b4c5d6-7e8f-9a0b-1c2d-3e4f5a6b7c8d` のような長いランダム文字列。
連番（1, 2, 3...）と違い、推測不可能で衝突しない。

### V

**VPS（ブイピーエス）**
Virtual Private Server。仮想専用サーバー。
レンタルサーバーの一種で、自分だけの独立した環境が使える。ConoHa、さくらVPS等。

### W

**Webhook（ウェブフック）**
イベントが起きた時に自動で通知する仕組み。
例: GitHubでPRがマージされた → 自動でサーバーにデプロイ開始。

### Z

**Zod（ゾッド）**
TypeScript用のバリデーション（入力チェック）ライブラリ。
「この入力は文字列で、5文字以上でなければならない」等のルールを定義・チェックする。
フォーム入力の検証に使用。

**Zustand（ズースタンド）**
React用の軽量な状態管理ライブラリ。
画面間で共有するデータ（ログインユーザー情報等）を管理する。

## 業務用語 → 技術用語 対応表

| 業務で言うと | 技術で言うと | 備考 |
|------------|------------|------|
| Excelファイル | データベース | 全テーブルを包含 |
| Excelシート | テーブル | 44シートある |
| 列の見出し | カラム（列） | name, email 等 |
| 1行のデータ | レコード（行） | 田中太郎のデータ |
| シート間のリンク | 外部キー（FK） | VLOOKUP的なもの |
| マクロ | API + バックエンド | 自動処理全般 |
| 条件付き書式 | バリデーション + UI | 入力チェック + 色分け |
| ピボットテーブル | 集計クエリ | GROUP BY等 |
| 共有フォルダ | MinIO（ファイルストレージ） | PDF/画像の保管 |
| メーリングリスト | 通知基盤 | アプリ/メール/Discord |
