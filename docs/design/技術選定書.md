## 2. 技術スタック一覧

### 2.1 フロントエンド（Django Templates + 軽量JS）

| 項目 | 選定 | 理由 |
|------|------|------|
| **テンプレート** | **Django Templates** | サーバーサイドレンダリング、既存実装を活用 |
| **インタラクション** | **HTMX** | SPAなしでAjax的な部分更新、学習コスト低 |
| **軽量JS** | **Alpine.js** | ドロップダウン、モーダル等の小さなUI制御 |
| **CSS** | **Tailwind CSS** | ユーティリティファースト、レスポンシブ対応 |
| **チャート** | **Chart.js** | 費用推移、消化率棒グラフ、ダッシュボード |
| **ガントチャート** | **frappe-gantt** | 現場単位のバー表示、軽量 |
| **カレンダー** | **FullCalendar** | 配置管理のカレンダー表示 |
| **テーブル** | **django-tables2 + HTMX** | ソート・フィルタ・ページネーション |
| **PWA** | **django-pwa** | スマホでのホーム画面追加 |

### 2.2 バックエンド

| 項目 | 選定 | 理由 |

## 4. 選定理由まとめ

### なぜ Django を継続するのか？
- **既存資産の活用**: 12個のDjangoアプリ、50+テスト、マルチテナント基盤が既に構築済み
- **Python統一**: AI/ML機能（Ollama、OCR、スクレイピング）との連携がネイティブ
- **Django Admin**: 管理画面が標準搭載。マスタ管理、デバッグに即活用可能
- **django-simple-history**: 全モデルの変更履歴が自動記録される（監査対応）
- **LTS（長期サポート）**: Django 5.2 LTSは2028年4月までセキュリティアップデート保証

### なぜ HTMX + Alpine.js？（SPAフレームワーク不要）
- **学習コスト**: React/Vue等のSPAフレームワークを別途覚える必要なし
- **サーバー中心**: ビジネスロジックは全てPython/Django側。JSはUI補助のみ
- **部分更新**: HTMXで「フォーム送信→該当部分だけ更新」が簡単に実現
- **軽量**: フロントエンドのビルドプロセスが不要（CDNから読み込むだけ）

### なぜ Celery？
- **非同期処理が多い**: アラート通知(5種)、スクレイピング、AI見積もり、メール取込
- **定期実行**: 毎朝の資格期限チェック、毎日のKY未記入チェック等
- **Django統合**: Django ORMをそのまま使えるため、DB操作が簡単
- **Redis上で動作**: リトライ・スケジューリングが堅牢

### なぜセルフホスト？
- **AI推論サーバー(Ollama)** をローカルで動かす要件
- **既存インフラ活用**: 192.168.0.35 で既に本番稼働中
- API費用のランニングコストを抑制

## 5. 開発環境セットアップ

```bash
# 前提: Docker, Python 3.12
git clone https://github.com/mstk13/KEM_DDENKI.git
cd KEM_DDENKI/saas

# Docker で起動（PostgreSQL + Django）
docker compose up -d

# マイグレーション
docker compose exec web python manage.py migrate

# テストユーザー作成
docker compose exec web python manage.py createsuperuser

# 開発サーバー（Docker外で開発する場合）
pip install -e ".[dev]"
python manage.py runserver
```

## 6. 現行版からの移行計画

```
現行版（Streamlit/Flask）        次期版（Django SaaS）
192.168.0.35:8080               saas/ ディレクトリ
    │                                │
    │  Phase 1: 日報+人材+権限        │
    │  Phase 2: 原価+材料+工期        │
    │  Phase 3: 入札+取引先+開発      │
    │                                │
    │  全機能が揃ったら               │
    └──── データ移行 ──→ 本番切替 ────┘
```

| Phase | 対象 | 依存 |
|-------|------|------|
| Phase 1 | 通知基盤、日報拡張、権限管理 | なし（基盤） |
| Phase 2 | 原価アラート・可視化、材料完全化、工期可視化 | Phase 1（通知基盤） |
| Phase 3 | 入札強化、人材・取引先拡張、Discord/GitHub連携 | Phase 1+2 |
