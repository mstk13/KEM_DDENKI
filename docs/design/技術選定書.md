## 2. 技術スタック一覧

### 2.1 フロントエンド

| 項目 | 選定 | 理由 |
|------|------|------|
| **フレームワーク** | **Next.js 15 (App Router)** | SSR/RSC対応、APIルートも統合、フルスタック1プロジェクト |
| **言語** | **TypeScript** | 型安全、DB設計44テーブルの型定義を共有 |
| **UIライブラリ** | **shadcn/ui + Tailwind CSS** | コピペ方式でカスタマイズ自由、モジュラーに合致 |
| **状態管理** | **Zustand** | 軽量、ボイラープレート最小 |
| **フォーム** | **React Hook Form + Zod** | バリデーション共有、日報等の複雑フォーム対応 |
| **チャート** | **Recharts** | 費用推移、消化率棒グラフ、ダッシュボード |
| **ガントチャート** | **frappe-gantt or カスタム** | 現場単位のバー表示、軽量 |
| **カレンダー** | **FullCalendar** | 配置管理のカレンダー表示 |
| **テーブル** | **TanStack Table** | ソート・フィルタ・ページネーション |
| **PWA** | **next-pwa** | スマホでのホーム画面追加、オフライン対応 |

### 2.2 バックエンド

| 項目 | 選定 | 理由 |
|------|------|------|
| **ランタイム** | **Node.js 22 LTS** | Next.js統合、TypeScript共有 |
| **API** | **Next.js API Routes + tRPC** | 型安全なAPI、クライアント-サーバー間の型共有 |
| **ORM** | **Prisma** | 44テーブルのスキーマ管理、マイグレーション |
| **認証** | **NextAuth.js (Auth.js v5)** | メール/パスワード認証、ロールベースアクセス制御 |
| **ジョブキュー** | **BullMQ + Redis** | アラート通知、スクレイピング、AI見積もり等の非同期処理 |
| **メール送信** | **Resend or Nodemailer** | 入札期限通知、資格期限通知 |
| **PDF生成** | **@react-pdf/renderer** | 発注書、健康診断結果のPDF出力 |
| **Excel処理** | **ExcelJS** | 発注書Excel出力、見積書Excel読込 |
| **スクレイピング** | **Playwright** | 入札案件の自動収集 |

### 2.3 AI機能

| 項目 | 選定 | 理由 |
|------|------|------|
| **推論サーバー** | **Ollama** | ローカルで簡単に動作、API費用なし |
| **モデル** | **Llama 3.1 8B / Qwen2.5** | 日本語対応、見積もりタスクに十分な性能 |
| **用途1** | テキスト/写真→日報抽出 | OCR + LLMで構造化 |
| **用途2** | 過去実績→入札見積もり | RAG方式で類似案件から金額推定 |
| **OCR** | **Tesseract.js** | 写真・名刺からのテキスト抽出 |
| **ベクトルDB** | **pgvector (PostgreSQL拡張)** | 類似案件検索、追加DBなしで完結 |

### 2.4 データベース・ストレージ

| 項目 | 選定 | 理由 |
|------|------|------|
| **RDBMS** | **PostgreSQL 16** | UUID、配列型、pgvector拡張、実績豊富 |
| **キャッシュ/キュー** | **Redis 7** | BullMQのバックエンド、セッション |
| **ファイルストレージ** | **MinIO** | S3互換、セルフホスト可、PDF/Excel/画像保存 |

### 2.5 外部連携

| 項目 | 選定 | 理由 |
|------|------|------|
| **Discord Bot** | **discord.js** | タスク通知、コマンド操作 |
| **GitHub連携** | **Octokit (GitHub API)** | PR/issue紐づけ |
| **メール取込** | **IMAP (imapflow)** | 入札案件のメール自動取込 |

### 2.6 インフラ・デプロイ

| 項目 | 選定 | 理由 |
|------|------|------|
| **コンテナ** | **Docker + Docker Compose** | 開発・本番環境を統一 |
| **ホスティング** | **VPS (ConoHa/さくら) or 自社サーバー** | コスト管理、AI推論サーバーも同居可能 |
| **リバースプロキシ** | **Nginx** | SSL終端、ロードバランシング |
| **SSL** | **Let's Encrypt (Certbot)** | 無料SSL |
| **CI/CD** | **GitHub Actions** | テスト→ビルド→デプロイ自動化 |
| **監視** | **Uptime Kuma + Grafana** | セルフホスト、アプリ稼働監視 |

## 4. 選定理由まとめ

### なぜ Next.js フルスタック？
- フロント・バックを**1リポジトリ、1言語(TypeScript)**で統一
- 44テーブルの型を Prisma → tRPC → クライアントまで**型安全に一気通貫**
- スマホ対応はPWA化で対応（ネイティブアプリ不要）
- SSR/RSCで初期表示が速く、SEO不要な業務アプリに最適

### なぜセルフホスト？
- **AI推論サーバー(Ollama)** をローカルで動かす要件
- API費用のランニングコストを抑制
- 将来的なデータ量増加にも対応しやすい

### なぜ Prisma + tRPC？
- 44テーブルの**マイグレーション管理**が容易
- API開発時に手動でスキーマ定義を書く必要がない
- クライアントからサーバーまで**自動補完が効く**

### なぜ BullMQ？
- 非同期処理が多い：アラート通知(4種)、スクレイピング、AI見積もり、メール取込
- Redis上で動作し、リトライ・スケジューリングが堅牢

## 5. 開発環境セットアップ（想定）

```bash
# 前提: Docker, Node.js 22, pnpm
git clone <repo>
cd denkiya-app

# 依存関係
pnpm install

# インフラ起動 (PostgreSQL, Redis, MinIO, Ollama)
docker compose up -d

# DB マイグレーション
pnpm prisma migrate dev

# 開発サーバー
pnpm dev
```
