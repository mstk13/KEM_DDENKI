# クラウド移行計画（案C: DB は社内で暗号化、暗号化したバックアップとファイルをクラウド）

社内PCにある個人情報と会社の数字を、**費用を抑えつつ安全に守る**ための計画。
方針は [ADR-0046](../saas/adr/ADR-0046-local-db-encrypted-backup-and-cloud-files.md)（案C）。
当初の「DB をまるごとクラウド」は [ADR-0044](../saas/adr/ADR-0044-cloud-database-and-file-storage.md)（置き換え済み）、
社内AIの扱いは [ADR-0042](../saas/adr/ADR-0042-local-ai-for-planning-and-optimization.md)。

案C は月¥数百で、ディスクの暗号化・固定・クラウドの暗号化バックアップを組み合わせれば、個人情報保護法の安全管理措置として説明できる。
DB が社内にあるので、ネットが切れても社内LANからは入力を続けられる。

## 2. 構成

```
 社内PC（DESKTOP-RMSK0VG）                          クラウド（国内リージョン）
 ┌───────────────────────────────┐              ┌──────────────────────────────┐
 │ アプリ（Django）・社内AI       │   画像・書類   │ ファイル保存先（非公開）        │
 │ DB（PostgreSQL）             │ ───────────▶ │  現場の画像・資格証・健診の書類 │
 │   └ BitLocker で暗号化         │              │                              │
 │ D:\backup（社内のバックアップ） │   暗号化した   │ バックアップの保存先            │
 │   └ BitLocker で暗号化         │ ───────────▶ │  過去の版を残す・削除から保護    │
 │ セキュリティワイヤーで固定       │   DBの写し     │                              │
 └───────────────────────────────┘              └──────────────────────────────┘
```

| 置くもの | 場所 | 守り方 |
|---|---|---|
| DB（氏名・電話・生年月日・時給・評価・原価・入札・日報） | 社内PC | BitLocker・固定・強いログイン |
| 社内のバックアップ（すぐ戻すため） | 社内PCの `D:` | BitLocker |
| 暗号化したDBのバックアップ（別の場所） | クラウド | PC上で暗号化してから送る・過去の版を残す・削除から保護 |
| アップロードファイル | クラウド | 非公開・保存時の暗号化・アプリ経由でだけ表示 |

バックアップは **3か所**（本体の DB・社内の `D:`・クラウド）、**2種類の置き場所**（社内のディスク・クラウド）、**1つは社外**になる。

## 3. 案C の対策と分担

### 3-1. 会社側で行うこと（手順は開発側が用意する）

| # | 対策 | 内容 | いつ |
|---|---|---|---|
| K1 | **Windows のエディションを確かめる** | 設定 → システム → バージョン情報 →「エディション」。BitLocker は **Pro / Enterprise / Education** で使える。Home の場合は「デバイスの暗号化」が使えるか確かめ、使えなければ Pro へのアップグレードを検討 | すぐ |
| K2 | **BitLocker で暗号化** | DB があるドライブ（Docker Desktop のデータの置き場所。Docker Desktop → Settings → Resources → Advanced の「Disk image location」で確認。既定は C: のユーザーフォルダ）と、バックアップの `D:` の両方 | K1 のあと |
| K3 | **回復キーを PC の外に保管** | 印刷して鍵のかかる場所に保管する、など。**無くすと、故障時にデータを取り出せなくなる** | K2 と同時 |
| K4 | **固定** | セキュリティワイヤー（PC の固定用の穴または固定金具）で机・ラックにつなぐ。可能なら施錠できる部屋に置く | すぐ |
| K5 | **ログイン** | 強い Windows のパスワード、離席時の自動ロック、UEFI（BIOS）のパスワードと USB からの起動の禁止 | すぐ |
| K6 | **持ち出しのルール** | 個人情報を USB メモリ・外付けSSDにコピーしない。使う場合は BitLocker To Go で暗号化し、固定する | すぐ |
| K7 | **クラウドの契約と設定** | アカウント作成・支払い・保存先の作成（国内・非公開・過去の版を残す・削除から保護）・社内PC用の「追加だけできる」鍵の発行。画面の手順は開発側が用意し、一緒に確認する | ベンダー決定後 |
| K8 | **バックアップの暗号の鍵（パスフレーズ）を PC の外にも保管** | K3 と同じ扱い。無くすとクラウドのバックアップを戻せない | バックアップ改修時 |
| K9 | **復元の訓練** | 年に数回、手順書どおりに別の DB へ戻して件数を確かめる | 運用開始後 |

**BitLocker の解除方法について**: サーバーPCは Windows Update や自動デプロイで再起動することがあるため、
起動時にPINを入れる方式にすると、再起動のたびに人が入力するまでアプリが止まる。**TPM による自動解除＋強い Windows パスワード＋固定（K4）** の組み合わせを基本にする。
ディスクだけを抜き取られても読めず、PCごと持ち去られても Windows のログインで止まる。

### 3-2. 開発側で行うこと（別 PR）

| # | 作業 | 内容 |
|---|---|---|
| D1 | BitLocker・回復キー・固定の手順書 | 会社側の K1〜K6 を画面の順に書く |
| D2 | バックアップの改修（`scripts/backup.sh`） | DB の書き出し → **PC上で暗号化** → 社内の `D:` に保存 → クラウドへ送信。保存期間（案: 毎日30日分＋毎月1年分）。失敗したら通知 |
| D3 | 復元の手順書（`docs/server_operations.md`） | クラウドから取り出す → 復号 → 別の DB に戻して確かめる → 本番に戻す |
| D4 | ファイル保存先の切り替え | アップロードファイルの保存先をクラウドにする。表示はアプリ経由（または期限つきのURL）。保存ライブラリの追加は依存追加なので ADR を足す |
| D5 | 既存ファイルの移行 | 今の `media_data` のファイルをクラウドへ移すコマンドと、移したあとの件数の突き合わせ |
| D6 | ネット切断時の振る舞い | 画像が表示・登録できないときの画面の出し方（O6 の回答に合わせる） |

## 4. 棚卸し（サーバーPCで実行）

本番のリポジトリの `saas/` で実行する（`docs/server_operations.md` の手動バックアップと同じ場所）。どれも読み取りだけで、データは変えない。

```bash
# DB 全体の容量
docker compose exec -T db psql -U postgres -d kensetsu_saas -c "select pg_size_pretty(pg_database_size('kensetsu_saas'));"

# 大きいテーブル上位15
docker compose exec -T db psql -U postgres -d kensetsu_saas -c "select relname, pg_size_pretty(pg_total_relation_size(relid)) as size from pg_statio_user_tables order by pg_total_relation_size(relid) desc limit 15;"

# アップロードファイルの容量と件数
docker compose exec -T web sh -c 'du -sh /app/media; find /app/media -type f | wc -l'

# バックアップの大きさの推移（増え方の目安）
ls -lh /d/backup/kem_ddenki | tail -30
```

| 項目 | 値 | 使い道 |
|---|---|---|
| DB 容量（圧縮したバックアップ1回分） | | クラウドのバックアップ容量と月額 |
| ファイル容量 / 件数 | | クラウドのファイル容量と月額、移行の時間 |
| 月あたりの増え方（DB / ファイル） | | 3年後の容量 |
| Windows のエディション | | K1 |
| DB があるドライブ / `D:` の空き容量 | | K2 |

## 5. 要件チェックリスト（ファイルとバックアップの保存先）

| 区分 | 要件 |
|---|---|
| 必須 | 国内リージョン（東京または大阪） |
| 必須 | 非公開（公開URLを出さない） |
| 必須 | 保存時の暗号化、通信の暗号化 |
| 必須 | **過去の版を残す**（バージョン管理）と、**一定期間は削除できない設定**（オブジェクトロック・不変ストレージなど） |
| 必須 | 権限を絞った鍵を発行できる（社内PC用は「追加だけ」、復元用は別の鍵） |
| 必須 | 管理画面の二段階認証と操作ログ |
| 必須 | 個人情報（要配慮個人情報を含む）の取扱い、契約終了時のデータ削除が規約・契約で確認できる |
| 望ましい | Django の保存ライブラリが対応している（S3 互換、または Azure Blob） |
| 望ましい | 第三者認証（ISMAP、ISO/IEC 27001・27017 など） |
| 望ましい | 料金の上限アラート、日本語サポート、円建ての請求 |
| 望ましい | 古いファイルを安い保管区分へ自動で移す |

## 6. 料金調査の結果（2026-09-12 時点）

前提: 1ドル＝¥154（2026-09-10）。ドル建ては税抜。AWS・Google Cloud は日本の法人に消費税10%が加わる（Azure は未確認）。
価格は各社の公式の価格表・料金ページから取った。**契約の前に各社の料金計算ツールで取り直す。**

### ファイル・バックアップの保存先（案C で使う）

| 構成 | 月額の目安（10〜50GB） | 注意 |
|---|---|---|
| AWS S3（東京） | ¥40〜190 | ダウンロードは全サービス合計で月100GBまで無料。削除から保護する機能（オブジェクトロック）あり |
| Azure Blob Storage（東日本） | ¥30〜150 | ダウンロードは月100GBまで無料。S3 互換ではないが、Django の保存ライブラリが対応している。不変ストレージの機能あり |
| さくらのオブジェクトストレージ | ¥495〜671（税込） | 削除から保護する機能の有無は未確認 |
| Cloudflare R2 | ¥0〜 | 保管場所を日本に限定できないので要件外 |

案C の月額は、4章の棚卸しで容量が分かれば確定する（ファイル＋暗号化したバックアップで、多くの場合 **¥1,000 以内**の見込み）。
ISMAP: AWS・Azure・Google Cloud・さくらのクラウドは公式に登録を表明している（ISMAP の一覧の原本は未確認）。

## 7. 試験移行（開発環境）

本番のデータは使わず、**開発環境のスタック**（`:8443` / `127.0.0.1:8001`）で確かめる。

| 測ること | 方法 | 合格の目安（案・要合意） |
|---|---|---|
| 画像のアップロードと表示 | 資格証の画像・現場の写真を登録・表示 | 体感で遅くない |
| 既存ファイルの移行 | D5 のコマンドで移し、件数と中身を突き合わせる | 件数・大きさが一致 |
| 暗号化したバックアップ | D2 の改修版で送り、クラウド上の中身が読めない（暗号文）ことを確かめる | 暗号文になっている |
| バックアップから復元 | クラウドから取り出して復号し、別の DB に戻して件数を確かめる | 手順書どおりに戻る |
| 削除からの保護 | 社内PC用の鍵でバックアップを消そうとして、断られることを確かめる | 消せない |
| ネットが切れたとき | 社内PCのネットを切って、日報の入力と画像の表示を試す | 日報は入力できる。画像は O6 の決めたとおりの出し方 |
