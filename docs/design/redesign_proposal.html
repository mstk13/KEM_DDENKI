KEM_DDENKI 業務管理システム画面構成 再設計案 — なぜ使いにくいのか、どう直すのか

機能は揃っているのに画面が分かりにくい。その原因をシステムの構造から特定し、ゼロベースで組み直す案をまとめた。結論を先に言うと：メニューを減らすのではなく、「1つの工事案件」を1箇所で追えるように背骨を通す。

対象：全17機能・249画面の棚卸しに基づく ／ 作成：2026-09-06 ／ 議論用ドラフト

1現状の問題：「同じ工事」が4つの画面系統に分断されている

1件の工事は「入札 → 積算 → 施工 → 原価締め」と流れる。ところが今のシステムでは、この1つの流れが4つの別々の画面系統に分かれていて、担当者は同じ工事を追いかけるために4箇所を渡り歩く。メニューが分かりにくい根本原因は、リンクの数ではなくこの分断にある。

2現状の問題：メニュー45個・ダッシュボード5種・権限3系統

分断のうえに、機能追加のたびにメニューとダッシュボードと権限の仕組みが増えていった。いま起きていることを数字で見るとこうなる。

まとめると：機能が多いこと自体は資産。問題は、機能同士をつなぐ背骨（案件の軸）と、全体をそろえる共通ルール（1つのナビ・1つの権限・1つのデザイン）がないこと。

3再設計案：「案件」を背骨にする

直し方はシンプルで、業務の実態に合わせて「1つの工事案件＝1つのページ」にする。入札・積算・工程・原価は独立メニューから消え、案件詳細ページのタブになる。データベースを作り直すのではなく、今ある4つの仕組みを「案件」で紐づけて1つの画面に見せる（システム内部には既に落札→現場登録の連携があり、土台はできている）。

4メニューはこう変わる：45リンク → 業務6項目＋管理系は権限表示

5アクセス管理：機能ごとの「使える人リスト」に統合する

いま3系統に分かれている権限の仕組み（図2の右）は、機能ごとに「使える人」を追加・削除するリスト方式1本に統合する。メニューも案件ページのタブも、このリストに連動して「リストに入っていない機能は表示自体されない」。管理画面は下のような機能×社員のチェック表にする——縦に見れば「この機能を使える人」、横に見れば「この人が使える機能」が1画面で分かる。

7整理の決定事項

7項目すべて決定済み。使わない機能は畳み、使う機能には新構成の中に正式な置き場所を作った。特に「紙・PDF・Excel を取り込む口」は見積・積算・納品書の3箇所で共通に必要と分かったため、共通の取り込み基盤として設計する（撮影/アップロード → AI読取 → 人が確認 → 登録）。

営業の訪問記録・業種リスト　✔ 決定：2つに分けて残す
来訪した売り込み業者の記録 →「マスタ」の業者名鑑へ ／ こちらから行く営業・商談の進捗 → 案件の「受注前」ステータスとして案件ページに統合
AIの独立画面　✔ 決定：案件に埋め込み、3機能に注力
独立画面は廃止。工程提案・費用最適化・作業員配置の最適化（新規）の3つを案件ページのタブ・ボタンとして提供
材料の在庫管理・調達リスト　✔ 決定：廃止
発注＋納品検収に集約。かわりに紙の納品書をスマホ写真で取り込んでデータ化する機能を追加
見積比較　✔ 決定：取り込み口を新設して活用
紙・Excel運用の見積を PDF / Excel / 写真 で読み込むインターフェースを作り、システム上で比較できるようにする
積算データの受け口　✔ 決定：Excel・PDFの取り込み口を新設
積算ソフトからの Excel、他社からの PDF を内訳書に取り込む受け口を作る（見積・納品書と共通の取り込み基盤）
2種類の日報　✔ 決定：1つに統合
作業内容と出退勤を1つの日報で入力。承認も1回。勤怠集計は統合日報から自動生成
原価の特別な閲覧ルール　✔ 決定：アクセスリストに統合して廃止
対象者を原価のリストに移し、社員番号Gの特例と個別許可の仕組みは撤去する
この資料の使い方：まず図1〜4で方向性の合意を取り、6番の7項目をその場で決める。決まったら詳細仕様（フロントエンド再設計仕様書）に反映して実装に入る。実装は段階的で、既存のデータや業務を止めずに進められる計画になっている。
