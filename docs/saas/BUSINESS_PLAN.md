# 事業計画メモ — 価格・コスト・損益分岐・100社シナリオ

作成日: 2026-08-01 ｜ 関連: `SPEC.md`（システム基本仕様書 v0.2）、`SaaS事業計画_月2社モデル.xlsx`

建設業向けマルチテナントSaaSの事業数値に関する検討結果のまとめ。数値モデルの実体は同名のスプレッドシート（前提シートの青字セルが入力）にあり、本書はその前提と結論を記録する。

---

## 1. 価格決定の基本方針

- SaaSの価格は**コスト積み上げではなく、顧客が浮かせられる金額から決める**。インフラ費は最終的に売上の1割未満に収まるため、原価計算は下限確認にのみ使う。
- 顧客側の置き換え対象: 日報転記・原価集計・Excel管理の事務工数（月30時間 ≒ 6〜8万円相当）、および予実対比による粗利率改善（1%改善で年商2億の会社なら年200万円）。この「浮く金額の1〜2割」が妥当な価格帯。
- 結論: **コア（日報＋工程）月3〜5万円/社、アドオン各1〜2万円**。原価・予実管理は利益改善に直結するため最も高く売れるアドオン。
- 人数課金は緩く（例: 20名まで定額、超過+500円/名）。職人の入れ替わりが多い業界特性への配慮。

## 2. コスト構造

| フェーズ | 月額コスト目安 | 内訳 |
|---|---|---|
| 開発・練習期 | 実質ゼロ〜数千円 | ミニPC（10〜15万円買い切り）＋検証用クラウド少額 |
| 初期 5〜15社 | 2〜5万円 | VPS 1〜2台、バックアップ外部保管、監視 |
| 成長期 15〜50社 | 10〜30万円 | クラウド＋マネージドDB |
| 目標到達 50〜100社 | 30〜80万円 | マネージドコンテナ／オートスケール |

- ミニPCは開発・検証・デモ用途に限定し、本番ホスティングには使わない（仕様書§8）。
- 練習段階から本番と同じ形（Docker + PostgreSQL + 環境変数設定）で動かし、クラウド移行を「置き場所の変更」だけにする。
- **真の原価はインフラではなく3人の人件費。** ここを原価に入れずに黒字と誤認するのが最多の失敗パターン。

## 3. 人件費と配分の方針

- 目標: 1人50万円 × 3名 = **月150万円**を実績に応じて配分。
- ただし初年度から満額は資金的に不可能なため段階制とする:
  - 抑制期（〜30社）: 各30万円（合計90万円/月）。差額は「未払い配分」としてプール可
  - 満額期（30社〜）: 各50万円（合計150万円/月）
  - それ以降: プール清算＋実績配分の上乗せ
- 実績配分の設計原則:
  1. 短期の個人実績（獲得数・開発量）で測らない。解約防止・ドキュメント・サポート等「数字に出ないが解約率を決める仕事」が死ぬ
  2. **基本給＋会社利益連動の2階建て**。変動部分はMRR成長と解約率という会社全体の数字に連動
  3. 配分ルールは書面化して全員署名。持分にはベスティング（4年・1年クリフ）を設定
  4. 役員報酬は定期同額給与の制約があり月次変動は不可。**器の設計は税理士に事前相談**（事前確定届出給与・業務委託併用等）

## 4. 損益分岐の目安（人件費150万円/月を計上）

| 単価/社・月 | 必要社数（インフラ5万） | 必要社数（インフラ20万） |
|---|---|---|
| 3万円 | 52社 | 57社 |
| 4万円 | 39社 | 43社 |
| 5万円 | 31社 | 34社 |

- 単価が1〜2万円違うだけで必要顧客数が約20社変わる。**初期の安売りがそのまま生存条件を悪化させる。**
- 何社で食えるかは価格より先に「自分たちの人件費をいくらで置くか」で決まる。

## 5. 基準シナリオ: 月2社獲得（36か月モデル）

前提: 単価5万円 / 導入支援20万円/社 / 解約率1.5%/月 / 抑制期90万→30社で150万円 / インフラは社数連動（§2の区分）

| 指標 | 結果 |
|---|---|
| 単月黒字化 | 6か月目（12社） |
| 投資回収（累計損益プラス） | 13か月目 |
| 必要資金の最大値 | ▲150万円 |
| 満額配分への切替 | 16か月目（30社） |
| 24か月後 | 41社 / MRR 205万円 |
| 36か月後 | 53社 / MRR 265万円 / 営業利益 月100万円 |

この結果を成立させている3条件（どれか欠けると大きく崩れる）:

1. **導入支援20万円/社が初期の生命線。** 0円にすると必要資金は▲900万円超、投資回収は2年超に悪化。「導入支援を有料で売れるか」が最重要変数
2. 抑制期30万円/人を約16か月、3人が生活として耐えられること
3. 月2社獲得を継続できること（36か月で累計70社超の商談母数が必要）

## 6. 100社シナリオ

### 100社定常時の月次損益（単価5万円）

| 項目 | 金額 |
|---|---|
| MRR | 500万円 |
| 費用（インフラ50万＋人件費150万＋経費5万） | 205万円 |
| 月次営業利益 | 約300〜335万円 |
| **年間営業利益** | **約3,600〜4,000万円**（営業利益率60%超） |

満額配分後もこの利益が実績配分の原資となり、1人あたり年1,000万円規模の上乗せが可能な水準。会社の売却価値も一般則（ARRの3〜5倍）で2〜3億円規模が視野に入る。

### 到達可能性

| 獲得ペース | 100社到達 | 備考 |
|---|---|---|
| 月2社 | 約7年（83か月） | 終盤は獲得2社のうち1.5社が解約補充に消える |
| 月3社 | 約3年半（44か月） | 営業リソース確保が前提 |
| 月2社・解約率2% | **到達不能** | 定常上限が100社ちょうどで漸近 |

**定常状態の社数上限 = 月間獲得数 ÷ 月次解約率。** 100社という目標は、営業目標である以上に「解約率を1%台前半に抑え続ける目標」である。

## 7. 利益をつくる順番（行動方針）

1. 初期は**導入支援費（1社10〜30万円）で稼ぐ**。マスタ整備・データ移行・定着支援。収益の柱かつ解約率低減策
2. 年間契約前払い＋若干の割引でキャッシュを先行させる
3. 最初の5社に深く伴走し**解約ゼロの実績を作る**。値上げより解約率がLTVに効く（解約2%/月なら平均継続50か月、LTV=月額×50）
4. 30〜50社（単月利益の安定後）で**カスタマーサクセス1名を採用**。人件費+30〜40万円/月でも、解約率0.5%改善で定常上限が数十社伸びるため採算が合う
5. 50社の手前でマネージドDBへ移行（仕様書§8の成長期フェーズと整合）

## 8. 主要リスクと監視指標

| リスク | 監視指標 | 対応 |
|---|---|---|
| 導入初期の「使いこなせず解約」 | 導入後3か月の利用率・解約 | 導入支援の標準化、日報UXの継続改善 |
| 獲得ペース鈍化 | 月間商談数・受注率 | 単価維持を優先し、値引きでの獲得はしない |
| 解約率上振れ | 月次解約率（目標1%台前半） | CS採用の前倒し |
| 資金繰り | 累計損益の最深部（基準▲150万円） | 導入支援の有料徹底、抑制期の延長 |

## 9. 未確定事項

- 解約率1.5%は仮置き。実績が取れ次第、初年度と2年目以降で分けて再推計する
- コア＋アドオンの具体的な価格表（アドオン単位の値付け）
- 実績配分の具体的算式と法人形態上の器（税理士相談後に確定）
- 100社超を狙う場合の増員計画（CS→営業の順を想定）
