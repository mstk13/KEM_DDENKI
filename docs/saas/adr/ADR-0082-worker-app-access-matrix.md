# ADR-0082: 作業員 × 機能 のチェック表を設定画面に置く

## ステータス

採用（2026-09-17）

## コンテキスト

プロダクトオーナーの依頼（2026-09-17）:

> 作業員ごとに表示する機能を設定したいので、そのためのインターフェスを用意してください。
> その設定画面はマトリックス上にして、アクセス可能な機能にしるしを付けるという
> インターフェスにしてください。マトリクスの画面を上下左右にスライドしたときには
> 作業員の名前や機能の名前がそのまま固定されるようにしてください。

今の状態を確かめた。

| 場所 | 中身 |
|---|---|
| `Worker.allowed_apps`（JSON の配列） | **実際に効いている**。`AppPermissionMiddleware` がこれを見て入口で止める |
| 作業員の編集画面「アプリ権限」 | `allowed_apps` を1人ずつ直すチェックボックス。11機能ぶんだけ |
| `permissions.AppAccess`（ADR-0030） | 機能 × 作業員 の1行1マス。**まだ誰も読んでいない**（expand の段階） |
| `/settings/permissions/` | ロール × モジュールの表。ロールは**本番で0件**（services.py の注記） |

「作業員ごとに使える機能」を見渡す画面が無く、1人ずつ編集画面を開いて
チェックを付け直すしかなかった。誰と誰の設定が違うのかも分からない。

## 決定

### 1. 印は `AppAccess` に書く。`allowed_apps` は写す先にする

表のマスは `AppAccess` の1行に対応させる。理由は3つ。

* `allowed_apps` は**空の配列が「制限なし」を意味する**ので、
  「どの機能も使えない」を書き分けられない
* `allowed_apps` は**履歴が残らない**。いつ誰が閉じたのかを後から辿れない
* `AppAccess` の語彙は `app_registry` の1か所だけ。`allowed_apps` の語彙
  （`workers.forms.APP_PERMISSION_CHOICES`）は11機能しか無く、積算・勤怠・
  業者名鑑・通知・設定・AI・書類アラートが**そもそも選べなかった**

ただし入口で止めているのは今も `AppPermissionMiddleware` で、見ているのは
`allowed_apps` のほうである。**印を外しても画面が開けるままでは、設定した意味がない。**
そこで保存時に `allowed_apps` を書き直す。

書き直すのは**この画面で設定が変わった作業員だけ**にする。触っていない人には
一切書かない。1回の保存で全員の `allowed_apps` が動くと、どこで何が変わったのかが
追えなくなり、事故が起きたときに戻せない。

### 2. 写せない機能が4つあることを、画面に書く

| 機能 | 写せない理由 |
|---|---|
| 積算・勤怠・AI | URL に入口の制限（`_PATH_TO_APP`）がまだ無い |
| 書類アラート | `/workers/` 配下で、作業員管理とアプリコードが重なる |

これらは印を `AppAccess` に残すが、画面の開閉はまだ変わらない。
画面の上にそのまま書く。**書かないと「チェックを外したのに開ける」と見える。**

書類アラートを無理に写すと、書類アラートの印を外したせいで
**作業員管理ごと閉じる**。同じアプリコードに2つの機能がぶら下がっているため。

### 3. 白紙からは始めない。最初の1回だけ今の実効権限を写す

`AppAccess` が1行も無い会社が画面を開いたら、`legacy_access_plan`（ADR-0045）で
今の実効権限をそのまま写した行を作ってから表示する。

**白紙の表を出すと、全員がどの機能も使えない状態から付け直すことになり、
うっかり保存した瞬間に全社が閉じる。** ロール権限の画面が初回に
`setup_default_roles` を呼ぶのと同じ考え方。

2回目以降は動かさない。`sync_app_access` を切り替え後に流すと、
画面で直した内容を今の判定で上書きしてしまう。

### 4. 表は縦にも横にもずらし、作業員の名前と機能の名前は動かさない

| | |
|---|---|
| 行 | 在籍中の作業員（社員番号順。一覧・名簿と同じ `sort_workers_by_code`） |
| 列 | `app_registry.APPS` の19機能。並びもそのまま |
| マス | チェックボックス1つ。承認のある機能（日報・原価）は「承認」をもう1つ |

表を包む箱に高さ（`calc(100vh - 300px)`）と `overflow: auto` を与え、
上の見出しは `position: sticky; top: 0`、左の列は `left: 0`、
左上の角は**両方**に固定する。角の重なり順（`z-index: 3`）を一番上にしないと、
横にずらしたときに機能の名前が角の上に乗る。

`border-collapse` は `separate` にする。`collapse` だと固定したセルの罫線が
置き去りになり、スクロール中に線だけが流れていく。

**どのマスを触っているのか分からなくなると、別の人の権限を開けてしまう。**
19列 × 作業員数の表で、見出しが流れるのは誤操作の原因そのものになる。

### 5. 作業員の編集画面からは「直す」を外し、「今どうなっているか」だけ残す

編集画面の「アプリ権限」は消し、使える機能の一覧と、この画面へのリンクに置き換える。

**2か所で直せると、後から直したほうが黙って勝つ。** 編集画面は `allowed_apps` を
直接書いていたので、そちらを保存した時点で `AppAccess` との食い違いが生まれる。

使われなくなった `workers.forms.APP_PERMISSION_CHOICES` / `AppPermissionForm` は
削除する。語彙が4か所に分かれている問題（ADR-0030 の冒頭）が1つ減る。

### 6. 3画面はタブでつなぐ

権限まわりは「ロール権限」「ユーザーロール」「作業員 × 機能」の3画面になった。
サイドバーは「権限管理」1項目のままにし、画面の上のタブ（`SectionTabs`）で行き来する。
入札・積算マスタ・業者名鑑と同じ扱い（ADR-0029）。

サイドバーに3項目並べると、設定グループだけが縦に伸びる。

## 捨てた選択肢

- **`allowed_apps` を直接編集する表にする**: 「何も使えない」を書けず、履歴も残らない。
  語彙が11機能に固定されていて積算・勤怠・AI を設定できない
- **`AppAccess` だけに書いて `allowed_apps` を触らない**: 画面で印を外しても
  何も起きない。設定できたように見えて効かないのが一番たちが悪い
- **ミドルウェアを `AppAccess` に切り替える（ADR-0030 の contract）**: 本番に
  `AppAccess` の行がほぼ無く、切り替えた瞬間に全員が閉じる。写す側で足場を作ってから
- **保存のたびに全作業員の `allowed_apps` を書き直す**: 触っていない人の権限まで
  1回の保存で動く。事故が起きたときに、どの保存が原因か分からない
- **書類アラートを `workers` として写す**: 印を外すと作業員管理ごと閉じる
- **表を縦に長い1画面にして、ブラウザのスクロールに任せる**: 横にずらしたときに
  作業員の名前が消える。列が19ある以上、横も固定しないと意味がない
- **列を機能ではなく役職にする**: 同じ役職でも現場によって使う機能が違う、という
  のが依頼の出発点。役職での制限は `POSITION_RESTRICTED_APPS` に既にある
- **作業員の編集画面にも残して両方から直せるようにする**: 食い違う（決定5のとおり）

## 影響

### モデル・マイグレーション

**無し。** `AppAccess`（ADR-0030）と `Worker.allowed_apps` は既にある。
この PR は画面と、その保存の筋道だけを足す。

### 追加・変更した画面

| 場所 | 内容 |
|---|---|
| `/settings/permissions/apps/` | 作業員 × 機能 のチェック表（新規） |
| `/settings/permissions/` ほか | 3画面をつなぐタブ。画面同士のリンクボタンは外した |
| 作業員の編集 | 「アプリ権限」を「使える機能」（読むだけ）に置き換え |

### 既存データ

* 初めて開いた会社は、今の実効権限を写した `AppAccess` が作られる。
  **その時点では誰の `allowed_apps` も変わらない**（保存するまで書かない）
* 保存すると、設定が変わった作業員の `allowed_apps` だけが書き直される
* 「どの機能も使えない」は `allowed_apps = ["__none__"]` で表す。
  空の配列が「制限なし」を意味するため、空では書けない

### テスト

`tests/test_app_access_matrix.py`（新規）。表の組み立て、印の保存と削除、承認、
`allowed_apps` への写し（全部・一部・ゼロ）、触っていない作業員を書き換えないこと、
初回の写し取りと2回目に動かないこと、写せない4機能、管理者以外は開けないこと、
テナント越境。
