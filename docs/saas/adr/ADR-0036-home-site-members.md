# ADR-0036: ホームの現場カードにその日の参加者（配置と出社予定）を出し、「誰がどの現場へ行くか」の枠をなくす

## ステータス

採用（2026-09-10）。ADR-0032 決定7の「誰がどの現場へ行くか」を置き換える

## コンテキスト

ADR-0032 でホームに「施工中の現場と今週の工程」（現場ごとのカード）と、別の枠の
「誰がどの現場へ行くか」（出社予定の行き先で束ねる）を置いた。同じ現場のことが2か所に分かれて出るため、
2026-09-10、プロダクトオーナーが次のとおり決めた。

> 現場ごとに誰が参加しているかは、その現場のカードの中に出す。「誰がどの現場へ行くか」の枠はなくす。
> 参加者は配置と出社予定の両方から集める。

調べた現状:

| | 内容 |
|---|---|
| 配置（`schedules.Assignment`） | 作業員・現場・開始日・終了日（空なら終わりなし）。「どの現場に何日から何日まで付くか」。現場と FK で紐づく |
| 出社予定（`attendance.AttendPlan`、ADR-0023） | 作業員1人1日1件。区分（出社・現場・直行直帰・在宅・出張・有休・半休・休み）・時刻・「現場名・行先」（`note`、**自由入力で現場と紐づかない**） |
| ADR-0032 の枠 | 出社予定だけを使い、`note` の前後の空白を除いた文字列で束ねていた。配置は「その日に実際どこへ行くか」が分からないとして使っていなかった |

配置だけだと、休み・直行直帰・配置の無い応援が分からない。出社予定だけだと、予定を入れていない日は
現場カードが空になる。両方を合わせる。

## 決定

1. **現場カードに「参加者」を出す**。見出しの下に「参加者: 9/10（木）」と日付を出し、
   前日・今日（今日以外の日を見ているときだけ）・翌日（`?date=YYYY-MM-DD`）と「予定を記入」（日シート
   `attendance:plan_day?date=`）を置く。**今週の工程・マイルストーンは `date` によらず今日を含む週のまま**
   （日を切り替えて変わるのは参加者だけ）
2. **参加者の集め方**
   - 配置: 期間がその日を含むもの（`start_date <= 日` かつ `end_date` が空か `>= 日`）
   - 出社予定: その日の予定のうち区分が**現場・直行直帰・出張**で、行き先（`note`）が現場名と一致するもの
   - どちらも在籍中（`Worker.is_active`）の作業員だけ
3. **行き先と現場名の突き合わせ**。両方を次のとおり揃えてから比べる
   - 揃え方: Unicode NFKC 正規化 → 前後の空白を除く → 空白（全角空白・タブ・改行を含む）をすべて除く → casefold
   - 一致: 揃えた行き先と現場名が**同じ**、または**行き先（2文字以上）が現場名に含まれる**、
     または**現場名が行き先に含まれる**
   - 行き先1文字の部分一致は採らない（「A」「東」のような書きかけが別の現場に当たるため）
   - 突き合わせる相手は**ホームに並んでいる施工中の現場**（最大10件、ADR-0032）。
     **2つ以上の現場に一致する行き先は、どれにも一致しないものとする**（あいまい）

   | 現場名 | 行き先 | 結果 |
   |---|---|---|
   | A社ビル新築 | A社ビル新築 | 一致（同じ） |
   | A社ビル新築 | A社ビル | 一致（行き先が現場名に含まれる） |
   | B工場 | B工場 2階 | 一致（現場名が行き先に含まれる。空白は除いて比べる） |
   | ABC ビル新築 | ａｂｃ　ビル新築 | 一致（全角・大文字小文字・全角空白を揃える） |
   | A社ビル新築 | A | 一致しない（1文字） |
   | A社ビル新築 と A社ビル改修 | A社ビル | 一致しない（あいまい） |

4. **現場ごとに作業員1人にまとめる**。表示は予定を優先する
   - 予定がこの現場と一致 → 予定の区分と時刻（「現場 8-17」「直行直帰 8:30-」）
   - 配置だけで予定が無い → 「配置」
   - 配置されていて、予定が現場へ出る区分でない（有休・半休・休み・在宅・出社）、または一致しない出張 →
     その区分（「有休」）を点線・薄い文字で**控えめに**出す。配置の期間中でも、その日は現場にいないと分かるように
   - 配置されていて、予定の行き先が**別の現場と一致** → この現場には出さない（その日はそちらへ行く）
   - 配置されていて、現場・直行直帰の予定の行き先が一致しない（空など） → 予定の区分と時刻で出す（配置で現場は分かる）
   - 並びは社員番号→氏名の順
5. **一致しない予定を黙って消さない**。区分が現場・直行直帰・出張で、行き先が空・どの現場とも一致しない・
   あいまいな予定は、現場セクションの一番下に1行でまとめる。
   「行き先が現場と一致しない予定: 佐藤 一郎（大阪 支店）、鈴木 次郎（行き先未入力）… 日シートで直す」。
   あいまいなものは「（A社ビル・複数の現場に一致）」と付ける。配置で現場カードに出ている人でも、
   行き先が一致しなければこの行にも出す（行き先を直してもらうため。判定を単純に保つ）
6. **「誰がどの現場へ行くか」の枠をなくす**。あわせて `attendance.plans.build_day_destinations` /
   `DESTINATION_KINDS` / `UNKNOWN_PLACE`、コンテキストキー `day_plan`、CSS の `.home-day-*` を削除する。
   出社・在宅・休みの人の一覧はホームに出さなくなる（出社予定の日シート・タイムラインで見る）
7. 集計はサービス `schedules.services.get_active_sites_with_week_schedule(company, ref_date, limit,
   include_amounts, members_date)` に置く。`members_date` を渡したときだけ、現場ごとに `members`、
   全体に `members_date` と `unmatched_plans` を載せる。クエリは現場・工程・マイルストーン・予定・配置の
   **5回**で、現場数に比例して増えない

## 捨てた選択肢

- **出社予定に現場の FK を足す**: 突き合わせは確実になるが、マイグレーションと出社予定の入力画面
  （月グリッド・日シート・まとめて記入）の変更が要る。今回は自由入力のまま突き合わせ、
  一致しない予定を1行で見せて書き方を直せるようにする。一致しない行が多ければ改めて検討する
- **あいまいな行き先を完全一致・最長一致で1つに決める**: 「A社ビル」が新築か改修かは文字だけでは決まらない。
  誤って別の現場に載るより、一致しない行に出して直してもらう方が害が小さい
- **一致しない出張は出さない**: ADR-0032 の枠では出張の行き先も見えていた。枠をなくしたうえで黙って
  消えると、その日いない人が分からなくなる
- **週の工程も `date` に合わせて動かす**: 日を切り替えるたびに工程の一覧まで入れ替わり、
  「今週の工程」という見出しと合わなくなる。変わるのは参加者だけにし、見出しに日付を出す
- **「誰がどの現場へ行くか」の枠を残す**: 同じ現場の情報が2か所に分かれたままになる
