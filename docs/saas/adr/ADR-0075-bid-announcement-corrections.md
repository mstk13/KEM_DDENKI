# ADR-0075: 公告から読んだ内容を直したら、取り直しで書き換えない／AI で読み直す

## ステータス

採用（2026-09-16）。ADR-0073・0074（入札管理の画面をタップしてその場で直す）の上に足す

## コンテキスト

プロダクトオーナーの依頼（2026-09-16）: 自動スクレイピングで案件を取り込むとき、公告 PDF の中身を読んでガントチャートや案件の詳細を作っている。
**その PDF から読み込んだ内容に不備があるときに直せるようにしたい**。

回答（同日）: 直せる範囲は**日程・締切・本文をすべて**、**手直しを守る**（取り直しで上書きしない）、入口は**詳細画面の欄ごと**、**AI での読み直しを付ける**（確認してから反映）。

並行して別の作業で、入札管理の画面の値を**タップしてその場で直す**仕組みが入った（ADR-0073・0074）。
工事概要・参加要件・参加資格の項目・日付はその場で直せ、重要日程の日付は `schedule_overrides` に持つ手直し（ADR-0022）で直せる。

それでも残っていた穴:

- **直しても取り直しで消える**: `fetch_announcements --force` は工事概要・参加要件・重要日程を空にしてから読み直す。
  人が消した（空にした）項目は、次の取り込みで埋め直される
- どの値を人が直したのかを持っていない（変更履歴を追うしかない）
- **編集画面で入札期限の時刻が消える**: 入札期限は日時（17時まで、など）なのに、まとめての編集画面の欄が `<input type="date">` で、保存すると 0時 になる
- 読み違いの多い案件を、もう一度 AI に読ませる手段が無い

## 決定

### 1. 「人が直した」印（`BidProject.corrected_fields`）

- 直した項目の名前を並べて持つ（`["work_outline", "required_score"]` のように）
- 印を付ける場所:
  - タップしてその場で直したとき（`apps/bids/inline_edit.py` の `save_value`。値が変わったときだけ）
  - まとめての編集画面で保存したとき（変わった項目だけ）
  - AI の読み直しから選んで入れたとき
- 取り込み・取り直しは、印の付いた項目に触らない
  - `fill_missing_fields`: 空でも埋めない
  - `fill_announcement`: 書き換えない
  - `fetch_announcements --force`: 取り直しの前に空にしない
- 印は項目ごと。直していない項目は今までどおり公告から埋まる
- 詳細画面の工事概要・参加要件に「手直しあり」を出す

### 2. 入札期限の時刻

- まとめての編集画面の入札期限を `<input type="datetime-local">` にし、時刻を落とさない
  （その場で直す仕組みは最初から日時で扱っている）

### 3. AI で読み直す

- 工事概要の欄の「AI で読み直す」で、公開文書を Claude に読ませる（ADR-0012 と同じ入口 `announcement_llm.extract_with_llm`）
- **その場では保存しない**。読み取った工事概要・参加要件・必要等級・必要点数を、今の内容と並べて出す
- チェックを入れた項目だけを入れ、印を付ける（人が見て選んだものなので、取り直しで書き換えない）
- 受け付ける項目名は読み直しで出した4つだけ。ほかの項目名を送られても入れない
- 使えないとき（API キー未設定・月の上限・読める文書が無い）は、その理由を画面に出して終わる

## 捨てた選択肢

- **欄ごとの「直す」フォームを別に作る**（この PR の最初の形）: その場で直す仕組み（ADR-0073・0074）と
  同じ画面に2通りの直し方が並ぶ。直す入口はそちらに寄せ、こちらは「直しを守る」側に絞った
- **重要日程の `bid_schedule` を直接書き換える**: ADR-0074 は、公告から読んだ日程は触らず手直しを `schedule_overrides` に持つと決めている。
  日付の直しはそちらで足り、取り直しでも残る
- **手直しを別テーブルに持つ**: 「直した値そのもの」は既に項目に入っているので、印だけを別に持てば足りる
- **AI の読み直しをそのまま保存する**: 読み違いを直すための機能なのに、また読み違いが入る

## 影響

- マイグレーション `bids/0025_bid_corrected_fields`（既定 `[]` の列を足すだけ）。既存の案件は印なしで、次に人が直した項目から守られる
- 新しい依存なし。AI は既存の Claude 呼び出し（月間予算の確認つき）を通す
