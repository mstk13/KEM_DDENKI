# ADR-0057: 作業員の現住所・緊急連絡先・経験年数・血液型・視力・血圧

## ステータス

採用（2026-09-14）

## コンテキスト

プロダクトオーナーの依頼（2026-09-14）: 作業員の編集に、現住所・電話番号・緊急連絡先（氏名・住所・電話番号）・経験年数・血液型・視力・血圧を記入する欄を作る。

回答（同日）:

| 問い | 回答 |
|---|---|
| 誰が見て直せるか | **管理者・事務員・本人だけ**（現住所・緊急連絡先・血液型・視力・血圧） |
| 経験年数 | **数字を入力し、年が経ったら自動で増える** |
| 視力・血圧 | **健康診断の記録ごとに持つ** |
| あわせて入れる項目 | 血液型は **A・B・AB・O から選ぶ**、**緊急連絡先の続柄**、**郵便番号**、**視力の裸眼・矯正** |

電話番号（`Worker.phone`）は前からあり、作業員管理を使える人は誰でも編集画面で見られた。

## 決定

### 1. 項目

作業員（`workers.Worker`）:

| 項目 | 見られる人 |
|---|---|
| 経験年数（`experience_started_on` から計算） | 作業員管理を使える人（今の電話番号・生年月日と同じ） |
| 郵便番号・現住所 | 管理者・事務員・本人 |
| 緊急連絡先の氏名・続柄・郵便番号・住所・電話番号 | 管理者・事務員・本人 |
| 血液型（A型・B型・AB型・O型） | 管理者・事務員・本人 |

健康診断（`workers.HealthCheckup`）:

| 項目 | 見られる人 |
|---|---|
| 視力（右・裸眼／左・裸眼／右・矯正／左・矯正）0〜3.0 | 管理者・事務員・本人 |
| 血圧（上 50〜300／下 20〜200 mmHg、下は上より小さい） | 管理者・事務員・本人 |

作業員の詳細には、視力と血圧をそれぞれ**記録のある一番新しい健康診断**から出す（受診日つき）。
健康診断の一覧（詳細・編集の画面）にも、見られる人にだけ視力・血圧の列を出す。

電話番号は今までどおり、作業員管理を使える人が見られる（詳細画面にも出すようにした）。

### 2. 見られる人（`apps.permissions.services.can_view_worker_private`）

- 社長（`is_president`: superuser・president ロール・役職「社長」）
- 管理者（社員番号 Y 始まり）
- 事務員（`office_staff` ロール）
- IT 担当（役職「Developer」）。システムの管理者として含める（日報の承認・人事評価と同じ扱い。ADR-0039）
- その作業員本人（ログインしているユーザーに紐づく作業員）

見られない人には、**フォームから欄ごと外す**（送られてきても保存しない）。詳細画面ではカードを出さず、コンテキストにも載せない。
作業員の新規登録には本人がいないので、役割だけで判定する。

### 3. 経験年数

- フォームでは「経験年数」を数字で入れる（0〜70）
- 保存するときに**起算日**（今日からその年数を引いた日）に変えて持つ。表示は起算日からの満年数なので、**入力した日から1年ごとに1年ずつ増える**
- 年数を変えずに保存したときは起算日を引き直さない（保存するたびに日がずれないように）。空にすると消える
- 年齢（生年月日から）と同じ計算（`full_years_since`）を使う

### 4. 視力・血圧を健康診断に持つ理由

視力・血圧は測るたびに変わり、いつの値かが大事。健康診断の記録（受診日つき）に持てば、年ごとの変化も残る。

## 捨てた選択肢

- **全員に見せる**: 血液型・視力・血圧は健康に関する個人情報（要配慮個人情報）で、住所・緊急連絡先も現場の全員が見る必要はない
- **経験年数を数字のまま持つ**: 毎年手で直さないと古くなる
- **視力・血圧を作業員に1つだけ持つ**: いつ測った値か分からなくなる。前の値が変更履歴にしか残らない
- **血液型に Rh を持つ**: プロダクトオーナーが A・B・AB・O の4つで選ぶと決めた
- **電話番号も「管理者・事務員・本人」にする**: 今は作業員管理を使える人が見ており、連絡に使っている。変えるなら別に決める
