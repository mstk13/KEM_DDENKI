# ADR-0029: サイドバーを業務グループに並べ替え、関連画面をページ上部のタブにまとめる

## ステータス

採用（2026-09-10）

## コンテキスト

再設計仕様書 v2.0 §2.1 は、業務ナビを「ホーム / 案件 / 日々の記録 / 材料・発注 / ヒト / マスタ」
の6項目に、設定・開発を別枠にすると決めた。サイドバーはこれまで「モジュール名の羅列」で、
ADR-0026（AI分析の撤去）・ADR-0024（勤怠日報の廃止）の後も 11 グループ・約40リンクあった。

| 旧グループ | 項目数 | 問題 |
|---|---|---|
| 現場・日報 / 現場見積もり・材料 | 3 + 2 | 同じ現場の「工程」と「原価」が別グループ |
| 入札・営業 / 営業 | 4 + 3 | 「営業」が二重に見える |
| 積算 | 8 | 案件（積算案件）とマスタ（品目・歩掛など7つ）がフラットに並ぶ |
| 取引先 / 設定 > マスタ管理 | 2 + 1 | マスタが分裂 |

要求定義（`docs/design/redesign_v2_requirements.md` §5）では、並べ替えを
アクセスリストの切り替え（D1）の後に置いていた。しかし並べ替えは URL も権限も変えず、
表示の配置だけを変える。見せ分けが入るまで全員に全項目が見えるのは今と同じなので、
D1 を待つ理由はない。

## 決定

### 1. サイドバーの並び

| グループ | 項目 |
|---|---|
| 🏠 ホーム（単独） | 既存のダッシュボード |
| 案件 | 入札案件 / 積算案件 / 現場管理 / 工期管理 / 現場見積もり・実経費 |
| 日々の記録 | 日報管理 / 出社予定 / 月次サマリ |
| 📦 材料・発注（単独） | 材料・発注 |
| ヒト | 作業員 / 人材評価 / 書類アラート / 人事評価3項目（役職で限定。ADR-0022） |
| マスタ | 顧客 / 発注先 / 業者名鑑 / 積算マスタ / 工種マスタ |
| 設定 | 通知・アラート / 権限管理 / 勤怠設定 / AI利用状況 / AI実行ログ / 変更ログ |
| 開発 | 開発管理 / 目安箱 |

11 グループ・約40リンク → 8 グループ・26 リンク。

- 「マスタ管理」は中身が工種マスタなので「工種マスタ」と呼ぶ（マスタグループ内で紛らわしいため）
- 「勤怠設定」は日々使う画面ではないため「設定」へ
- 「ダッシュボード」は v2.0 の呼び方に合わせ「ホーム」。5種の統合は KPI の選定（要求定義 D8）待ち

### 2. ページ上部のタブ（SectionTabs）

画面数の多い3つは、サイドバーを1項目にし、画面の上にタブを出して行き来する。

| サイドバー項目 | タブ |
|---|---|
| 入札案件 | 入札案件 / 入札ダッシュボード / 入札参加資格 / 単価マスタ / 案件取得 |
| 積算マスタ | 積算品目 / 名寄せレビュー / 発注機関 / 労務単価 / 積算基準・歩掛 / 仕入実績 / データソース一覧 |
| 業者名鑑 | 訪問記録 / 業種別一覧 / 営業ダッシュボード |

入札のタブは v1.1 §4.1「案件取得・参加資格・単価マスタは入札案件画面内のタブへ」、
業者名鑑は v2.0 §3「来訪営業の記録はマスタ > 業者名鑑へ」に沿う。
入札ダッシュボードはこれまでサイドバーに無く、入札一覧のボタンからしか開けなかったので、タブに出した。

**実装**: タブの定義は `navigation.py` の `SECTION_TABS` に置き、context processor が
`section_tabs` を渡し、`base.html` が `{% block content %}` の直前に1回だけ描く。

- 対象の15テンプレートは変更しない。どの画面にタブを出すかは Python の1箇所で決まる
- サイドバー項目の `match` はタブの `patterns()` から作るので、タブを足せばサイドバーの
  active 判定にも自動で反映される（2箇所に同じパターンを書かない）
- スマホ幅ではタブ列を横スクロールにし、タップ領域は 44px（v1.1 §7-5）

## 捨てた選択肢

- **ハブページを新設してカードで各画面へ誘導する**: 1クリック増え、各画面に戻る導線も別途要る。
  既存画面の URL を活かすタブの方が、ブックマークも崩れない
- **各テンプレートにタブの include を書く**: 15枚に同じ行が入り、タブを足すたびに全枚数を直すことになる
- **並べ替えとタブ化を別 PR にする**: 両方とも `NAVIGATION` を書き換えるため、間に
  「マスタに16項目並ぶ」状態が開発環境に出る

## 影響

- 変更: `apps/core/navigation.py`（並び、`SectionTabs` / `build_section_tabs` を追加）
- 変更: `apps/core/context_processors.py`（`section_tabs` を追加）
- 変更: `templates/base.html`（タブの描画）、`static/css/style.css`（`.section-tabs`）
- 変更: `tests/test_core_navigation.py`
- URL・ビュー・権限・データへの影響なし
- 要求定義 §5「1-2 業務6項目ナビ」の着手条件（4.1 の切り替え完了）を外す
