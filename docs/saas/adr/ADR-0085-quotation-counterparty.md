# ADR-0085: 見積の相手先は向き（kind）を見て出す

## ステータス

採用（2026-09-17）

## コンテキスト

現場詳細の材料の項目を揃える作業（ADR-0087）の途中で見つけた。

`Quotation` は2つの向きを同じモデルで持つ（ADR-0017 の見積ファイル取り込みで、
自社発行の見積も同じ形で扱えるように `kind` を足した）。

| 向き | 相手先の入る列 | `supplier` |
|---|---|---|
| `RECEIVED`（仕入先から受領） | `supplier` | 入っている |
| `ISSUED`（自社が顧客へ発行） | `customer` | **空** |

そのため画面で `supplier` を直接読むと、**自社発行の見積で相手先が空欄になる。**
実際に3箇所で起きていた。

| 画面 | 症状 |
|---|---|
| 見積一覧 | 「仕入先」列が空欄 |
| 見積詳細の見出し | `見積-12` の後ろが空（誰の見積か分からない） |
| 見積詳細の情報表 | 「仕入先」行が空欄。しかも `kind` をどこにも出していないため、自社発行かどうか画面から判別できなかった |

**同じ系統のより深い不具合が `compare_quotations` にあった。**
絞り込みが `status__in=["received", "accepted"]` だけで **`kind` を見ていない**。
自社が顧客へ出した見積が「採用」になると、**仕入先どうしの値段比較に自社の見積が
混ざる**（しかも `supplier` が空の行になる）。表示崩れではなく、比較結果が誤る。

`counterparty_name`（向きによって顧客／仕入先を返すプロパティ）は最初から
あったが、使っていたのは現場詳細だけだった。

## 決定

**向きによる出し分けをモデルに集め、画面はそれだけを読む。**

1. `counterparty_name` の docstring に「**画面に相手先を出すときは `supplier` を
   直接読まないこと**」と、そうすると空欄になる理由を書く
2. **`counterparty_label` を足す。** 自社発行なら「顧客」、受領なら「仕入先」を返す。
   見出しを「仕入先」で決め打ちにすると、顧客名に「仕入先」と付いてしまう。
   呼び方の出し分けも1箇所に集める
3. 見積一覧の見出しは **「相手先」**（受領と自社発行が混ざる一覧のため）、
   値は `counterparty_name`
4. 見積詳細は見出し・情報表の両方を `counterparty_name` / `counterparty_label` にし、
   **「見積の向き」の行を足す**（自社発行かどうかが画面で分かるようにする）
5. `compare_quotations` に **`kind=RECEIVED` を足す**。仕入先どうしの比較なので、
   自社発行の見積は入れない

## 捨てた選択肢

- **`{{ q.supplier }}` を `{{ q.counterparty_name }}` に置き換えるだけ**: 今見えている
  3箇所は直るが、次に見積を出す画面を作る人が同じ間違いをする。`supplier` は
  モデルに残る正当なフィールドなので、読めてしまうこと自体は止められない。
  **どこを読むべきかをモデル側に書き、テストで全画面を押さえる**ほうが持つ
- **見出しを「仕入先／顧客」と両方併記する**: 1行に両方出ると、どちらが自分の立場か
  読み取れない。向きは1件ごとに決まっているので、その件の呼び方だけを出す
- **`kind` ごとにモデルを分ける**: ADR-0017 が1つにまとめた理由（明細と材料マスタの
  引き当てはどちらの向きでも同じものを使う）を捨てることになる
- **`compare_quotations` は status だけのままにし、画面側で空行を隠す**: 比較表から
  自社の見積が消えても、**最安値の判定は誤ったまま**になる。絞り込みで直すべき

## 影響

- モデル・マイグレーションの変更なし（`counterparty_label` はプロパティ）
- **`compare_quotations` の結果が変わる**。自社発行の見積が「採用」で混ざっていた
  場合、比較表から消える。混ざっていた比較は誤りだったので、これは修正
- `tests/test_quotation_counterparty.py` で、自社発行の見積の相手先が
  見積一覧・見積詳細・現場詳細のどの画面でも出ることを固定した。
  `supplier` を直接読む書き方に戻すと落ちる
