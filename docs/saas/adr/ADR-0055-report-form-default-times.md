# ADR-0055: 日報を書くときの開始・終了に所定の時刻を最初から入れる

日付: 2026-09-14
状態: 採用

## 背景

日報を書く画面の開始時間・終了時間は空欄から始まり、スマホでは毎回時刻の輪をスクロールして選ぶ必要があった。
「開始は 8:30、終了は 17:30 で始めから表示し、そこから微調整したい」という要望。

## 決定

- 新しく書く画面（`reports:create` の GET）で、開始時間・終了時間に **所定の始業・終業** を初期値として入れる。
  - 会社の勤怠設定（`AttendSettings`）に `standard_start` / `standard_end` が **保存されていれば** その時刻
  - 保存が無い・読めない値なら **8:30 / 17:30**
  - 取り出しは `apps/reports/standard_times.py` の `standard_work_times()` にまとめる
- **編集画面**は保存済みの値をそのまま出す（開始・終了が空の日報に初期値を入れない）。
  入力エラーで戻った画面は送られた値を出す。
- 時刻の入力欄は `format="%H:%M"` で出す（`08:30:00` のように秒まで出すと、端末によって秒の欄が出る）。
- 開始・終了が最初から入っているときは、画面を開いた時点で作業時間を計算して入れる
  （今までは時刻を変えたときだけ計算していた）。
- 作業時間だけの日報を PDF に書くときの範囲の割り出し（ADR-0054）も同じ `standard_work_times()` を使い、
  既定の始業を 8:30 に揃える（画面の初期値と PDF で基準がずれないように）。

### 勤怠設定の既定値を変えない理由

`AttendSettings.DEFAULTS` の `standard_start` / `standard_end`（08:00 / 17:00）は勤怠の早出・残業の計算にも使われている。
既定値を 8:30 / 17:30 に変えると勤怠の集計が変わるので、日報側だけの既定値を持つ。
会社として所定時刻を決めたい場合は勤怠設定に保存すれば、日報の初期値にもそのまま反映される。

## 結果

- 日報を書くとき、開始・終了は 8:30〜17:30 から始まり、違う日だけ直せばよい
- 作業時間だけで書きたいときは、開始・終了を消して作業時間を入力する（従来どおり保存できる）
