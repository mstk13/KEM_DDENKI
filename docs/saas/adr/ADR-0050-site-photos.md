# ADR-0050: 現場写真を、どこの・どのような写真かと一緒に現場ごとに登録する

## ステータス

採用（2026-09-12）

## コンテキスト

プロダクトオーナーの依頼（2026-09-12）:

- 現場ごとに**現地調査や施工状況を写真で撮る**ので、**どこの・どのような写真か**を付けて現場ごとに登録できるようにする
- 現場詳細の「見積もり/実経費」以外の **内訳書・内訳明細書** と **見積内訳** の欄を削除し、**そこに現場写真を登録する画面**を置く
- **材料の受発注** は **見積もり/実経費の下** に置く

これまで写真を残す場所は、納品書の画像（材料）・資格証の画像（作業員）だけで、現場の写真を置く場所が無かった。
現場は電波が弱いことが多く、写真付きの入力は圏外保存（ADR-0048）の優先対象でもある。

## 決定

### 1. データ

モデル `sites.SitePhoto`（`TenantModel`、変更履歴あり、管理画面あり）。

| 項目 | 内容 |
|---|---|
| 現場 `site` | 現場を消すと写真も消える（削除の確認画面に件数が出る） |
| 種類 `kind` | **どのような写真か**。現地調査・施工前・施工中・施工後・その他（既定は施工中） |
| 撮影場所 `location` | **どこの写真か**（必須・自由入力）。例「2F 東側 分電盤」。この現場で使った場所を、よく使う順に候補として出す |
| 撮影日 `taken_on` | 入力 → 写真に記録された撮影日（EXIF）→ 今日 の順に決める。圏外で撮って後から送ると登録日とずれるため |
| メモ `note` | 任意 |
| 写真 `image` | 元の写真を**加工せずに**保存する |
| 縮小画像 `thumbnail` | 一覧用（長辺 480px の JPEG）。写真の向き（EXIF）を直してから縮める。作れなければ空で、元の写真を出す |
| 元のファイル名 `original_filename` | スマホのファイル名（IMG_1234.jpg など） |

- 種類は、まずは固定の選択肢にする。増やしたい種類が出てきたらマスタ化を検討する
- 保存先は `site_photos/<会社>/<現場>/<乱数>.<拡張子>`。会社・現場ごとにまとまるので、あとでクラウドへ移すとき（ADR-0046）に分けやすい。
  ファイル名を乱数にするのは、スマホのファイル名が現場をまたいで重なるのと、名前から他の写真を当てられないようにするため

### 2. 画面

| 画面 | URL | 内容 |
|---|---|---|
| 現場詳細の「現場写真」欄 | `/sites/<id>/` | 種類ごとの枚数（押すとその種類で絞り込んだ一覧へ）・新しい写真 8 枚・「+ 写真を登録」「すべて見る」 |
| 写真の一覧 | `/sites/<id>/photos/` | 種類と、撮影場所・メモの文字で絞り込む。48 枚ずつ。写真を押すと元の写真を別のタブで開く |
| 写真を登録 | `/sites/<id>/photos/new/` | **まとめて 20 枚まで**選び、種類・撮影場所・撮影日・メモを一度に付ける（1 枚 30MB まで）。**圏外なら端末に保存**して電波が戻ったら送る |
| 写真の情報を直す | `/sites/photos/<id>/edit/` | 種類・撮影場所・撮影日・メモを直す（写真の差し替えはしない） |
| 写真を削除 | `/sites/photos/<id>/delete/` | 確認してから消す。**ファイルも消える** |

使える人は、ほかの現場の画面と同じ（ログインした同じ会社の人）。

### 3. 現場詳細の並び

```
基本情報 ／ 原価サマリ
見積もり/実経費（原価を見られる人だけ）
材料の受発注            ← 見積もり/実経費のすぐ下へ移した
見積ファイルからの取り込み（取り込んだ現場だけ）
工程
現場写真               ← 内訳書・内訳明細書と見積内訳の欄を外し、ここに置いた
```

- 「内訳書・内訳明細書」と「見積内訳」は**現場詳細の欄だけを外す**。取り込んだ内訳書のデータ・見積と見積明細のデータは消さない
- 見積の明細は、材料の受発注の見積の行の「明細」から見積の画面で見る
- 内訳書の画面（表形式で編集・ファイルから取り込む・Excel 出力）は URL で開ける状態のまま残す。現場詳細からの入口は無くなる。
  使わないと確定したら、画面とデータの扱いを別に決める（いきなり消さない）

### 4. 写真のファイルの出し方

写真は `/media/` から直接出さず、**ログインした同じ会社の人だけが見られるビュー**（`/sites/photos/<id>/image/`・`/thumb/`）を通す。

- 現場写真には人の顔や、表札・書類など個人の情報が写り込むことがある
- 端末には 1 日控えさせる（`Cache-Control: private`）。共有のキャッシュには置かせない
- あとでクラウドに置く（ADR-0046）ときも、このビューから期限付きの URL へ振り向ければ、画面は変えずに済む

### 5. 削除

写真を消したら（現場ごと消したときも）、写真と縮小画像のファイルを消す。写り込みを理由に消したいことがあるため、ファイルを残さない。
削除が取り消されたときにファイルだけ消えないよう、確定してから消す（`post_delete` → `transaction.on_commit`）。変更履歴の行は残るが、ファイルは開けなくなる。

### 6. 圏外（ADR-0048 の対象に追加）

`/sites/<id>/photos/new/` を `OFFLINE_FORM_PATTERNS` に載せ、ビューに `offline_resendable` を付けた。
何枚かのうち途中で失敗したらどれも登録しない（同じ送信を送り直しても二重にならないようにするため）。

## 捨てた選択肢

- **元の写真を縮小して保存する**（容量を抑える）: 公共工事の写真の提出では加工が認められないことがある。元の写真は残し、一覧は縮小画像で軽くする
- **`/media/` から直接出す**（資格証・納品書の画像と同じ）: ログインしなくても URL を知っていれば開けてしまう
- **撮影場所を選択肢にする**: 現場ごとに場所がまったく違う。自由入力にし、その現場で使った場所を候補に出す
- **写真を工程に紐づける**: 今回の依頼は「どこの・どのような」まで。工程と結びつけたい要望が出たら追加する
- **内訳書・見積内訳のデータや画面を同時に消す**: 欄を外すだけにとどめ、消すかは使われ方を見て別に決める（expand/contract）
