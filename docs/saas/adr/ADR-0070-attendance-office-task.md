# ADR-0070: 出社・在宅・半休の予定に「何を行うか」を入れる

## ステータス

採用（2026-09-16）。ADR-0069（まとめて記入の詳細入力）の続き

## コンテキスト

プロダクトオーナーの依頼（2026-09-16）: 「出社を選んだ場合も何を行うかを選べるようにしてほしい」。

- ADR-0023 の `AttendPlan.KIND_FIELDS` では、現場・直行直帰は「現場名」、出張は「行先」を訊き、
  **出社・在宅・半休は何も訊いていなかった**。出社の予定は「出社する」としか分からない
- 予定1件は `note`（場所・メモ）の列を1つ持つ。現場名・行先はここに入る
- 現場名には登録済みの現場名の候補を出している（ADR-0037）

回答（同日）:

| 項目 | 回答 |
|---|---|
| 候補の決め方 | **これまでに入力した内容を候補に出す**（管理画面での候補の管理はしない） |
| 出す区分 | **出社・在宅・半休**（現場へ出ない働く区分） |
| 出す画面 | **全部**（まとめて記入・マスの詳細ダイアログ・日シート） |

## 決定

1. `KIND_FIELDS` の出社・在宅・半休の `place` を **「作業内容」** にする。列は増やさず、
   現場名・行先と同じ `note` に入れる（「その日どこで何をするか」という同じ情報のため）
2. `KIND_FIELDS` に **`suggest`** を足し、入力欄に出す候補を区分ごとに決める。
   `"sites"`＝登録済みの現場名（ADR-0037）、`"notes"`＝これまでに入れた作業内容、空＝候補なし
3. 作業内容の候補は `work_note_suggestions`（出社・在宅・半休の `note` を新しい順に、
   同じ内容は1つにまとめて20件まで）。**候補にない内容もそのまま入力できる**
4. 画面はどれも `KIND_FIELDS` を読んでいるので、ラベル・表示の出し分けは3画面とも自動で揃う。
   候補（`<datalist>`）の付け替えだけ各画面の JavaScript で行う

## 捨てた選択肢

- **候補を会社ごとの管理画面で持つ**: 使い始めに登録の手間がかかる。実際に入れた内容が候補になれば足りる（回答どおり）
- **決め打ちの候補をコードに持つ**: 会社ごとの言い回しに合わない。変えるたびに開発が要る
- **作業内容の列を `note` と別に足す**: 1件に2つの場所の情報ができ、画面・PDF・集計のすべてで
  「どちらを出すか」の分岐が増える。マイグレーションも要る
- **有休・休みにも出す**: 働かない日に作業内容は要らない

## 影響

- モデル・マイグレーションの変更なし（`note` をそのまま使う）
- すでに入っている出社の予定の `note`（空のはず）はそのまま。候補は入力が増えるほど育つ
