# ADR-0067: 現場ごとの提出書類のリストと、PDF・Excel の保存

## ステータス

採用（2026-09-15）

## コンテキスト

プロダクトオーナーの依頼（2026-09-15）:

- 登録されている現場ごとに、提出する書類のリストを作り、そこに書類を保存したい
- 最初に用意されているリスト以外の書類を追加する場合は、名称をこちらで付けて登録できるようにしたい
- 受け口は PDF と Excel シート

回答（同日）:

| 項目 | 回答 |
|---|---|
| 最初のリスト | 会社の Excel「現場ごとの書類一覧.xlsx」のシートと「別紙添付目次」から作った案（着工時・施工中・完成時・その他の4つに分けた24種類） |
| 足した書類 | その現場だけ。足すときに「次の現場からも最初のリストに入れる」を選べる |
| 1つの書類のファイル | PDF と Excel。PDF・Excel を何件でも置け、差し替え前の版も残す形でよい（再確認で「#143 と同じで」） |
| 提出の状況 | 管理する（状況: 未作成・作成済み・提出済み・不要、提出日・メモ） |

今までの `bids.BidDocument`（入札案件の書類）と `reports.SafetyTemplate`（安全書類のひな型）は、現場の提出書類のリストとしては使えない（前者は入札案件、後者は毎日の記入チェック用）。

## 決定

### 1. モデル（`apps.sites`）

| モデル | 1件の単位 | 中身 |
|---|---|---|
| `DocumentTemplate`（最初のリスト） | 会社 × 書類名 | 時期・並び順・最初のリストに入れるか |
| `SiteDocument`（提出書類） | 現場 × 書類名 | 時期・並び順・状況・提出日・メモ・この現場で足したか・元の最初のリストの書類 |
| `SiteDocumentFile`（ファイル） | 置いたファイル1件 | ファイル・種類（PDF／Excel）・元のファイル名・大きさ・メモ |

- どれも `TenantModel`・変更履歴・管理画面あり
- 時期は `DocumentPhase`（着工時・施工中・完成時・その他）。一覧をこの順に分けて出す

### 2. 最初のリストの写し方

- 会社に `DocumentTemplate` が1件も無ければ、既定の24種類を入れる（外した行も「ある」に数え、全部外した会社に既定を戻さない）
- **現場の書類の一覧（または現場詳細）を初めて開いたときに**、そのときの最初のリストを現場へ写す。写すのは1回だけ
- あとで会社のリストを変えても、**写し済みの現場は変わらない**（次に開く現場から変わる）。進行中の現場に急に書類が増えたり消えたりしないため
- 最初のリストの名前・並び順・入れる／外すは管理画面で変える

### 3. 書類を足す・消す

- リストに無い書類は、名前（前後と続いた空白は詰める）と時期を入れて足す。同じ現場に同じ名前は足せない
- 「次の現場からも最初のリストに入れる」を選ぶと `DocumentTemplate` にも足す（外してあった同じ名前の行は戻す）
- **足した書類は消せる**（置いたファイルも消える）。**最初のリストの書類は消せず**、この現場で要らなければ状況を「不要」にする
  - 写し済みかどうかを「書類が1件でもあるか」で判定できるようにするため
  - 「不要」は進み具合の数（提出済み N / 対象 M）に入れない

### 4. ファイル

- 受け付けるのは **PDF（.pdf）と Excel（.xlsx・.xls）だけ**。拡張子に加えて**中身の先頭の形**を確かめる（写真や Word を .pdf にしたファイルを通さない）
  - PDF: 先頭 1024 バイトに `%PDF-`
  - .xlsx: ZIP の中に `[Content_Types].xml` と `xl/`。パスワード付きの .xlsx は ZIP ではなく OLE の入れ物なので、それも通す
  - .xls: OLE の入れ物（`D0 CF 11 E0 A1 B1 1A E1`）
  - マクロ付き（.xlsm）は受け付けない
- 1件 50MB まで、一度に10件まで。1件でも受け付けられなければ、どれも登録しない
- 1つの書類に何件でも置け、新しいものが上。差し替え前の版も残し、要らなければ1件ずつ消す
- ファイルを置くと、状況が「未作成」なら「作成済み」にする
- 保存先は `site_documents/<会社>/<現場>/<乱数>.<拡張子>`。元の名前は `original_filename` に残し、開くときにその名前で返す
- 開けるのは同じ会社のログインした人だけ（`CompanyScopedManager` で引き、他社は 404）。**PDF は画面で開き、Excel はダウンロード**。`Cache-Control: private, no-cache`
- ファイル（書類・現場ごと消したときも）を消すと、保存したファイルも消す（作業員名簿など個人の情報を含むため。削除が確定してから消す）

### 5. 画面

| 何 | どこ |
|---|---|
| 進み具合と、まだ提出していない書類の名前（5件まで） | 現場詳細の「提出書類」の欄 |
| 時期ごとの書類のリスト（状況・提出日・最新のファイル）と「リストに無い書類を足す」 | `/sites/<id>/documents/` |
| ファイルの登録・一覧・削除と、状況・提出日・メモ（足した書類は名前も） | `/sites/documents/<id>/` |
| ファイルを開く | `/sites/documents/files/<id>/` |

- URL は現場と同じ `sites` の名前空間（サイドバーの「現場管理」が選ばれたままになる）
- 圏外での保存（ADR-0048）には入れない。事務所で扱う書類で、ファイルが大きいため

## 捨てた選択肢

- **会社のリストを変えたら、進行中の現場にも足す／消す**: 現場ごとに出す書類は発注者で違い、途中で勝手に変わると困る
- **1つの書類に1ファイル（置き直したら上書き）**: 「PDF と Excel の両方」「差し替え前の版」を残せない
- **ファイルの形を拡張子だけで見る**: 別の形式のファイルに拡張子を付けただけのものが通る
- **新しいアプリに分ける**: 現場の一部の情報で、現場写真（ADR-0051）と同じく `apps.sites` に置くほうが URL・権限・削除の扱いが揃う

## 影響

- マイグレーション `sites/0007_site_documents`: テーブルの追加だけ
- 見られる人は現場と同じ（同じ会社のログインした人）。作業員名簿など個人の情報を含む書類もあるので、見る人を絞る必要が出たら別に決める
- 新しい依存なし（Excel の中身は読まず、形だけ確かめる）
