# ADR-0084: 同じ現場の二重登録を、登録後に見つけてまとめる

日付: 2026-09-17
状態: 採用

## 背景

ADR-0077 で、現場名を入力している途中に似た名前を出すようにした。それでも
二重登録は起きる。入力の途中で候補を見落とすこともあるし、何より

    高橋住宅   ／ 高橋アパート

のように**言い方そのものが違う**組は、文字の並びでは似ていない（似ている度合い 0.4）。
一方で

    鮎まつり   ／ 厚木鮎まつり

は文字でも拾える（0.8）。プロダクトオーナーから
「登録後にローカルAIで推論して名称を統一できないか」と相談された（2026-09-17）。

このアプリはローカルの Ollama を既に使っている（埋め込み `bge-m3`、生成 `qwen3:8b`）。
外にデータを出さずに意味の近さを測れる。

## 決定

- **候補を出すところまでが機械の仕事。まとめるかどうかは人が決める**
  （プロダクトオーナーの指示）。統合を間違えると日報・原価・発注が別現場に混ざり、
  元に戻すのが大変なため。
- 候補は3つの手がかりで拾う（`apps/sites/merge_candidates.py`）。
  1. 文字の似ている度合い（ADR-0077 の `name_match`。0.72 以上）
  2. 意味の近さ（`bge-m3` の埋め込みのコサイン類似度。0.80 以上）
  3. まわりの一致（発注先・住所・工期の重なり・現場担当者）
- 拾った組は `qwen3:8b` に「同じ現場か」を判定させ、理由を1文もらう。
  年度違い・その1／その2・工種違いは別の現場と答えるよう指示する。迷ったら別の現場。
- ローカルAIに繋がらないときは、文字とまわりの手がかりだけで候補を出す（止めない）。
- 候補は `SiteMergeCandidate` に貯める。人が「まとめる」「別の現場」を選ぶ。
  「別の現場」と決めた組は、次から候補に出さない。
- まとめるときは、現場にぶら下がる 22 種類の行（日報・原価・材料・工期・安全書類など）の
  参照を付け替える（`apps/sites/merge.py`）。
  - 寄せたほうの現場は**消さない**。`Site.merged_into` を立てて残す
  - 付け替えた行の id を候補に記録し、**取り消せる**ようにする
  - 日報のように一意の決まりがある行は、付け替えるとぶつかることがある。
    ぶつかった行は動かさず、画面に「〇件は動かしていません」と出す
- どちらを残すかは人が選ぶ。既定では、ぶら下がる行の多いほうを残す形で並べる。
- 調べ直しは、画面の「いま調べる」と管理コマンド
  `find_site_merge_candidates`（夜間に1回流す想定）の2通り。

## 結果

- 「高橋住宅／高橋アパート」のように、文字では拾えない二重登録も見つかる
- 判定の理由が画面に出るので、人が確かめてから決められる
- 間違えてまとめても取り消せる
- ローカルAIが止まっていても、これまでどおり文字の似ている組は拾える
