# ADR-0011: 入札参加資格の判定と、公告PDFからの要件取り込み

## ステータス

承認

## コンテキスト

参加資格判定は実装されていなかった。`apps/bids/qualification.py` が呼ぶ
`BidProject.check_qualification()` は存在せず（呼べば AttributeError）、
ビューも `qual_check` をテンプレートに渡していないため、画面は常に「未判定」だった。

判定に使えるデータは揃っている。

- 資格マスタ `Qualification` に96件（発注機関・業種区分・等級・経審点・総合点・有効期限）
- 案件側は i-ppi から取り込むが、i-ppi は**参加要件を持たない**。
  要件は情報源URLが指す公告PDFにしか書かれていない

2026-08-14 に実データ（資格96件、i-ppi 実案件12件、公告PDF 11件）で確認した。

## 決定

### 1. 突き合わせは表記ゆれを吸収する

資格マスタと案件で表記が揃っていない。

| | 資格マスタ | 案件（i-ppi） |
|---|---|---|
| 発注機関 | `国土交通省(関東地方整備局)` | `国土交通省関東地方整備局` |
| 発注機関 | `防衛省` | `防衛省北関東防衛局` |
| 業種区分 | `電気設備` / `電気工事` / `電気` | `電気設備工事` / `電気` |
| 等級 | `B` / `Ｄ` / `○` / 空欄 | — |

- 発注機関: 括弧・空白・中黒を落として比較する。前方一致も拾い、
  地方局まで一致した資格を本省だけの資格より優先する
- 業種区分: 末尾の「工事」を落として**完全一致**で比較する。
  部分一致にすると「電気」が「電気通信」に含まれ、
  **電気通信の資格で電気設備工事に参加できると誤判定する**（テストで検出した）
- 全省庁統一資格は物品・役務の資格で発注機関名ではないため、突き合わせから除く

### 2. 公告PDFから工事概要・参加要件を取り込む

情報源URL（`BidProject.source_url`）が指すのは、発注機関のサイトに置かれた
公告PDF、または e-bisc の公開文書サーブレットが返すPDF。
どちらも「番号 + 見出し」で章立てされている。

**章見出しの語彙を並べない。** 発注機関ごとに違う（「工事概要」「業務概要」
「工事の概要」、「競争参加資格」「技術資料等の提出を求める対象者に必要な要件」…）。
「番号 + 空白を含まない短い見出し語」という構造で章を切り、見出しに含まれる語
（概要 / 資格・要件）で分類する。

見出し語に空白を許すと、`４．入札手続等 入札説明書の交付期間及び受 令和８年…`
のような表の行を見出しと誤認して章の切れ目がずれる。

実データ11件で工事概要 10/11・参加要件 10/11。取れなかった1件はフォントに
ToUnicode が無く、テキストが `(cid:NNN)` にしかならないPDF。OCR が要るので
扱わないが、「公告に書いていない」と誤解しないよう判別してログに残す。

### 3. 等級要件は「下限」と「列挙」を区別する

発注機関によって切り方が違う。

- 国土交通省: 「電気設備工事**Ｂ等級又はＣ等級**に認定されている者であること」
  → **列挙**。下限ではない
- 防衛省: 「総合審査数値…が**780点以上**」「経営事項評価数値…が**1,100点以上**」
  → **点数**の下限。等級の指定は無い

列挙を下限として大小比較すると誤判定になる。実際、中部地方整備局の
「三遠南信青崩峠トンネル照明設備工事」はＡ等級の認定が要件だが自社の中部は
Ｂ等級で、区別する前の判定は「参加可」と出していた。

`BidProject` に以下を追加した。

- `required_grades` … 公告が認定を求める等級の列挙（例 `BC`）。集合として判定する
- `required_score` … 総合審査数値・経営事項評価数値の下限。自社の総合点／経審点と比較する
- `required_grade` … 既存。「X等級以上」と下限が明示された場合のみ使う

判定では実際に突き合わせた要件を `checked` に積み、画面に根拠として出す。
突き合わせるものが何も無い場合は「登録があります。等級・点数の要件は公告本文で
確認してください」と返す。**分からないことを分かったように書かない。**

### 4. 抽出は文ではなく文脈窓で見る

PDFのテキストは文の途中で改行され、括弧の中にも「。」が入る
（`以下「防衛省競争参加資格」という。）`）。句点で文に切ると要件が分断される。
該当箇所の前後の文字数で窓を取り、その中に文脈語があるかで判定する。

除外が要る。「工事成績評定点が65点未満」「証明をもって65点以上の工事とみなす」は
過去の工事成績の話で、資格の点数ではない。

共同企業体の構成員向けに緩い点数が併記される場合
（代表者1,100点以上／構成員1,000点以上）は、単体で参加する前提の厳しいほうを採る。

## 結果

- 案件詳細に判定結果・根拠にした自社資格（発注機関／業種／等級／経審点／総合点／
  業者番号／有効期限）・照合した要件が出る。一覧にもバッジが出る
- 実案件12件の判定: 参加可12件（判定根拠つき）、
  資格マスタに無い発注機関（横浜市等のデモデータ）は「要確認」
- 公告の取り込み: 実案件10件で 等級 5/5・点数 3/5
  （残り2件は点数要件が本当に無い案件）

## 残っている限界

- **地方自治体の資格が資格マスタに無い**。国の機関96件のみ。
  「資格なし」と断定せず「マスタに無いだけの可能性がある」と返している
- **(cid) 化したPDFは読めない**。OCR が必要
- 公告の取り込みは相手が官公庁サイトなので、落ちていたり証明書が古かったり
  DNS が引けなかったりする。取れなくても案件取得自体は成功として扱う

## 代替案

- **等級を1フィールドで表す**: 「以上」と「列挙」を区別できず、
  Ａ等級しか持たない会社がＢ・Ｃ指定の案件で参加可と出る。採らない
- **公告を LLM に読ませて要件を抽出する**: 章立てが明確で正規表現で足りる。
  費用と再現性の面で現時点では見合わない。取りこぼしが増えたら再検討する
