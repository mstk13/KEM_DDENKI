# ADR-0040: 日報の開始・終了に日付を持たせ、工程を選択式（標準6種＋手入力）にする

## ステータス

採用（2026-09-11）

## コンテキスト

現場作業の日報（`DailyReportForm`）の開始・終了は時刻（`start_time` / `end_time`）だけで、
夜間工事など日をまたぐ作業は「終了時刻が開始以前なら翌日とみなす」暗黙の扱いで計算していた。
2日以上にまたがる作業や、翌日の昼まで続く作業は正しく表せなかった。

工程は `datalist` による自由入力で、候補は会社で使われている工程名を名前順に出すだけだった。
プロダクトオーナーから次の要望があった（2026-09-11）。

- 開始・終了は時刻だけでなく日付も選べるようにしてほしい（日付をまたいで作業する場合がある）
- 「見積り・現調・施工・試験・追加工事・納入」を選択式で出し、他に追加がある場合は
  入力できるようにしてほしい。新しく入力されたものは次から選択候補に登録してほしい

後者は最初「工種」に対して実装したが、同日に「工種ではなく工程の方で」と訂正があったため、
工種は従来の自由入力に戻し、工程を選択式にした。

## 決定

### 開始・終了の日付

- `DailyReport` に `start_date` / `end_date`（任意）を追加する。`start_time` / `end_time` はそのまま
- 作業時間の計算は `work_period()` に集約する
  - 開始日が空なら日報の日付（`report_date`）を開始日とみなす
  - 終了日が空なら開始日と同じ日とし、終了時刻が開始以前なら翌日とみなす（従来どおり）
  - 終了日があればその日時までを作業時間とする（2日以上でも可）
- フォームは「開始（日付・時刻）」「終了（日付・時刻）」として1行ずつに並べる
  - 開始日・終了日は日報の日付に追従して自動で埋まる（手で変えた日付は残す）
  - 同じ日で終了時刻が開始以前なら、終了日を翌日に直す（画面でも保存時でも同じ扱い）
  - 終了日が開始日より前はエラー
- 事務の日報（`OfficeDailyReportForm`、社員番号 G / S / A / P の人）にも同じ開始日・終了日の欄を置く。
  当初は「1日ぶんの勤務時間を入れるものなので変えない」としたが、プロダクトオーナー（社員番号 G）が
  「日報を書く」を開いて日付欄が無いと報告したため、同日に追加した。日付は勤務時間と同じく最初の現場にだけ入る
- 日付・時刻の整合性の判定は `clean_work_period()` に置き、両方のフォームから呼ぶ

### 工程の選択

- 標準の工程 `STANDARD_PROCESS_NAMES = ("見積り", "現調", "施工", "試験", "追加工事", "納入")` を定める。
  工程（`Process`）は現場に紐づくので事前には登録せず、日報を保存したときにその現場の工程として
  登録する（`_resolve_process`、従来どおり）
- 工程欄は `select` にし、「（なし）」の次に標準の工程をこの順で、続けて会社で使われている工程名を
  名前順に出す（`process_choice_names`）。最後に「その他（新しい工程を入力）」を置く
- 「その他」を選ぶと入力欄（`process_other`）が出る。入力した名前は保存時にその現場の工程として登録され、
  次回から候補に並ぶ
- 送信値は工程名のまま受ける（`process` は `CharField`）ので、候補に無い名前を直接送る既存の経路
  （テスト・API 相当）はこれまでどおり通る。工程は従来どおり任意
- 編集中の日報の工程が候補に無くても、選び直せるよう候補に残す
- 工種は従来どおり `datalist` の自由入力（候補は会社の有効な工種名）。変更しない

## 捨てた選択肢

- **`start_time` / `end_time` を `DateTimeField` に変える**: 出社予定・ホームのガント・AI 助言など
  時刻だけを見る箇所が多く、影響範囲が広い。日付を別欄で足す方が既存データもそのまま使える
- **標準の工程を全現場に事前登録する**: 工程は現場ごとの行なので、現場が増えるたびに6行ずつ増える。
  選ばれたときに登録すれば十分
- **工程を `datalist` のまま候補の順だけ変える**: スマホでは選択肢が出ることが分かりにくく、
  「選択式にしてほしい」という要望に合わない

## 影響

- モデル変更: `apps/reports/models.py`（`start_date` / `end_date`、`work_period()`）、
  マイグレーション `reports/0006_dailyreport_start_date_end_date`
- 変更: `apps/reports/forms.py`（日付欄、`clean_work_period`、工程の選択肢 `process_choice_names`）、
  `apps/reports/views.py`（`process_names` を廃止。候補はフォームが組み立てる）、
  `templates/reports/form.html`、`templates/reports/office_form.html`
- 追加テスト: `tests/test_report_datetime_worktype.py`
- 既存データ: `start_date` / `end_date` は空のまま。空なら従来どおりの計算になる
- 月次サマリ・原価（労務費）は `work_hours` を使うので、計算式が変わらない限り影響なし
