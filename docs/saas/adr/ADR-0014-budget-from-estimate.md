# ADR-0014: 現場見積もり TOP に見積書の受け口を置き、実行予算を起こす

## ステータス

承認

## コンテキスト

現場見積もり/実経費（`costs:list`）の「見積もり」列は `BudgetItem`（実行予算）の
合計である。これまで実行予算は `costs:budget_create` から**1件ずつ手入力**する
しかなく、見積書に明細が並んでいても転記作業が必要だった。

ADR-0013 で見積ファイルの明細パーサ（`apps/sites/line_items.py`）を作ったので、
同じ読み取りを実行予算にも使える。

## 決定

### 1. 受け口は TOP 画面に直接置く

`costs:list` にアップロードフォームを置き、`costs:budget_import` が受ける。
別画面へ遷移してから選ばせると、TOP を見て「予算が入っていない現場」に
気づいた流れがそこで切れる。

対応形式は見積取り込みと同じ PDF / Excel(.xlsx/.xlsm) / CSV。
ファイルの検証は `sites.forms.EstimateUploadForm` を継承して共用する。
読み方を2箇所で持つと、片方だけ直したときに挙動がずれる。

### 2. 工種 × 原価区分は行ごとに選ぶ

`BudgetItem` は `work_type` と `cost_category` が必須だが、**どちらも見積書には
書かれていない**。CLAUDE.md 規律5 は「予算・原価に触れるコードは工種 × 原価区分の
粒度を崩さない」としているので、ここを省略した登録はできない。

受け口で既定値を選び、確認画面では全行にそれが入った状態で出す。行ごとの
`<select>` で変えられる。既定が無いと全行を選び直すことになり、あっても
変えられないと粒度が既定値ひとつに潰れる。

### 3. 分類が欠けた行は登録しない

工種か原価区分のどちらかを引けなかった行は**作らずに飛ばす**。
「未分類」を作って後で直す運用にすると、予実の集計が未分類に吸われたまま
放置される。入っていないほうが、入っていないと分かる。

同じ理由で、確認画面のチェックを外した行も作らない。

### 4. 他社の工種は pk を送られても拾わない

行ごとの選択は pk でフォームを往復するため、`company` で絞った辞書から
引き直して照合する。引けなければその行を落とす（テストで固定）。

### 5. 数量・単価が無い行は 0 で入れ、金額は読み取った値を使う

見積書には「一式」計上のように金額しか無い行がある。`BudgetItem` の
数量・単価は null を許さない（既定 0）ので 0 を入れるが、**金額は読み取った値を
そのまま使う**ので予算合計はずれない。画面にもその旨を出す。

`QuotationItem`（ADR-0013）では null 可にしたが、こちらは予実集計の分母に
なるモデルで、null を許すと集計側の分岐が増える。金額さえ正しければ
目的を果たすので、モデルは変えない判断をとった。

## 結果

- 見積書1つで実行予算をまとめて起こせる。TOP の「見積もり vs 実経費」が
  すぐ意味を持つ
- 明細の合計は見積書の合計欄と一致しないことがある（値引き・消費税は明細に
  含まれない）。ADR-0013 と同じく**明細の和を正とする**
- `bulk_create` は使わず1件ずつ `save()` する。simple-history が履歴を作らないため。
  予算は誰がいつ入れたかを追えないと困る
