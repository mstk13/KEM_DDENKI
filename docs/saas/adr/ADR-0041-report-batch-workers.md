# ADR-0041: 日報のまとめて登録（自分を先にチェック・人ごとの時間・組での反映・事務の人の現場日報）

日付: 2026-09-12
状態: 採用

## 背景

現場では代表の一人がその日の作業員ぶんの日報を書く。作業員を複数選んで
人数分の日報を作る仕組みは ADR 以前（2026-08-12）からあるが、使ってみて
次の不便が出た。

- 自分の日報を書くのに毎回自分をチェックし直す
- 人によって開始・終了が違う（先に上がる、遅れて入る）のに全員同じ時間になる
- 代表者が後で作業内容を直しても、一緒に作った他の人の日報は古いまま
- 社員番号が G / S / A / P の事務の人は「日報を書く」が事務の形式になり、
  現場作業員の日報を代わりにまとめて書けない

## 決定

### 自分を最初からチェック

新規作成の GET で、ログインした人が現場作業の区分（E・T）なら
`workers` の initial に入れる。事務の人が代わりに書くときは本人の日報を
作るのが目的ではないので付けない（右の列にはいるので手で選べる）。

### 人ごとの時間

`DailyReportForm.__init__` で候補の作業員ごとに `start_time_<pk>` /
`end_time_<pk>` を足す。両方入っていればその人だけ共通の時間の代わりに使い、
`work_hours` はモデルの `save()`（`calculate_hours`）で人ごとに出る。
片方だけはエラー。共通の時間が空でも、選ばれた全員に個別の時間があれば通す。

画面ではチェックした人の行にだけ時間の欄を出す（JS で表示切替）。
開始・終了の右に作業時間 `work_hours_<pk>` も置き、開始・終了を入れると JS で
自動計算して見せる。開始・終了が無く作業時間だけ入っていればその値を使い、
その人の日報には共通の開始・終了を入れない（入れるとモデルの `save()` が
そこから計算し直して手入力を上書きするため）。両方あれば開始・終了からの
計算を優先する（共通の欄と同じ扱い）。
日付（開始日・終了日）は共通のまま。人ごとに日付まで違うのは稀で、
その場合は個別に書けばよい。

候補は在籍中の全員。左の列に現場作業の区分（社員番号 E・T）、右の列に
それ以外（事務などで、現場に出ることもある人）を、作業員一覧と同じ
社員番号順で並べる。以前は E・T だけを候補にしていたが、それ以外の人が
現場に出た日の日報が書けなかった。

### 組（batch）と反映

`DailyReport.batch`（UUID、null 可）を追加し、2人以上でまとめて作ったときだけ
同じ値を入れる。1人なら null（反映する相手がいない）。

編集画面で同じ組の日報（承認済みを除く）があれば
「一緒に作った他の作業員の日報にも反映する」（既定でオン）を出す。
オンで保存すると `BATCH_SHARED_FIELDS`（現場・工種・工程・日付・天候・作業内容・
協力会社・その他）を同じ組の日報に写す。

時間は別扱い: **編集前のこの日報と同じ時間だった人だけ** 新しい時間に揃える。
人ごとに変えてあった時間を、代表者の編集で上書きしないため。

承認済みの日報は労務費を計上済みなので触らない。現場・日付・工種を変えた結果
その人の別の日報とぶつかる（unique_together）ものは飛ばして警告する。

状態（下書き / 提出済）は写さない。提出は各自の日報ごとの行為のため。

### 事務の人が現場作業員の日報を書く

`reports:create` に `?mode=field` を付けると、事務区分の人でも現場作業の
フォームを出す。事務のフォームの見出しにそのリンクを置く。
事務の人自身は右の列に出るが、最初からチェックはされない。

### 事務区分の判定

従来どおり社員番号の先頭（G / S / A / P）で決める。社員番号が空の人だけ、
職種・役職の名前に「事務」が入っていれば事務とみなす。
社員番号が入っていればそちらを優先し、職種名では変えない
（番号で運用が決まっているところに、名前の揺れで判定が変わらないように）。

## 結果

- 代表者の 1 回の入力で、人ごとの時間まで含めて全員の日報ができる
- 後から直したときも組の日報が揃う。個別に変えた時間は残る
- 事務の人も現場の日報を代わりに書ける
- マイグレーション `reports/0007_dailyreport_batch`。既存の日報は batch が null で、
  反映の欄は出ない（従来どおり個別に編集する）
