# ADR-0009: 入札案件の詳細取り込みと工事種別フィルタ

## ステータス

承認

## コンテキスト

入札案件詳細画面が「-」ばかりで、案件そのものの情報が読めない状態だった。
原因は取り込み側にある。

- i-ppi の検索結果テーブル（`#dgrSearchList`）が持っているのは
  **発注機関／工事名／入札契約方式／工事区分／公告日** の5項目だけで、
  工事場所・入札期限・開札日は一覧に存在しない。
- 一覧の案件リンクは `javascript:__doPostBack('dgrSearchList','$N')` で、
  URL にならない。よって `source_url` が常に空になっていた。
- 詳細ページの巡回は「締切日が取れていない案件だけ」に限っていたため、
  締切以外の項目はそもそも取りに行っていなかった。

また、自社（電気設備・機械設備）が施工しない土木・舗装系の案件が
そのまま取り込まれ、一覧のノイズになっていた。

2026-08-14 に i-ppi の実データ（工事区分＝電気設備工事／建築工事）で
DOM 構造と表記を確認した。

## 決定

### 1. 詳細ページを全件巡回し、案件概要を取り込む

詳細ページの案件概要は `#tblDataHdr` の「ラベル / 値」2列テーブル。
ラベル名で引いて `BidProject` の項目に対応づける
（`DETAIL_LABEL_MAP`）。取り込む項目:

担当部・事務所 / 工事場所 / 入札契約方式 / 設計書番号 / 公告日時 /
期限日時 / 開札日時 / 電子入札対象 / 予定価格

対応づけできなかった項目を黙って捨てないよう、案件概要の原文を
`BidProject.summary` にそのまま保存し、詳細画面に表示する。

巡回コストは変わらない。従来も締切が空という理由で結局は全件を開いていた。

### 2. 情報源URLは「公開文書」のリンクを使う

案件詳細そのものは `Koji/Kokoku/List.aspx?tab=3` という全案件共通のURLで、
セッション状態に依存するため保存しても再訪できない。

一方、詳細ページの「公開文書（入札公告等）」のリンクは案件ごとに変わる
絶対URLで、発注機関のページ（例: `moj.go.jp/...`）または e-bisc の
公開文書サーブレット（`AnkenKanriNo` を含む）を指す。これを
`source_url` として保存する。

`source_url` は `max_length=500` に拡張した。既定の200では
`AnkenKanriNo` 付きのURLが入らない。

### 3. 工事種別の除外は部分一致で行う

i-ppi の工事区分は発注機関ごとの自由記述で、
「建築工事及び土木工事」「建築一式工事（電気設備工事、機械設備工事含む。）」
のように1つの文字列に複数種別が入る。完全一致では判定できない。

- 除外語（`EXCLUDED_CATEGORY_KEYWORDS`）:
  一般土木工事 / 土木工事 / アスファルト舗装工事 /
  セメント・コンクリート舗装工事
- 例外語（`INCLUDED_CATEGORY_KEYWORDS`）: 電気設備工事 / 機械設備工事

例外語を含む場合は除外語を含んでいても取り込む。
「建築一式工事（電気設備工事、機械設備工事含む。）」を捨てないため。

判定は `apps.bids.models.is_excluded_category()` の1箇所に置き、
`ScrapeTarget` の工事区分・業種の選択肢も同じ関数を通して生成する
（`_selectable()`）。選択肢と取り込みフィルタが食い違うと
「選べるのに1件も保存されない検索条件」ができてしまう。

既存の `ScrapeTarget.koji_kbn` に除外対象が入っている場合は
マイグレーション `0010_clear_excluded_koji_kbn` で空にする。

## 結果

- 案件詳細画面に発注機関・担当部・工事場所・入札契約方式・電子入札対象・
  設計書番号・公告日・入札期限・開札日・情報源URL・案件概要原文が出る。
- 実サイトに対する通し確認（2026-08-14, 3件）で全項目 3/3 取得。
- 編集画面に出ていない項目は保存時に空で上書きされるため、
  `BidProjectForm` に追加した項目は `project_form.html` にも描画し、
  取りこぼしをテストで固定した。

## 代替案

- **案件概要をJSONで1カラムに持つ**: 検索・集計ができない。
  工事場所や開札日は一覧の絞り込みに使いたいので採用しない。
- **除外を `category_filter`（既存の取得対象フィルタ）で表現する**:
  テナントごとの設定になり、全社の方針が設定漏れで崩れる。
  施工しない業種の除外は方針なのでコード側に置く。
