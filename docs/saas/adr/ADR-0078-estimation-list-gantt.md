# ADR-0078: 積算案件の一覧に、1案件1本のガントを出す

## ステータス

採用（2026-09-16）

## コンテキスト

プロダクトオーナーの依頼（2026-09-16）:

> 積算案件のトップに積算中の案件の日程がガントチャートで見れないので見れるようにしてください。
> なお、各案件ごとに1本の仕様として色でフェーズを分けてください

ADR-0076 で積算案件に日程（`EstimationPhase`）とガントを入れたが、**詳細画面にしか無い**。
積算中の案件が何件動いていて、どれの開札が先に来るのかは、
案件を1つずつ開かないと分からなかった。

詳細画面のガントは frappe-gantt で**工程1つにつき1本**を並べている。
これをそのまま一覧に持ってくると、案件3件 × 工程4本 = 12行になり、
縦に伸びて「どの案件がいつ終わるか」が読めない。

## 決定

### 1. 一覧の上に、1案件1本のガントを置く

**1案件1本**にし、その1本の中を**工程ごとの色で塗り分ける**。
段階（入札説明書の入手 → 参加申請 → 入札書提出 → 開札）が色の帯として連なるので、
**案件どうしの前後関係**と**各案件がいまどの段階か**が同時に読める。

色は `EstimationPhase.color` をそのまま使う。公告から取り込んだ工程には
段階ごとの色が入っており（ADR-0076 の `_STAGE_COLORS`）、詳細画面のバーの色と揃う。
凡例は、並んでいる案件に実際に出てくる工程名だけを出す。

### 2. 描画は frappe-gantt を使わず、帯を並べた自前のものにする

**frappe-gantt は1タスク1バーで、1本を塗り分けられない。**
色は `custom_class` でバー単位に付けるもので、バーの中を区切る仕組みが無い。

そこで、この図だけは帯を並べた自前の描画にする。

- **位置はサーバ側で％にして渡す**。全体の期間に対する左端の位置と幅を
  `left_pct` / `width_pct` として持たせ、テンプレートは並べるだけにする
- **JavaScript を使わない**。日付の計算が Python 側に閉じるのでテストで固定でき、
  印刷にもそのまま出る

詳細画面のガントは frappe-gantt のままにする。あちらは工程を1本ずつ並べる図で、
現場管理の工期画面と操作を揃える意味がある（ADR-0076 の決定6）。

### 3. 表の絞り込みには連動させない

一覧の表には状態・キーワードの絞り込みがあるが、**ガントは常に積算中を出す**。

ここは「いま動いている案件の締切」を置いておく場所で、
失注した案件を探すために絞り込んだ拍子に消えると用をなさない。
他の状態を見たいときのために、サービス側は `statuses` を引数で受けられるようにしてある。

### 4. 並び順は「終わりが近い順」

表は更新順（`-updated_at`）だが、ガントは**終了日の早い案件を上**に出す。
上から読めばそのまま「次に開札が来るのはどれか」になる。

## 捨てた選択肢

- **詳細画面と同じく工程1本ずつ並べる**: 案件が増えると縦に伸びて、
  一覧に置く意味（全体を一目で見る）が無くなる。依頼もそうではない
- **frappe-gantt のまま1案件1本にし、色は案件ごとに変える**: 工程が読めない。
  依頼は「色でフェーズを分ける」なので、色は工程に使う
- **frappe-gantt のバーの上に帯を重ねて描く**: バーの座標を DOM から読んで
  重ねることになり、表示切替やリサイズのたびにずれる。ADR-0076 で
  バーの色を塗るのに一度やっており、これ以上重ねるものを増やさない
- **表の絞り込みに連動させる**: 決定3のとおり
- **日付の計算を JavaScript でやる**: テストで固定できず、印刷にも出ない

## 影響

### モデル・マイグレーション

**なし。** `EstimationPhase` をそのまま読むだけ。

### 追加したもの

| 場所 | 内容 |
|---|---|
| `estimation.services.gantt.get_projects_gantt_data` | 案件を1本ずつ並べるデータ（帯の位置は％） |
| `templates/estimation/partials/projects_gantt.html` | 帯を並べる描画と CSS |
| `/estimation/projects/` | 一覧の上にガントを表示 |

### 表示されないとき

積算中の案件に、**開始日と終了日の両方が入った工程**が1件も無いときは、
図の代わりに入れ方の案内を出す。日付の片方しか無い工程は帯にできないので数えない
（詳細画面の工程一覧には出るので、そちらで気づける）。

### テスト

`tests/test_estimation_projects_gantt.py`（20件、新規）。1案件1本になること、
帯の位置が期間に対する％になること、積算中だけを出すこと、終わりが近い順に並ぶこと、
目盛りと今日の線、凡例の重複除去、テナント越境。
