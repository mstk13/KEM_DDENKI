# ADR-0083: 積算案件のガントの目盛りを日付で刻む

## ステータス

採用（2026-09-17）

## コンテキスト

プロダクトオーナーの指摘（2026-09-17）:

> 積算案件のガントチャートに月の表示しかなく日付がないので見にくい。
> 日付が見えるようにしてください。

1案件1本のガント（ADR-0078。一覧の上と、詳細の「この案件の流れ」）は、
目盛りを**月の1日だけ**に置いていた。

```
2026/09        2026/10        2026/11
  ├──────────────┼──────────────┤
  ▓▓▓▓▓▓░░░░▒▒▒▒▒▒▒▒▓▓▓▓
```

入札公告の日程（説明書の入手 → 参加申請 → 質問 → 入札書提出 → 開札）は
**たいてい1〜2か月に収まる**。その長さだと目盛りが2〜3本しか出ず、
帯の左右がいつなのかを図から読めない。

帯そのものの日付は、左の案件名の下と、帯に乗せたツールチップには出ている。
だが**図として読めないと意味がない。** 案件を並べて「どれが先に開札か」
「今どの段階か」を一目で見るための図なので、目盛りを頼りに読む。

## 決定

### 1. 1年以内は日付で刻む

期間の長さで刻み幅を選ぶ。目盛りの本数がだいたい10〜15本に収まるようにする。

| 期間 | 刻み | ラベルの例 |
|---|---|---|
| 〜14日 | 1日 | `9/1` `9/2` `9/3` |
| 〜28日 | 2日 | `9/1` `9/3` `9/5` |
| 〜45日 | 3日 | `9/1` `9/4` `9/7` |
| 〜100日 | 7日 | `9/1` `9/8` `9/15` |
| 〜200日 | 14日 | `9/1` `9/15` `9/29` |
| 〜400日 | 28日 | `9/1` `9/29` `10/27` |

**10〜15本という上限は、ラベルの幅から来ている。** `9/17` のラベルは
1本あたり 30px ほど要る。図の帯の部分は狭いときで 400px しかないので、
15本を超えると隣と重なって読めなくなる。刻みを細かくするほど親切、ではない。

刻みは月の1日ではなく、**期間の左端から**数える。月をまたぐたびに
間隔が 28〜31日で揺れるのを避けるため。図の上では等間隔の格子になる。

### 2. 1年を大きく超えるときだけ月に戻す

400日を超えたら、これまでどおり月の1日に `2026/09` の形で置く。
この長さになると日付のラベルは何を刻んでも隣と重なり、
1日の違いを読む意味も無くなる。

### 3. 年をまたぐ目盛りにだけ年を足す

`9/1` `12/20` `2027/1/4` のように、**年が変わったときだけ**年を書く。

全部に年を書くと `2026/9/1` が並んで幅を食い、本数を減らすことになる。
年を一切書かないと、年をまたぐ案件で `12/20` の次が `1/4` となり、
どちらの年の1月かが読めない。

### 4. 左右の端の目盛りは寄せ方を変える

目盛りのラベルは中央そろえ（`translateX(-50%)`）で置いている。
左端（0%付近）はラベルの左半分が図の外に出て切れるので、左そろえにする。
右端いっぱい（97%より右）に乗った目盛りは右そろえにする。

寄せ方はサーバ側で `align` として決める。位置（％）を出しているのと
同じ場所で決めたほうが、しきい値が1か所に収まる。

## 捨てた選択肢

- **月の目盛りのまま、帯に日付のラベルを直接書く**: 帯が短い案件では
  文字が入らない。帯が重なる案件どうしで文字も重なる
- **目盛りを毎日にする**: 2か月の案件で60本。ラベルが完全に潰れる
- **常に「年/月/日」を書く**: 幅を食い、置ける本数が半分になる
- **刻みを月の1日から数える**: 月をまたぐたびに間隔が 28〜31日で揺れ、
  図の上では格子が不揃いに見える
- **画面幅を JS で測って本数を決める**: 位置の計算はサーバ側に置いてある
  （ADR-0078）。印刷とテストのために、図の中身は JS 無しで決まるようにしている
- **曜日を足す（`9/17(木)`）**: 入札の締切は曜日で覚えることもあるが、
  ラベルが 50px になり本数が 2/3 に減る。曜日は帯のツールチップで足りる
- **frappe-gantt に寄せる**: 1本を工程ごとに塗り分けられないので、
  この図を自前で描いている（ADR-0078）。目盛りだけ借りることはできない

## 影響

### 変わる画面

| 場所 | 変わり方 |
|---|---|
| 積算案件 一覧の上のガント（ADR-0078） | 目盛りが日付になる |
| 積算案件 詳細「この案件の流れ」（ADR-0080） | 同上（同じ図を使っている） |

詳細画面の上にある工程ごとのガント（ADR-0076。frappe-gantt）は変えない。
あちらには元から 日/週/月 の切り替えが付いている。

入札案件のガント（`bids.gantt`）も変えない。図の作りが別で、
今回の指摘も積算案件に対するもの。

### モデル・マイグレーション

無し。目盛りの作り方だけの変更。

### テスト

`tests/test_estimation_projects_gantt.py` に追加・差し替え。
日付で刻むこと、期間が延びても日付のままで本数が収まること、
年をまたぐと年が付くこと、1年を大きく超えると月に戻ること、端の寄せ方。
