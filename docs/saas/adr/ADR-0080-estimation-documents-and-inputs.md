# ADR-0080: 積算案件に資料を持たせ、発注機関・担当者・工期末日を入れやすくする

## ステータス

採用（2026-09-17）

## コンテキスト

プロダクトオーナーの依頼（2026-09-17）:

1. 積算案件の編集画面で、**発注機関**の候補に無い機関名を手で入力できるようにしたい
2. **積算の担当者**を入力し、過去に入れた内容を候補に出したい
3. **工期**は、工期の末日を西暦で日付まで入れて出したい
4. 案件ごとに**参考資料や公告のPDF**を保持したい
5. 入札案件から積算へ移したものは、**公告のPDFもそのまま**アクセスできるようにしたい
6. **AIで解析したPDFの中の入札までの日程**を見られるようにし、**案件ごとのガント**で流れを追いたい

今の状態を確かめた。

| 項目 | 現状 |
|---|---|
| 発注機関 | `EstimationProject.orderer` は FK（PROTECT）で、画面は**プルダウンだけ** |
| 積算担当者 | **項目が無い** |
| 工期 | `construction_period_days`（日数）のみ。**末日を置く場所が無い** |
| 案件の資料 | **持てない**。入札案件の `BidDocument` は入札に提出する書類で別物 |
| 公告 | `BidProject.source_url` に**URLだけ**。ファイルは手元に残らない |
| 日程 | 公告から抽出した `bid_schedule` は**入札案件にしか無い** |
| ガント | 詳細は工程1本ずつ（ADR-0076）、一覧は1案件1本（ADR-0078） |

## 決定

### 1. 発注機関は自由入力にし、無ければマスタに登録する

`orderer_name`（CharField）で受け、`resolve_or_create_orderer` が引き当てる。
候補は `<datalist>` で出す。現場の顧客欄と同じ作り。

**プルダウンだけだと積算が止まる。** 公告を見ながら積算を始める時点で
マスタに無い機関は珍しくなく、「先に発注機関マスタへ登録してから案件を作る」
という2画面の往復が要る。

引き当ては `Orderer` の一意キー（company, name）と**同じ完全一致**で行う。
顧客マスタのような表記ゆれの正規化は**しない**。「厚木市」と「厚木市教育委員会」は
似ていて別物で、寄せると積算基準を取り違える。

### 2. 積算担当者は CharField。候補は過去の入力そのもの

`estimator_name`（CharField）にする。`User` の FK に**しない**理由は2つ。

- 積算を外部に頼むことがあり、その相手はシステムのユーザーではない
- 入社前の担当者名を先に入れておくことがある

候補はマスタを作らず、**過去に入れた値を重複なく集めて**出す。
担当者は人の入れ替わりで変わるので、マスタにすると使わなくなった名前を
消す手間が残る。

### 3. 工期に末日を足し、必ず西暦・日付まで出す

`construction_end_date`（DateField）を足す。`construction_period_days` は残す。

日数だけだと「いつまでの工事か」が分からず、公告に
「契約の日から令和9年6月30日まで」と書いてある値をそのまま置けなかった。

画面には `2027年6月30日 まで` の形で出す。**和暦では出さない。**
読み替えの手間がかかり、令和8年と令和9年の取り違えが起きる。

保存時に**開札予定日より前の末日は弾く**。入力の打ち間違いがここで止まる。

### 4. 案件資料は新しいモデルで持つ

`EstimationDocument`（ファイル・種別・メモ＋AIの読み取り結果）を新設する。

`bids.BidDocument` を使い回さない。あちらは入札に**提出する**書類、
こちらは積算で**読む**書類で、入札を経ない民間案件でも使う。

**URLだけでは足りない。** 発注機関のサイトは入札が終わると公開文書を消すので、
積算が終わったあとに「何を根拠に積んだか」を辿れなくなる。

受け取れる形式・大きさ・中身の確かめ方は `apps.core.documents` に揃える
（現場の提出書類 ADR-0067・自社書類 ADR-0071 と同じ規則）。
ファイルは**ログイン必須・自社のみ**で配信し、共有キャッシュに置かせない。
資料を消したら保存したファイルも消す。

### 5. 公告には積算案件から直接飛ぶ

入札から引っ越した案件の詳細に、`source_url`・`document_urls`・`BidDocument` への
ボタンを並べる。入札案件の画面まで辿らせない。

同時に「発注機関のサイトは入札が終わると公開文書を消すので、
大事な資料は案件資料に登録してください」と画面に書く。
**消えることを知らないと、消えてから気づく。**

### 6. PDF の日程は「文字 → AI」の順に読む

`document_schedule.read_schedule` が2段で読む。

1. **文字から読む** — `bids.announcement.extract_bid_schedule` をそのまま使う
2. **AI に読ませる** — 1 で取れないとき、または文字が `(cid:NNN)` に化けているときだけ

**AI を最初から使わない。** 文字で読めるものは1件0円・1秒で済み、
AI に投げると1件あたり数十円かかる。

**同じ公告を2通りに読まない。** 日付の読み方（和暦→西暦、「正午」「17時」、
「同年」の解決）は `bids.announcement` に全部ある。ここで書き直すと
入札側と積算側で結果が食い違う。

### 7. 読み取った日程は、そのままでは工程にしない

読み取り結果は資料（`ai_schedule`）に貯め、画面の表で見せる。
**人が「工程に取り込む」を押したときだけ** `EstimationPhase` を作る。

AI も文字からの抽出も読み違える。自社書類の AI 読み取り（ADR-0071）と同じ考え方。
取り込みは項目名をキーにした1回限りで、読み取り直しても手で直した日付は戻らない。

### 8. 詳細画面に「この案件の流れ」を出す

一覧（ADR-0078）と**同じ1本のガント**を、この案件だけに絞って詳細にも出す。

上にある「日程」のガント（ADR-0076）は工程を1本ずつ並べたもので、
1つの工程の長さを読むためのもの。こちらは段階の連なりを1行で読むためで、
読みたいことが違うので両方置く。

図は `partials/gantt_chart.html` に切り出し、一覧と詳細で同じものを使う。

## 捨てた選択肢

- **発注機関のプルダウンに「その他」を足して別欄に書かせる**: マスタに入らないので
  次の案件でまた打つことになり、表記ゆれが増える
- **発注機関名を顧客マスタと同じ正規化で寄せる**: 「厚木市」と「厚木市教育委員会」を
  同じものにしてしまう。積算基準の取り違えは金額の間違いに直結する
- **積算担当者を `User` の FK にする**: 外部に頼んだ積算と、入社前の担当者を置けない
- **担当者のマスタを作る**: 使わなくなった名前を消す手間が残る。候補を出すだけなら要らない
- **工期を「開始日〜末日」の2つにする**: 公告は「契約の日から◯◯まで」と書くので
  開始日が決まっていないことが多い。末日だけで足りる
- **資料に `bids.BidDocument` を使う**: 提出する書類と読む書類が混ざり、
  入札を経ない民間案件で使えない
- **公告はURLのリンクだけにする**: 入札が終わると消える（決定4のとおり）
- **アップロードのたびに自動で AI に読ませる**: 読ませなくてよい仕様書・図面にも
  費用がかかる。ボタンを押したときだけにする
- **読み取った日程をそのまま工程にする**: 読み違えた日付がそのまま予定になる
- **日付の読み取りを積算側に書き直す**: 入札側と結果が食い違う（決定6のとおり）
- **詳細のガントを1本だけにして ADR-0076 の図を消す**: 工程1本ずつの図は
  1つの工程の長さを読むのに要る。読みたいことが違う

## 影響

### モデル・マイグレーション

| 変更 | 内容 |
|---|---|
| `EstimationProject` | `construction_end_date`・`estimator_name` を追加 |
| `EstimationDocument` | 新設（ファイル・種別・メモ・AI の読み取り結果） |

`estimation/0007`。**追加のみで、削除・改名・データ移行はない**（規律7）。

### 既存データ

- 既存の積算案件は `construction_end_date`・`estimator_name` が空。画面には「-」が出る
- `orderer` は FK のまま。既存の紐づけはそのまま残り、編集画面では機関名が初期値に入る
- 過去の案件には資料が無い。必要なものは手元のPDFを登録する

### 追加した画面・URL

| 場所 | 内容 |
|---|---|
| 積算案件 編集 | 発注機関の自由入力、積算担当者、工期末日 |
| 積算案件 詳細 | 公告への導線、案件資料の一覧と登録、読み取った日程の表、この案件の流れ |
| `/estimation/projects/<pk>/documents/add/` | 資料の登録 |
| `/estimation/documents/<pk>/file/` | 資料を開く（ログイン必須・自社のみ） |
| `/estimation/documents/<pk>/delete/` | 資料を消す（ファイルも消える） |
| `/estimation/documents/<pk>/read-schedule/` | PDF から日程を読み取る |
| `/estimation/documents/<pk>/import-schedule/` | 読み取った日程を工程に取り込む |

### AI の費用

読み取りは**ボタンを押したときだけ**動く。文字で読める公告は AI を通らない。
AI に回るのは文字が化けている公告だけで、1件あたり数十円（`announcement_llm` の見積り）。
月間予算の確認は既存の `call_claude_with_log` が行う。

### テスト

`tests/test_estimation_documents.py`（35件、新規）。発注機関の自由入力と引き当て、
似た機関名を寄せないこと、担当者の候補、工期末日の表示と入力チェック、
資料の登録・閲覧・削除、拡張子だけ変えたファイルを弾くこと、
日程の読み取りと工程への取り込み、取り込み直しで手直しが戻らないこと、
公告への導線、この案件の流れ、テナント越境。
