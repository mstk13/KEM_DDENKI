# ADR-0102: 評価項目とアンケート設問を、書き出して読み込めるようにする

日付: 2026-09-19
状態: 採用

## 背景

人材評価の評価項目（`EvalItem`）と設問（`SurveyQuestion`）は、画面から直せるデータである。
プロダクトオーナーが開発環境で項目を直し、「main に反映したい」と依頼された（2026-09-19）。

しかし調べたところ、`apps/evaluation` と `saas/static/data/eval_items.json`・
`survey_questions.json` を含め、**コードには main と developer で差が無い**。
直した内容は開発環境の DB にだけあり、PR を作っても本番には出ない。
開発（`kemdev`）と本番（`saas`）は Docker のプロジェクトが別で、DB も別物のため。

## 決定

- 評価基準の画面に「書き出す」「読み込む」を置く。
  - 書き出しは JSON（`kem-eval-items`）。項目と、その下の設問をまとめて出す
  - 読み込みは**足すか直すだけ**。ファイルに無い項目は消さない。
    消すのは取り返しがつかないので、画面の削除から人が行う
  - 同じ項目かどうかは「セクション＋項目番号」、設問は「項目＋質問番号」で見る
  - 会社は読み込む側のものを使う。ファイルの中の会社は見ない（他社のデータは入らない）
- ボタンは2つに分ける。
  - 「確認」… 何が足され・直されるかだけを画面に出す（保存しない）
  - 「読み込む」… 実際に登録する
- 使えるのは人事評価の画面に入れる人（社長・役員・Developer）だけ。

## 人材評価のテンプレートも同じようにする（2026-09-19 追記）

書き出してみたところ、`EvalItem` は0件だった。プロダクトオーナーが直していたのは
**人材評価のテンプレート**（`workers.EvaluationTemplate`。評価項目・質問・スケール・
総合所見を JSON でまとめて持つ）のほうだった。

そこで評価テンプレート編集の画面にも「書き出す」「確認」「読み込む」を置く。

- 書き出しは JSON（`kem-eval-template`）
- 読み込みは、今あるテンプレートの中身を**ファイルの内容で置き換える**。
  項目ごとの突き合わせはしない（テンプレートは1件のまとまりとして扱うため）。
  置き換える前の中身は履歴（simple-history）に残る
- 使えるのは admin グループ（テンプレート編集と同じ条件）

## 使い方

- 人事評価の評価基準（`/evaluation/criteria/`）
  1. 開発環境で「書き出す」→ `eval_items.json`
  2. 本番の同じ画面でそのファイルを選び、「確認」→「読み込む」
- 人材評価のテンプレート（`/workers/evaluations/template/`）
  1. 開発環境で「書き出す」→ `eval_template.json`
  2. 本番の同じ画面でそのファイルを選び、「確認」→「読み込む」

## 結果

- 環境をまたいで評価項目を移せる（今後の修正も同じやり方で運べる）
- 消し忘れ・消しすぎが起きない（読み込みでは消さない）
- どの項目が足され・直されるかを、登録の前に確認できる
