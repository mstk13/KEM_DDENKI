# ADR-0093: アップロードしたファイルを、本番でもログインした人に返す

日付: 2026-09-18
状態: 採用

## 背景

資格証・健診報告書・現場写真などのアップロードは `MEDIA_ROOT` に保存し、
`/media/...` の URL で開く。この URL を配信していたのは

```python
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

の1行だけだった。本番は `DEBUG=False` なので **URL が存在せず**、
資格証の「表示」を押すと Django の素の 404（Not Found）になっていた
（プロダクトオーナーの申告、2026-09-18）。開発環境は `DEBUG=True` なので気づけなかった。

配信を止めていたのは、Django の `static()` が開発用で本番に向かないため。
ただし単に本番でも `static()` を足すのは避けたい。ここに入るのは
**資格証・運転免許証・健診報告書といった個人の書類**で、URL を知る誰にでも返す形にはできない。

## 決定

- `apps/core/media_views.serve_media` を作り、`MEDIA_URL` 配下を常にこのビューで返す。
  `DEBUG` で分けるのをやめ、開発も本番も同じ道を通す（開発で気づけない差をなくす）。
- ログインを必須にする（`@login_required`）。ログインしていなければログイン画面へ送る。
- パスは `MEDIA_ROOT` の中に収まることを確かめてから開く。
  `../` で上の階層へ出る指定は 404 にする。
- 画像・PDF は画面の中で開きたいので `Content-Disposition: inline`。
  個人の書類なので `Cache-Control: private, max-age=0` を付け、共有のキャッシュに載せない。
- 同じ会社かどうかまではここでは見ない。保存名に Django が付ける乱数があり URL を当てられないこと、
  アプリ全体が社内ネットワーク（Tailscale）の内側にあることから、まずはログインを境界とする。
  会社ごとに分けるなら、保存先を会社別にしてからこのビューで照合する（そのときに改めて決める）。

## 結果

- 本番でも資格証の「表示」が開く
- 個人の書類がログイン無しで取れる形にはならない
- 静的ファイル（`/static/`）はこれまでどおり WhiteNoise が配信する。今回の変更は `/media/` だけ
