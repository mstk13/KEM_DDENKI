# ADR-0069: まとめて記入でも区分ごとの詳細（現場名・行先）を入れられるようにする

## ステータス

採用（2026-09-16）

## コンテキスト

プロダクトオーナーの依頼（2026-09-16）: 勤怠管理の「まとめて記入」に、出社や出張などの詳細を記入できる欄を足したい。

- 今の「まとめて記入」は **対象者・対象日・区分・開始・終了** だけ。現場名や出張の行先は入れられず、
  入れたい人は月グリッドのマスの詳細ダイアログか日シートで1件ずつ入れ直していた
- 区分ごとに訊く項目は `AttendPlan.KIND_FIELDS`（ADR-0023）で決まっている。
  現場・直行直帰は「現場名」、出張は「行先」、出社・在宅などは場所を訊かない。時刻を訊かない区分もある
- 現場名の候補（登録済みの現場名の `<datalist>`）は ADR-0037 で入れてある

## 決定

1. まとめて記入に **場所の欄（`note`）** を足す。ラベルと出す・出さないは `KIND_FIELDS` に従う
   （現場・直行直帰＝「現場名」、出張＝「行先」、それ以外は隠す）。時刻の欄も同じく、
   時刻を訊かない区分（出張・有休・休み）では隠す
2. 現場名の候補（ADR-0037 の `attend-site-names`）を、まとめて記入の欄でも使う
3. **サーバ側でも同じ規則で落とす**。場所を訊かない区分の `note` は空にし、時刻を訊かない区分の時刻は
   `None` にして保存する。画面の JavaScript を通らない送信でも、ダイアログ・日シートと同じ形に揃うため
4. 上書き（`overwrite`）のときは現場名・行先も置き換える。「先週と同じ現場で入れ直す」を1回で終わらせるため
5. 知らせに入れた詳細を出す（例:「全員の平日 22 件を「出張」（行先: 大阪）にしました」）

## 捨てた選択肢

- **出張の期間（`span`）もまとめて記入で扱う**: 対象日の指定（平日・曜日）と二重になり、どちらが優先か分からなくなる
- **場所を訊かない区分でも `note` を保存する**: ダイアログと食い違い、区分を変えたときに前の現場名が残る
- **詳細を別画面にする**: 1画面で終わるほうが早い。まとめて記入は朝礼前に使う画面

## 影響

- モデル・マイグレーションの変更なし（`AttendPlan.note` をそのまま使う）
