# ADR-0066: 資格不足の理由を1つ目で止めず、不足する要件をすべて出す

日付: 2026-09-15
状態: 採用（ADR-0011 の資格判定、ADR-0065 の建設業許可の照合を変える）

## 背景

入札参加資格の判定（`qualification.check_project`）は、満たさない要件が1つ見つかるとそこで判定を終えていた。
そのため、たとえば建設業許可と等級の両方が足りない案件でも、理由は最初の1つしか出なかった。
プロダクトオーナーから「ほかの参加資格でも不足していればそれも書く。不足する該当項目はすべて書く」と依頼された（2026-09-15）。

## 決定

- 判定は不足を `result["shortfalls"]`（`[{"failed_on", "reason"}]`）に集め、確かめられる要件はすべて確かめる。
  - 建設業許可と営業所の所在地は別々に確かめる
  - 資格が期限切れでも、一番新しい資格で等級・点数の不足を続けて確かめる（`matched` にその資格を入れる）
  - 等級の列挙・等級の下限・点数の下限は、それぞれ確かめる
  - 発注機関・業種の資格そのものが無いときは、比べる相手が無いのでそこまで
- 最後に `_finish` で判定を決める。
  - 不足が1つでもあれば資格不足。`reason_lines` は不足の理由すべてと、確かめられなかった要件の「要確認: …」
  - 不足が無く、確かめられなかった要件（建設業許可が未登録・統一資格の等級が未登録など）があれば要確認
  - `reason` は `reason_lines` を改行でつないだもの。不足が1つなら、これまでと同じ1文。`failed_on` は1つ目の不足
- 案件詳細の判定結果は、理由が複数なら1行ずつ並べる。
- 参加要件の表では、理由ごとにその話をしている項目を探して右側に出す（1つの項目に複数付くこともある）。
  該当する項目が無い理由は、資格の話をしている最初の項目、それも無ければ表の上にまとめて出す。
- 取り込み時に見送った案件（`SkippedBid.reason`）にも、改行でつないだ理由すべてを残し、一覧では改行して出す。

## 結果

- 建設業許可・営業所の所在地・等級・点数がそれぞれ足りない案件は、4つの理由がそれぞれの項目の右側に出る
- 不足が1つの案件の表示は、これまでと変わらない
