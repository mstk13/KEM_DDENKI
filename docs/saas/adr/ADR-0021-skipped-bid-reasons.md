# ADR-0021: 資格判定で見送った案件を理由付きで残す

## ステータス

承認

## コンテキスト

ADR-0020 の「資格を満たす案件だけ登録」では、資格不足・判定不能の案件は
登録されず、件数だけが取得対象の結果に残っていた。判定が正しいかを人が
公告と照らして確認したい、足りない資格を洗い出したいという要望が出た。

## 決定

### 1. 見送った案件は `SkippedBid` に理由付きで保存する

`BidProject` に混ぜて「資格不足」の状態を持たせる案は採らない。
案件一覧・集計・通知はすべて `BidProject` を対象にしており、参加できない
案件が混ざると「新着 N 件」「参加可 N 件」の意味が変わるため。

`SkippedBid` は案件そのものではなく判定の記録として持つ。

- キー: `(company, source_url)`。同じ公告は上書きし、取り込みのたびに増えない
- 保存する内容: 判定（資格不足／判定不能）、理由の文、公告が求める資格
  （機関・種類・等級・点数）、読み取った参加要件の本文、期限、取得対象
- 資格の追加などで次の取り込みで登録できたら、その記録は消す

### 2. 画面は `/bids/skipped/` に置き、「理由」ボタンで開く

一覧は期限が近い順。各行の「理由」で判定の理由・公告が求める資格・
参加要件の本文を同じ画面内に開く（別ページに飛ばない）。公告 PDF への
リンクを添え、人が原文と照らせるようにする。

確認が済んだ記録は「確認済み」で一覧から消せる。次の取り込みで再び見送られれば
戻るので、消しても取りこぼしにはならない。

## 影響

- `apps/bids/models.py` に `SkippedBid`（simple-history 付き）、マイグレーション 0017
- `apps/bids/services.py`: `_record_skipped`、登録できた案件の記録削除
- `/bids/skipped/`（一覧・理由）、`/bids/skipped/<pk>/delete/`（確認済み）
- 案件一覧と取得対象一覧からのリンク
- テスト `tests/test_bids_eligible_scrape.py::TestSkippedBidRecording`
