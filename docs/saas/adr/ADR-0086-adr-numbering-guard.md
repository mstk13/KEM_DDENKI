# ADR-0086: ADR の番号の重複を CI で止める（過去の重複は凍結する）

## ステータス

採用（2026-09-17）

## コンテキスト

ADR の番号の重複が5回起きている。

| 番号 | 重複している件 |
|---|---|
| 0022 | `bid-schedule-gantt` / `position-based-app-access` |
| 0070 | `attendance-office-task` / `date-inputs-rendered-by-widget` |
| 0080 | `daily-report-missing-alerts` / `estimation-documents-and-inputs` |
| 0082 | `certificate-pdf-import` / `worker-app-access-matrix` |
| 0084 | `estimation-document-source` / `site-merge-candidates` |

原因は、**並行して進んだ別々の作業がそれぞれ「次の空き番号」を同時に取ること。**
マージされるまで相手の番号は見えないので、人の注意では防げない。
`ab95447`（2026-09-16）で 0079〜0081 に振り直した直後にも 0082 が重複しており、
手作業での整理では収まっていない。

**このガードを書いている最中にも 2 回ぶつかった。** 0083 を取った直後に別の 0083 が
マージされ、0084 に振り直したところ、今度は 0084 が**3つ**になった（`developer` 側に
2件入った）。最終的に 0087 に落ち着いている。人の注意で防げないことの実例として、
ここに残す。

番号が重複すると、コード・テスト・コミットメッセージにある「ADR-0082」が
どちらを指すのか決まらない。実際に重複している4組は**両側ともコードから
参照されている**（例: 0082 は `apps/permissions/access_matrix.py` と
`tests/test_certificate_import.py` の両方）。

## 決定

**過去は凍結し、これ以上増やさない。**

1. `saas/tests/test_adr_numbering.py` を置き、CI で次の3つを見る
   - ファイル名が `ADR-0001-lowercase-slug.md` の形であること
   - **既知の4つ以外に番号の重複が無いこと**（落ちたら次に使う番号を案内する）
   - 凍結した一覧に、もう重複していない番号が残っていないこと
2. 既知の重複は `KNOWN_DUPLICATES` に明記する。**番号ではなくファイル名の集合で
   固定する。** 番号だけを許すと、同じ番号にもう1つ足しても検出できない
   （0084 が3つになったのがこのケース）。
   **ここに足して自分の新しい ADR を通してはいけない。** 足してよいのは、
   このガードが入る前から base 側で重複していた分だけ
3. `saas/CLAUDE.md` のルール9に、命名規則と「番号はマージ直前に確定させる」を書く

## なぜ過去を振り直さないか

振り直したほうが綺麗に見えるが、実際には状態が悪くなる。

- **コミットメッセージは書き換えられない。** 0082 を振り直すと、過去のコミットに
  ある「ADR-0082」が別の決定を指すようになる。**曖昧なままより悪い**
  （読めないのではなく、誤った先を指す）
- 参照は散在している。コメント・テストの docstring・他の ADR 本文に及び、
  追従漏れが1つでもあれば嘘が残る
- 機能上の利益がゼロ。番号は人が引くための短い手掛かりで、識別子は**ファイル名**

番号だけで一意に決まらない4つは、参照する側がファイル名で特定する。
ファイル名は内容が分かる形なので、番号で grep すれば2件出てどちらか判断できる。

## 捨てた選択肢

- **全ての重複を振り直して番号を一意にする**: 上記のとおり、書き換えられない
  コミットメッセージが誤った先を指すようになる
- **番号をやめて日付やスラッグだけにする**: 既存の全参照（数十箇所）が読めなくなる。
  短い手掛かりとしての番号は機能している
- **CONTRIBUTING に「番号を確認してから付ける」と書く**: 4回起きた原因は
  確認不足ではなく**同時に取ること**。確認しても、相手がまだマージされていなければ
  見えない。文章では防げない
- **番号を自動で払い出すスクリプトを置く**: ローカルで払い出しても、
  同時に走った別の作業とはぶつかる。**ぶつかったことを検出する**ほうが確実で、
  仕組みも小さい

## 影響

- テスト3件が増える。DB を使わないため 0.1 秒程度で終わる
- 凍結しているのは 0022 / 0070 / 0080 / 0082 / 0084 の5つ。
  それ以外の番号が重複した場合と、この5つにファイルが足された場合の両方で落ちる
- 次に重複が起きたとき、マージ後に気づくのではなく**PR の CI で止まる**。
  その時点なら未マージのファイル1つを改名するだけで済む
