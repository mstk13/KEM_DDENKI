# ADR-0017: 見積書PDFの内訳書取込を作り直す

## ステータス

採用（2026-08-24）

## コンテキスト

現場詳細の内訳書が実際の見積書と合わない、という指摘を受けた。
`ADR-0016` で作った `boq_import.parse_pdf` に実物の見積書PDF
（A4横・7ページ・内訳書2ページ＋内訳明細書4ページ）を通したところ、
**76行あるうち41行しか取れず、全行が細目別、数量は全て誤り**だった。

原因は独立した3つで、いずれも「静かに壊れる」形をしていた。

### 1. 罫線が1行おきにしか引かれず、半分の行が消えていた

この様式は行に縞模様の背景を敷いており、`extract_tables()` が
罫線を検出できるのは背景のある行だけだった。罫線の無い行は
7列ぶんが1セルに潰れる。

```
1 ['A', '舗装工', '', '1', '¥ 70,000', '¥ 70,000', '']      ← 取れる
2 ['B 掘削工事 1 ¥ 96,080 ¥ 96,080', '', '', '', '', '', '']  ← 全部1セル
3 ['C', '残土運搬工', '', '1', '¥ 74,120', '¥ 74,120', '']    ← 取れる
```

潰れた行は名称列が空になり、`rows_to_drafts` の
「名称が空の行は飛ばす」で**警告も出さずに捨てられていた**。

### 2. NFKC が単位記号を数字に変えていた

`_to_decimal` は「数字以外の文字を消す」実装だった。
NFKC 正規化は ㎡ を `m2`、㎥ を `m3` に展開するため、英字を落としたあとに
`2` `3` が残る。

| 見積書 | 取込結果 |
|---|---|
| 0.66㎡ | 0.662 |
| 1.79㎥ | 1.793 |
| 6.4㎡ | 6.42 |

金額には `¥` しか付かないので無傷のまま通り、
**数量×単価と金額が合わない行だけが残る**という気づきにくい壊れ方をした。

### 3. 「数量と単価がそろう行は細目別」が成り立たない様式だった

`ADR-0016` で採った判定は、種目行が金額しか持たない前提だった。
この様式は**種目行にも「数量 1・単価・金額」を入れる**（単価＝集計額）。
結果、A〜S の種目行も末端の施工費も区別できず、全行が細目別になった。

さらに `parse_pdf` はページの種類を見ないため、
内訳書ページ（集計）と内訳明細書ページ（明細）の両方を平らに取り込み、
同じ工種が二重に入っていた。

## 決定

### 1. 罫線から行を取りこぼしたら、語の座標から表を組み直す

`extract_tables()` の結果に**名称が空で捨てられる行があるか**を数え
（`_dropped_row_count`）、あれば `_rows_from_words()` で組み直して、
読める行が増えたほうを採る。罫線が素直に取れる様式は従来どおり通る。

組み直しは次のようにする。

- **列の境界は縦罫線から採る。** 縦罫線は横罫線と違って表全体に通っている
- **見出しラベルの位置は使わない。** 「名称」は列の中央に置かれるのに
  中身は左詰めで、境界を取り違える
- 行は語の `top` を行送りの半分弱の幅でまとめる。
  折り返した単位（「0.66㎥(」＋「立方メートル)」）を同じ行に寄せるため
- **表の範囲は縦罫線が通っている範囲に限る。** ページ番号や
  「※印は軽減税率対象です」は表の外にあり、拾うと名称列の最左になって
  段の順位を1つずつずらす

### 2. 数量は「数字以外を消す」のではなく「最初の数値を取り出す」

消す方式は、消し残した文字が数値に化ける。取り出す方式なら
単位が何であれ影響しない。

あわせて、**単位列を持たない様式のために数量セルから単位を拾う**
（`_split_unit`）。数値の後ろに残った文字が単位で、
カッコ書きの読み仮名（立方メートル）は落とす。
ここでは NFKC を通さない。㎥ を `m3` に崩さないため。

### 3. 階層はインデントの「順位」で決める

`ADR-0016` はインデントの**段数**が様式ごとにばらつくことを理由に
数量×単価の有無を優先していた。ばらつくのは幅であって順序ではないので、
**表全体に現れたインデント幅を浅い順に並べ、その順位を階層に割り当てる**
（`_levels_by_rank`）。2段の様式でも4段の様式でも同じ規則で読める。

- いちばん浅い段は種目別
- いちばん深い段は、そこに数量×単価のそろう行があれば細目別に固定
- 間の段を科目別・中科目別で埋め、あふれたら中科目別にまとめる

ただし**最上位段より深く、下に行を持たない（葉の）行で
数量×単価がそろっていれば細目別に落とす。**
「コンクリート工 → 斫り工 → 施工費」のように3段で終わる枝の末端を拾うため。

インデントの段が1種類しか無い表は、これまでどおり数量×単価の有無で決める。

### 4. ページを跨いだ表は繋いでから読む

内訳書はページを跨いで続き、階層はページ内で閉じない。
ページごとに読むと、**ページ末尾の行が「下に行が無い＝枝の末端」に見えて**
階層を取り違える。列構成（見出しの対応）が同じページを1つの表として繋ぎ、
2ページ目以降は繰り返しの見出し行から下だけを足す。

### 5. 内訳明細書があるページだけを取り込む

同じPDFに内訳書と内訳明細書が綴じられている場合、
内訳書は内訳明細書の集計なので**内訳書ページを読み飛ばす**。
両方入れると同じ工種が二重に入り、
「合計は最上位行の金額から」（ADR-0016）が二重計上になる。

ページ見出しで見分けられるPDFなら、**見出しの無いページは表紙・鑑として
黙って飛ばす。** Excel の表紙シートで警告を出さないのと同じ扱い
（ADR-0016：本当の失敗が埋もれるため）。

内訳明細書が無いPDFでは内訳書をそのまま読む。飛ばすのは重複するときだけ。

## 理由

### なぜ LLM に回さなかったのか

`ADR-0016` の方針どおり。この壊れ方はどれも座標と正規化の問題で、
決定論的に直せる。ローカル推論に回していたら
「だいたい合っている表」が返ってきて、
数量が 0.662 であることに誰も気づかなかった。

### なぜ実物のPDFをテストに置かないのか

顧客の見積書そのもので、金額と取引先名が入っている。
壊れ方は「縞模様で罫線が1行おき」「単位が数量セルに同居」
「種目行にも数量・単価」「内訳書と内訳明細書が同居」という
**様式の特徴**なので、その特徴を持つ `_FakePage` を組んで再現する。

## 影響

### コード変更

- `apps/estimation/services/boq_import.py`
  - `_to_decimal` … 最初の数値を取り出す方式に変更
  - `_split_unit` … 新設。数量セルに同居する単位を拾う
  - `_is_subtotal` … 「【合計】」のように括る様式に対応
  - `_page_kind` / `_table_span` / `_column_bounds` / `_row_tolerance` /
    `_rows_from_words` / `_dropped_row_count` / `_usable_row_count` /
    `_page_rows` … 新設
  - `_levels_by_rank` … 新設。`_resolve_level` に `rank_level` / `is_leaf` を追加
  - `rows_to_drafts` … 段の順位と葉の判定を表全体で組み立てる
  - `parse_pdf` … 列構成ごとにページを繋ぐ。内訳書ページと表紙を飛ばす
- `tests/test_sites_boq.py` … PDF 取込のテストを追加（`_FakePage` ほか）

### 実ファイルでの結果

| | 修正前 | 修正後 |
|---|---|---|
| 取込行数 | 41 | 61 |
| 階層 | 全行が細目別 | 種目別19 / 科目別13 / 中科目別12 / 細目別17 |
| 数量 | 全て誤り | 全て一致（数量×単価＝金額） |
| 種目別合計 | 二重計上 | ¥950,000（見積書の小計と一致） |

### 運用

- 依存追加なし
- 取込の対象ページと組み直しの有無は `logger.info` に出る。
  読めない様式に当たったらまずこれを見る

## 残課題

- 3段で終わる枝（コンクリート工→斫り工→施工費）は、
  他の枝と段数がそろわないまま取り込む。
  そろえたいなら取込後に画面で1段挿す
- ページ見出しを持たない内訳書PDFでは、
  内訳書ページと内訳明細書ページの重複を見分けられない
- `ADR-0016` の残課題（様式差、積算案件と現場の突合）はそのまま
