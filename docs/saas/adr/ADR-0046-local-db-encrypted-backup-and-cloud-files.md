# ADR-0046: DB は社内PCに残して暗号化し、暗号化したバックアップとアップロードファイルをクラウドに置く（案C）

## ステータス

採用（2026-09-12）。**ADR-0044（DB をまるごとクラウドへ）を置き換える**。ファイル保存先のベンダーは選定中（計画: `docs/design/cloud_db_migration_plan.md`）

## コンテキスト

ADR-0044 で DB をまるごとクラウドのマネージド PostgreSQL へ移すと決め、料金を調べた（計画書 6章、2026-09-12 時点）。

| 構成 | 月額の目安 | 必須要件 |
|---|---|---|
| A: DB をクラウド（Azure B1MS・AWS RDS の最小構成） | 税込 約¥4,000〜4,500 | 満たす |
| B: ファイルだけクラウド（AWS S3・Azure Blob など） | ¥数十〜数百 | DB が社内に残る |
| **C: DB は社内で暗号化、暗号化したバックアップとファイルをクラウド** | **¥数百** | 下の対策と組み合わせて満たす |

予算の上限はとりあえず月¥1,000（計画書 O2）。3つの構成の違い（置くもの・料金・ネット切断時・盗難時に残るもの）と、
個人情報保護法・労働安全衛生規則の観点（安全管理措置、要配慮個人情報を含む漏えい等の報告、健康診断個人票の5年保存）を説明したうえで、
プロダクトオーナーが **案C** を選んだ（2026-09-12）。社内の DB の暗号化は会社側で行う。

## 決定

1. **DB（PostgreSQL）は社内PCに残す**。アプリ・社内AI・Redis も社内PCのまま
2. **アップロードファイル**（現場の画像・資格証・健康診断の書類など、`STORAGES["default"]`）は、クラウドのオブジェクトストレージ（国内リージョン・非公開・暗号化）へ移す
3. **DB のバックアップは社内PC上で暗号化してから**クラウドのストレージへ送る。暗号の鍵（パスフレーズ）は会社が PC の外にも保管し、クラウドには置かない
4. **社内PCの守り**を必須にする

   | 対策 | 内容 |
   |---|---|
   | ディスクの暗号化 | BitLocker で、DB のあるドライブ（Docker Desktop のデータの置き場所）とバックアップのドライブ（`D:`）の両方を暗号化する。回復キーは PC の外に保管する |
   | 固定 | セキュリティワイヤーなどで PC を固定し、持ち出せない置き方にする。外付けの媒体に個人情報を置く場合も暗号化と固定をする |
   | ログイン | 強い Windows のパスワードと、離席時の自動ロック |

5. **バックアップは3か所**に置く（本体の DB・社内の `D:`・クラウド）。クラウド側は、過去の版を残す設定と削除からの保護を有効にし、
   社内PCに持たせる鍵は「追加だけできて削除できない」権限に絞る（社内PCがウイルスに乗っ取られてもクラウドのバックアップを消させないため）
6. 復元の手順書を作り、年に数回、別の DB に戻して件数を確かめる訓練をする
7. 会社側と開発側の分担は計画書の「案C の対策と分担」に従う

## 捨てた選択肢

- **A: DB をまるごとクラウドへ（ADR-0044）**: 物理的な安全性・可用性・任意時点への復元は最も高いが、月¥4,000〜4,500 と予算の4倍以上。
  ネットが切れるとアプリ全体が止まる。利用者が増えた・社外からの要件が厳しくなったなど、必要になった時点で見直す
- **B: ファイルだけクラウド（DB のバックアップは社内だけ）**: 安いが、社内PCの盗難・故障・火災で DB と社内のバックアップが一緒に失われる
- **外付けSSDで容量を増やす**: 法令上は置いてよいが、安全性を上げる手段にはならない（同じ場所にあり、持ち出しやすい）。容量が足りなくなったときの手段として、暗号化と固定を条件に残す

## 影響

- **費用**: クラウドはファイルとバックアップの保存容量ぶんだけ（月¥数百の見込み。4章の棚卸しで確定）
- **ネット切断時**: DB が社内にあるので、社内LANからは日報・出社予定などの入力を続けられる。止まるのは画像の表示と登録。
  社外の利用者は、社内PCに届かないので使えない（今と同じ）。オフライン時の一時保存（計画書 O6）の範囲が小さくなる
- **社内AI**: DB が社内にあるので、社内PCの中で読んで処理できる（ADR-0042 の決定5を更新）
- **失いうるデータ**: 最後のバックアップ以降の分。バックアップの頻度で決まる（まず毎日、必要なら数時間おき）
- **コード変更（実装時、別 PR）**: ファイル保存先の切り替えと既存ファイルの移行（保存ライブラリの追加は依存追加なので、その PR で ADR を足す）、
  `scripts/backup.sh` の改修（暗号化とクラウドへの送信、保存期間）、復元手順書（`docs/server_operations.md`）
- **ADR-0044 は置き換え**。ADR-0044 に書いた「DB を分割しない」理由はそのまま有効（DB は分けずに丸ごと社内に置く）
- この ADR の時点ではコード・設定の変更なし
