# ADR-0108: フォーム1項目の描画を core の共通パーシャルに寄せる

日付: 2026-09-19
状態: 採用

## 背景

テンプレートに `<div class="form-group">` が **401 箇所** 手書きされている。中身はどれも
「ラベル + 入力欄 + 補足 + エラー」で同じだが、1箇所ずつ書かれているため、書き写す
たびにズレが入る。実際に次の2つのズレが混入していた。

1. `estimation/orderer_form.html` の `<label for="id_customer">` … 入力欄の実際の id は
   `id_customer_name`。**ラベルを押しても入力欄にフォーカスが移らない。**
   スマホの小さな欄ほどラベル押しが効くかどうかが効く。
2. 同じ項目のラベル文言 … テンプレートは `顧客マスタ`、`OrdererForm` は `label="顧客"`。
   画面には `顧客マスタ` と出るが、検証エラーの文面だけ `顧客` になっていた。

どちらもテスト 2254 件を全部通る。**テストは「ラベルと入力欄が結びついているか」を
見ていない**ため、この種のズレは自動では捕まらない。

共通パーシャル自体は既に存在していた（`templates/workers/_form_field.html`、41 箇所から
include）。しかし置き場所が `workers/` で、実際には `safety/` の4画面からも使われていた。
アプリ名のフォルダに入っていると「これは workers のものだ」と読めてしまい、共通部品として
見つけられない。事実、estimation・sites・bids はどれも手書きのままだった。

## 決定

1. `templates/workers/_form_field.html` を `templates/core/_field.html` へ移す。
   `core/_bulk_delete.html` と同じ並びにし、名前からアプリ名を外す。
   **中身は変更しない。** 41 箇所の include はパスのみ差し替える。
2. ラベル文言・`for` 属性・ヘルプテキストは**フォーム定義（forms.py / models.py の
   verbose_name）を唯一の出どころ**とする。テンプレートに文言を書き写さない。
3. 手書きの 401 箇所は**一度に置換しない。** 1画面ずつ、描画後の HTML を旧版と突き合わせて
   差分を確認しながら移す。今回は `estimation/orderer_form.html` の1画面のみ。

`customer_name` のラベルは、**画面に出ている `顧客マスタ` の側に揃えた**。利用者が今
見ている文言を変えない方を採る。

## 結果

`orderer_form.html` の描画 HTML を旧版と機械的に突き合わせた差分は次の1行だけ。

```
-<label for="id_customer">顧客マスタ</label>
+<label for="id_customer_name">顧客マスタ</label>
```

つまり**壊れていたラベルの紐付けが直っただけで、他は1バイトも変わっていない。**

テンプレートは 45 行 → 41 行。行数の削減が目的ではなく、**ラベルと入力欄がズレる書き方が
そもそもできなくなること**が目的である。

## 代替案

- **(a) ズレている3箇所だけ直す** … 直近は最小の差分で済むが、次に誰かが form-group を
  書き写した瞬間に同じズレが生まれる。バグを消してもバグの生まれる余地が残る。
- **(b) django-crispy-forms のようなライブラリを入れる** … 記述量は最も減る。ただし
  絶対ルール1（依存追加は ADR 必須）に触れるうえ、401 箇所の見た目を一度に変えることに
  なり、差分を1画面ずつ突き合わせる進め方が取れない。
- **(c) 採用案** … 既にあるパーシャルを正しい場所へ移し、1画面ずつ移す。各段階で
  「描画結果が変わらないこと」を機械的に確認できる。

## 限界

- `datalist` を後ろに足す項目、似た現場名の警告を出す項目のように、**共通パーシャルに
  収まらない項目がある**。今回は `customer_name` を手書きのまま残した。パーシャルに
  引数を足して全部を飲み込ませると、パーシャル自体が読めなくなる。
  **収まらないものは手書きのまま残す**方針を採る。
- フォーム部品を `{{ form.x }}` ではなく `<input name="x">` と手書きしている箇所が
  **96 箇所**ある。こちらは widget の属性（maxlength・required・class）もフォーム定義から
  切れているため、別途扱う。
