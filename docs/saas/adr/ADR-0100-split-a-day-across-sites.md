# ADR-0100: 1日を現場ごとに分けて日報を書けるようにする

## ステータス

採用（2026-09-18）

## コンテキスト

プロダクトオーナーからの報告（2026-09-18）:

> 日報管理の画面で同じ日に複数の現場を登録しようとするとエラーが出るそうです。
> 1日の中で作業時間を区切って登録をできるようにしたいです。

再現して中身を確かめた。**保存そのものは止まっていない。** 起きているのは次の2つ。

### 1. 別の現場でも「重複があります」と赤字で出る

ADR-0079 で入れた二重登録の確認が、**現場を見ずに**「同じ日・同じ人」だけで
引っかけていた。午前A現場・午後B現場という普通の1日でも、赤い枠で
「重複があります」と出て、「このまま登録する」をもう一度押さないと進めない。

現場の人はこれを**エラーだと受け取って、そこで入力をやめる。**
「エラーが出る」という報告は、この画面のことだった。

### 2. 欄に結びつかないエラーが画面に出ていない

`reports/form.html` は `form.non_field_errors` を描いていなかった。
使用材料の行のエラーなど `add_error(None, ...)` で付けた文言は、
**どこにも出ないまま画面が戻る。** 利用者からは「押しても戻るだけ」に見える。

## 決定

### 1. 「重複」の判定に現場を入れる

| 既にあるその日の日報 | 扱い |
|---|---|
| **同じ現場** | これまでどおり確認を挟む |
| **別の現場だけ** | 止めない。そのまま保存する |

**1日に2現場へ行く日は普通にある。** 止める理由が無い。

同じ現場・同じ工種は `unique_together` が弾くので、確認が出るのは
「同じ現場の別工種」だけになる。同じ現場に1日2回書くのは、
うっかりの可能性が高いので残す。

現場の一致は**名前の完全一致**で見る。この時点では入力された現場名がまだ
現場に解決されていない（未登録なら保存時に作る）ため、名前で突き合わせる。

### 2. 止めるのは「1日24時間を超える」ときだけ

現場をまたぐこと自体は止めないが、**1人1日の合計が24時間を超える入力は
必ず打ち間違い**なので弾く。既に入っている日報の時間と、これから入れる時間を
足して見る。

所定の8時間で切らないのは、**残業も泊まり込みも実際にある**ため。
ここで8時間を上限にすると、正しい入力まで止まる。

### 3. 分けて入れた結果を、その場で知らせる

保存したあと、その人のその日に2件以上あれば内訳を出す。

```
電工太郎 さんの 9月10日 は合計 8 時間（A現場 4 / B現場 4）
```

**分けた結果がそのとおり入ったかを、一覧を開かずに確かめられる。**
「区切って登録したい」という依頼は、分けられることと、
**分けた結果が合っていると分かること**の両方が要る。

1件しか無い人には出さない。分けていないので確かめることが無い。

時間は `8.00` ではなく `8`、`8.50` は `8.5` と書く。
小数第2位まで出すと読みにくい。

### 4. 欄に結びつかないエラーを画面に出す

`form.non_field_errors` を描く。**出ていないエラーは、無いのと同じではなく、
理由の分からない「エラー」になる。**

## 捨てた選択肢

- **確認そのものを外す**: 同じ現場に1日2回書くうっかりは実際にあり、
  ADR-0079 が解いた問題が戻る
- **1日の上限を所定の8時間にする**: 残業も泊まり込みもある。正しい入力が止まる
- **現場ごとの時間を1つの画面でまとめて入れさせる**（明細行のような作り）:
  日報は1現場1件で、原価も安全書類も工期もその粒度に紐づく。
  画面の都合でその粒度を変えると、影響がアプリ全体に及ぶ
- **現場の一致を ID で見る**: 入力された現場名はこの時点ではまだ現場に
  解決されていない。解決してから見ると、確認の前に現場を作ってしまう
- **合計時間の超過を警告にとどめる**: 24時間超は打ち間違い以外にない。
  確認を挟む意味が無く、そのまま通ると原価が狂う

## 影響

### モデル・マイグレーション

**無し。** 日報の粒度（現場・作業員・日付・工種で一意）は変えていない。
**もともと別現場の日報は保存できていた。** 変えたのは、その手前の確認と画面の出し方。

### 変わる画面

| 場所 | 変わり方 |
|---|---|
| 日報の登録・編集 | 別の現場なら確認を挟まない。同じ現場のときだけ「重複があります」 |
| 日報の登録・編集 | 欄に結びつかないエラーを画面に出す |
| 日報の登録後 | その日に2件以上ある人の内訳を知らせる |
| 日報の登録・編集 | 1人1日24時間を超える入力を弾く |

### 既存データ

影響しない。既に入っている日報はそのまま。

### テスト

`tests/test_report_duplicates.py` に追加・差し替え（14件）。
同じ現場かどうかの見分け、別の現場は止めないこと、午前・午後で分けて登録できること、
24時間超を弾くこと、内訳を知らせること、1件しか無い人には出さないこと。
