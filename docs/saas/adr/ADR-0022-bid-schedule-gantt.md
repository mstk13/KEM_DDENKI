# ADR-0022: 入札案件の「受注までの流れ」ガントチャートと、その設定の持ち方

## ステータス

承認

## コンテキスト

入札公告PDFの別表には、受注までの手続きが日付つきで並んでいる。

    ① 配置予定技術者の専任期間      専任を要しない
    ② 入札説明書等の交付期間        令和8年9月4日から同年11月10日まで
    ③ 申請書、技術資料及び技術提案書の提出期限   令和8年9月17日 正午
    ④ 見積等の提出期限              該当なし
    ⑤ 入札書の受領期限              令和8年10月27日 17時
    ⑥ 開札の日時及び場所            令和8年11月11日 15時

`announcement.extract_bid_schedule` がこれを `BidProject.bid_schedule` に入れており、
詳細画面には表として出していた。ただし表では「どの手続きにあと何日使えるか」
「いま流れのどこにいるか」が読み取れず、案件ごとの段取りに使えていなかった。

別表には2つの困りごとがある。

1. **ほとんどの項目が締切の日時しか持たない。** バーの始点が無い。
2. **項目の性質が混在している。** 交付期間は窓口が開いている「期間」で他と並走するが、
   提出期限は流れの一本道に並ぶ「締切」。同じ列に並べると読み方が変わる。

さらに、どの項目を締切とみなすかは公告の書き方と会社の運用に依存する。
コードに固定すると、発注機関が変わるたびに直すことになる。

## 決定

### 1. 締切をバーに引き延ばす（カスケード）

締切を終点、ひとつ前の締切（先頭は公告日）を始点としてバーにする。
バーの長さは「その手続きに使える期間」、`progress` には進捗ではなく
**経過率**を入れる。frappe-gantt はこれをバーの塗りに使うので、
「持ち時間のうちどこまで来たか」がそのまま図になる。

### 2. 期間の項目は一本道の鎖に入れない

`kind == "period"` の項目は矢印で繋がず、後続バーの始点（カーソル）も進めない。
混ぜると、交付期間の締切（11/10）に引きずられて開札のバーが 11/10 始まりになり、
本来の 10/27（入札書の締切）から引けなくなる。

### 3. 扱いは3段階で解決する

    1. BidProject.schedule_overrides … 案件ごとの手直し（JSONField）
    2. BidScheduleRule              … 会社共通の既定（段階ごと・TenantModel）
    3. 自動判定                      … 開始日があれば期間、無ければ締切

会社の既定は `gantt._stage_of` が正規化した**段階名**をキーにする。
生のラベル（「入札書の受領期限」「入札の締切」…）は発注機関ごとに違うため、
一度設定すれば別の機関の公告にも効くようにする。

### 4. 手直しは bid_schedule を書き換えず、別フィールドに差分で持つ

`schedule_overrides` は `{ラベル: {kind, start, end}}`。
`fetch_announcements --force` で公告を読み直しても手直しが残る。
日付は日単位（ドラッグの粒度）で持ち、時刻は公告から読んだ値を再利用する。
「正午必着」「17時」を、日をずらしただけで失わないため。

## 理由

- **カスケード** … 締切だけを点で置いた図は表と情報量が変わらない。
  期間として見せると「あと何日あるか」が長さで分かる。
- **段階名をキーにした会社既定** … 案件ごとに設定させると運用が続かない。
  一度決めれば効くようにし、例外だけ案件側で上書きする。
- **差分で持つ** … 公告の再取得と利用者の手直しはどちらも起こる。
  同じフィールドに書くと、取り直しのたびに手直しが消えるか、
  公告の訂正を取り込めないかのどちらかになる。
- **frappe-gantt の再利用** … apps/schedules・apps/devkanri と同じ描画系にそろえ、
  CSS（`.bar-*`）と月ラベルの日本語化（`localizeGanttMonths`）を共有する。

## 影響

- マイグレーション `bids/0015_bid_schedule_rules`
  （`BidScheduleRule` 追加、`BidProject.schedule_overrides` 追加）
- 既存案件の `bid_schedule` は、時刻の抽出を直す前の値が入っている。
  `python manage.py fetch_announcements --force` で読み直す。
- 新規依存なし。
