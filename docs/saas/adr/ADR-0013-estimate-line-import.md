# ADR-0013: 見積ファイルから明細と材料を取り込む

## ステータス

承認

## コンテキスト

`sites:import`（見積ファイルから現場を登録）は、ライデンの CSV/Excel と見積書 PDF から
**見出し部だけ**を読んでいた。件名・宛名・支払条件・合計金額などである。

明細行は意図的に捨てていた。`importer.py` はラベルと値の組を探す走査なので、
数量や単価の並ぶ行を拾うと見出しがノイズに埋もれる。実際
`DETAIL_ROW_MIN_CELLS = 4` で「非空セルが4つ以上ある行」を除外している。

結果として、見積書に載っている材料・数量・単価は1件も登録されず、
現場に紐づく見積を作るには全て手入力し直す必要があった。

## 決定

### 1. 明細の抽出は見出しの走査と分ける

`apps/sites/line_items.py` を新設し、明細だけを対象にする。既存の
`importer.py` の走査には手を入れない（見出しの読み取り精度を落とさないため）。

ファイルの読み込みは `importer.read_rows()` に集約し、見出しの走査
（`parse_rows`）と明細の抽出（`extract_lines`）が同じ結果を使い回す。
PDF を2回開かないため。

### 2. LLM は使わない

見積書の明細は表形式が保たれているので、ヘッダ行を見つけて列を対応付ければ
決定論的に読める。ADR-0010 の3層分割でいう層0で片が付く範囲であり、
`labor_table.py`（労務単価表のパーサ）と同じ判断をとる。

実測でも、規則的な表に対しては決定論的パーサが LLM を精度・速度・費用の
すべてで上回っている（ADR-0010 の比較表）。

### 3. 読めなかったら何も返す

ヘッダ行（「名称／品名／材料名」＋「数量・単価・金額」のいずれか）を
判別できなければ**空リストを返す**。列位置を推測して数字を拾うと、
金額が1桁ずれた明細が黙って登録される。

同じ理由で:

- 「小計」「合計」「消費税」に当たったら明細は終わりとみなして打ち切る
- 名称だけで数値が無い行は小見出しとみなして飛ばす
- 金額が空なら数量×単価で補うが、**逆は補わない**。単価を金額から割り戻すと
  端数処理で元の単価と変わり、根拠のない数字が残る

### 4. 自社発行の見積を `materials.Quotation` で扱う

取り込むファイルは自社が得意先に出した見積だが、`Quotation` は
「仕入先から取得した見積書」を前提に `supplier` が必須だった。向きが逆になる。

見積モデルを2つに分けず、`Quotation` を双方向に拡張した:

| 追加・変更 | 内容 |
|---|---|
| `kind` | `received`（仕入先から受領）/ `issued`（自社が発行）。既定は `received` |
| `customer` | 自社発行のときの宛先。null 可 |
| `supplier` | null 可に変更（自社発行では空） |
| `quotation_number` / `source_filename` | 取り込み元の見積番号とファイル名 |

`QuotationItem` と `Material` の引き当てを両方向で共用でき、見積比較や
見積書 PDF 出力といった既存機能をそのまま使える。別モデルを立てると
これらを二重に持つことになる。

既存行はマイグレーションの既定値で `kind='received'` になる。追加と
null 許容だけなので expand のみで、破壊的変更は含まない。

### 5. `QuotationItem` の数量・単価を null 許容にする

見積書には「一式」計上のように金額だけで数量・単価が無い行がある。
0 を入れると「単価0円」という読めてもいない数字が残るので null を許す。

影響するのは2箇所だけで、どちらも 0 として扱わないよう直した:

- `compare_quotations` … 単価が無い明細は比較表から外す（0 だと最安に見える）
- `generate_quotation_pdf` … 空欄のまま出す

### 6. 材料マスタは自動作成しない

読み取った材料名は `find_material_by_name` で既存マスタに引き当て、
当たったものだけ FK を張る。当たらなければ `material_name`（自由入力）に
名称をそのまま残す。

得意先を自動作成しない既存方針（`find_customer_by_name`）と揃えている。
表記ゆれで重複マスタが増えるほうが後で困る。確認画面に「未登録 N 件」を
出し、マスタ整備は人の判断に任せる。

照合キーは NFKC 正規化＋大小文字統一＋空白と区切り記号の除去。
「VVF 1.6mm 2C」「ＶＶＦ1.6MM2C」「VVF-1.6mm-2c」が同じになり、
「VVF 2.0mm 2C」とは別になる。数字は落とさない。

### 7. 確認画面との往復で材料の pk を持ち回らない

確認画面を挟むため明細は一度ブラウザへ渡って戻ってくる。このとき
**渡すのは文字列だけ**にして、材料マスタの引き当ては確定時にサーバ側で
やり直す。pk を往復させると、他社の材料を指す値を送られたときに
紐づいてしまう。

戻ってきた JSON は件数・文字数を読み取り時と同じ上限で切り直し、
数値は Decimal に通し直す。

## 結果

- 見積ファイル1つで、現場・見積・明細がまとめて登録できる
- 現場と取込履歴と明細は同一トランザクション。現場だけできて明細が落ちると、
  入れ直したときに現場が二重になる
- 明細を登録しない選択もできる（確認画面のチェックを外す）
- 明細の合計は見積書の合計欄と一致しないことがある。値引きや消費税は
  明細に含まれないため、**明細の和を正とする**（画面にもその旨を出す）
