# ADR-0090: 現場の名寄せを人が直接指定できるようにし、まとめた現場を一覧から外す

## ステータス

採用（2026-09-17）

## コンテキスト

プロダクトオーナーの依頼（2026-09-17）:

> 本番の現場管理の現場一覧で、高橋住宅と高橋アパート、厚木あゆ祭りとあゆ祭りと
> 厚木鮎まつりで名前がばらばらなので高橋住宅と厚木鮎祭りに統合してください。
> その際、それぞれでこれまで登録されていたデータがあると思いますが
> すべてまとめて登録してください。

名寄せの仕組みは ADR-0084 で入っている。だが**この依頼はその画面では実行できない。**
理由が3つある。

### 1. 候補に出ない組がある

候補になるのは、文字の近さが 0.72 以上か、ローカル埋め込みの近さが 0.80 以上の組だけ。
依頼の6組を実測した。

| 組 | 文字の近さ | 候補になるか |
|---|---|---|
| 高橋住宅 ／ 高橋アパート | 0.40 | ✗ |
| 厚木あゆ祭り ／ あゆ祭り | 1.00 | ○ |
| 厚木あゆ祭り ／ 厚木鮎まつり | 0.50 | ✗ |
| あゆ祭り ／ 厚木鮎まつり | 0.20 | ✗ |

つまり**6組のうち1組しか出ない。** 残りはローカルAI（bge-m3 / qwen3:8b）が
繋がっているかどうかに懸かっている。ADR-0084 自身が
「ローカルAIに繋がらないときは文字と手がかりだけで候補を出す（止めない）」と
書いているが、そのとき**人が手を出す口が無い。**

### 2. まとめた現場が現場一覧に残る

`merge_sites` は寄せたほうの現場を消さず、`merged_into` を立てて残す
（取り消せるようにするため。ADR-0084）。ところが `site_list` は
`merged_into` を見ていない。

**依頼は「一覧で名前がばらばら」だった。** まとめても一覧の見た目が変わらないなら、
やったことが伝わらない。次の日報もそちらの名前に付く。

### 3. 揃えたい名前がどれとも違う

「厚木鮎祭り」は、登録されている3つ（厚木あゆ祭り・あゆ祭り・厚木鮎まつり）の
**どれでもない**。まとめたあとに名前を直す手が要る。

## 決定

### 1. 名寄せ画面に「手で選んでまとめる」を置く

残す現場・まとめる現場をプルダウンから選び、そのまま統合する。
候補の一覧とは独立していて、**機械が何を拾ったかに関係なく実行できる。**

機械が拾うのは「名前が似ている」か「意味が近い」組だけで、
**その外側は必ず残る。** 人が知っている二重登録を、機械の判定が
追いつくのを待って直せないのはおかしい。

3つ以上は2つずつ繰り返す。1回の操作で3件を同時に指定できるようにはしない。
**どの記録がどこへ動いたかが1回ごとに残らないと、取り消せない。**

### 2. 手で選んだ統合にも候補の行を作る

`merge_sites` は候補を渡されたときだけ、付け替えた行の id を記録する
（`SiteMergeCandidate.moved_rows`）。記録が無いと取り消せない。

**手で選んだ統合ほど取り消せるべき。** 機械の判定という裏付けが無く、
人の思い違いがそのまま通るため。候補が無ければ `candidate_for` が作る。

同じ2件の候補が向き違いで既にあることがある（機械が拾った組）。
その行を使い回す。`unique_together`（company, primary, duplicate）に
ぶつかる行を新しく作らないため。

### 3. まとめたあとの名前をその場で直せる

統合のフォームに「まとめたあとの現場名」を置く。空なら変えない。

別画面の編集へ回さないのは、**まとめた直後こそ正しい名前が分かっているから。**
「あとで直す」は直らない。今回の「厚木鮎祭り」がまさにその例で、
3つのどれとも違う名前に揃える必要がある。

### 4. まとめた現場を現場一覧から外す

`site_list` に `merged_into__isnull=True` を足す。

消しはしない。詳細を開いたときに、どこへまとめたのかと、
取り消しへの導線を出す。**リンクや履歴から来た人が「消えた」と思わないため。**

## 捨てた選択肢

- **ローカルAIが繋がるのを待つ**: 繋がるかどうかは本番の環境次第で、
  こちらから確かめられない。繋がっても判定は「迷ったら different」なので、
  人が知っている組を必ず拾う保証はない
- **文字の近さのしきい値を下げる**: 0.40 まで下げると、
  「その1」「その2」や年度違いまで候補に並ぶ。**誤って寄せる事故のほうが重い**
- **管理コマンドで名前を指定してまとめる**: 事務の担当者がコマンドを叩く運用にはできない。
  依頼はこの先も出るので、画面に無いと毎回こちらに回ってくる
- **Django admin で `merged_into` を直接書き換える**: 記録が付け替わらない。
  日報も原価も古い現場にぶら下がったままになる
- **1回の操作で3件以上を指定する**: どの記録がどこへ動いたかが1回ごとに残らず、
  取り消せない
- **まとめた現場を削除する**: 取り消せなくなる。ADR-0084 が消さないと決めた理由がそのまま効く
- **一覧に残して「統合済み」の印を付ける**: 一覧がばらばらに見えるのは変わらない。
  依頼はその見た目そのものだった

## 影響

### モデル・マイグレーション

**無し。** `Site.merged_into` と `SiteMergeCandidate` は ADR-0084 で入っている。

### 変わる画面

| 場所 | 変わり方 |
|---|---|
| 現場 > 名寄せ | 「手で選んでまとめる」を追加（残す現場・まとめる現場・まとめたあとの名前） |
| 現場一覧 | まとめた現場を出さない |
| 現場 詳細 | まとめた現場に、行き先と取り消しへの導線を出す |

### まだ残っている穴

**日報などの現場を選ぶ欄からは、まだ外していない。** 現場を選ぶ箇所は45か所あり、
まとめて直すと影響範囲がこの変更に収まらない。次の変更で
`Site.objects` の既定の絞り込みごと見直す。

今は、まとめた現場が一覧から消えることで**新しい記録が付く経路がほぼ塞がる**
（一覧から現場詳細に入る導線が主なため）。

### 本番のデータ

この変更は**画面を足すだけで、本番のデータには触らない。**
依頼の統合は、本番へ反映したあとに画面から実行する（下の手順）。

1. 現場 > 名寄せ を開く
2. 「手で選んでまとめる」で 残す＝高橋住宅／まとめる＝高橋アパート → まとめる
3. 同じ欄で 残す＝厚木あゆ祭り／まとめる＝あゆ祭り → まとめる
4. 同じ欄で 残す＝厚木あゆ祭り／まとめる＝厚木鮎まつり、
   「まとめたあとの現場名」に **厚木鮎祭り** → まとめる
5. 現場一覧で「高橋住宅」「厚木鮎祭り」の2つになっていることを確かめる

同じ日・同じ作業員の日報が両方の名前で書かれていた場合、その行は動かず警告に出る。
中身を見て、どちらを残すかを決める。

### サーバ上から名前で流すコマンド

画面を開けないとき、表記ゆれが多いときのために
`manage.py merge_sites_by_name` を用意する。画面の「手で選んでまとめる」と
**同じ道筋**（`candidate_for` → `merge_sites`）を通り、違うのは選び方が
プルダウンではなく現場名だという点だけ。取り消しも画面から同じようにできる。

```bash
# まず確かめる（書き込まない）
docker compose exec web python manage.py merge_sites_by_name \
    --keep 高橋住宅 --merge 高橋アパート

# 実際にまとめる
docker compose exec web python manage.py merge_sites_by_name \
    --keep 高橋住宅 --merge 高橋アパート --apply

# 3つ以上をまとめ、最後に名前を揃える
docker compose exec web python manage.py merge_sites_by_name \
    --keep 厚木あゆ祭り --merge あゆ祭り --merge 厚木鮎まつり \
    --rename 厚木鮎祭り --apply
```

**既定では書き込まない。** `--apply` を付けたときだけ動く。
付けずに流すと、どの現場がいくつの記録を持っているかを出して終わる。
**本番のデータを動かす操作なので、まず何が起きるかを見られることを既定にする。**

同じ会社に同じ名前の現場が2つあるときは、どちらか分からないので止める。
その場合は画面から選ぶ。

### テスト

`tests/test_site_merge_manual.py`（17件、新規）と
`tests/test_site_merge_command.py`（12件、新規）。
候補に無い組をまとめられること、名前を揃えられること、3つを2回でまとめられること、
取り消せること、同じ現場・統合済み・他社を弾くこと、一覧から消えること、
詳細に行き先が出ること、テナント越境。
