# ADR-0012: 文字が読めない公告PDFを LLM で読む（最後の手段）

## ステータス

承認

## コンテキスト

入札公告PDFのうち、フォントに ToUnicode が無いものは pdfplumber が
`(cid:NNN)` しか取り出せない。本番65件のうち1件（立川防災合同庁舎（２６）
電気設備改修工事）が該当した。この案件は他の公開文書も「指名結果書」202字だけで、
章立てを持つ文書が存在しないため、複数文書へのフォールバック（ADR-0011）でも救えない。

工事概要・参加要件が取れないと、参加資格判定は「登録があります。等級・点数の
要件は公告本文で確認してください」で止まり、判断材料が画面に出ない。

## 決定

### 1. OCR ではなく Claude に読ませる

| | tesseract | Claude |
|---|---|---|
| 依存 | `tesseract-ocr` + 日本語データ + `pytesseract` の追加 | `anthropic` は既に依存。APIキーの設定枠も予算監視もある |
| リスク | Dockerfile にシステムパッケージが増える。ビルドが失敗すると自動デプロイが止まる | なし |
| 出力 | 文字列。章立ての復元は別途必要 | 章立てを解釈した構造化データ |

本番イメージのビルドを壊す可能性がある変更を、65件中1件のために入れる判断はしない。
Claude は PDF をページ画像としても読むので、cid 化していても中身が取れる。

### 2. 決定論的な抽出が失敗したときだけ通す

`fill_announcement` は候補の公開文書を順に決定論的に読み、
**どれも読めず、かつ (cid) 化を検出した場合に限り** LLM を呼ぶ。
決定論的に読めた案件では LLM を呼ばない（テストで固定）。

これは ADR-0010（AI推論の3層分割）の考え方と揃えている。
決まった形のものは決まった手順で読み、崩れたものだけモデルに回す。

### 3. 既存の Claude 呼び出しの作法に乗せる

`apps.ai.services.llm_advisor.call_claude_with_log` を通す。これにより

- 月間予算（`AI_MONTHLY_BUDGET_JPY`）のチェック
- `AILog` への記録（プロンプト・応答・トークン数・費用・レイテンシ）
- 費用計算

が自動的に効く。新しい呼び出し口を作らない。

### 4. モデルは Sonnet

`llm_advisor` の方針は「OCR/抽出は Haiku、分析/提案は Sonnet」だが、
ここは Sonnet を既定にする。参加要件の読み違いは入札可否の判断を誤らせるためで、
純粋な文字起こしではなく「どこが競争参加資格の節か」を解釈させる作業だから。

費用は1件あたり11ページで入力2万トークン前後、$0.06 程度（¥10弱）。
決定論的な抽出が失敗した案件だけなので月数件を見込む。

### 5. 失敗しても案件取得は成功として扱う

予算超過・APIキー未設定・API側の障害はいずれも `None` を返してログに残すだけにする。
公告が読めないことを案件取得の失敗にはしない。

### 6. LLM には「以上」の判定をさせない

`required_grade`（下限）は LLM の出力から採らない。
「Ｂ等級又はＣ等級」（列挙）と「Ｄ等級以上」（下限）は判定を分ける必要があり、
ここを取り違えると参加可否が逆になる。LLM には列挙（`required_grades`）と
点数（`required_score`）だけを出させ、下限は決定論的な抽出に任せる。

また「工事成績評定点が65点未満」「証明をもって65点以上の工事とみなす」を
資格の点数と混同しないよう、プロンプトで明示的に除外させている。

## 地方自治体の資格について

資格マスタ（93件）は国の機関のみで、横浜市・神奈川県などの登録が無い。
**登録が無いことを「資格なし」とは扱わない。** 案件は取り込んだうえで
「要確認」（`eligible=None`）とし、「資格要件が無いものとして取り込んでいます。
参加できるかは公告の参加資格の記載で確認してください」と返す。

自治体の資格審査結果通知書を資格マスタに取り込めば、同じ仕組みで判定される。

## 結果

- (cid) 化した公告からも工事概要・参加要件・等級・点数が取れる
- 決定論的に読めた案件では LLM を呼ばない
- 呼び出しは `AILog` に残り、月間予算を超えたら止まる

## 代替案

- **tesseract を Dockerfile に入れる**: 本番イメージのビルドを壊す可能性がある変更を
  65件中1件のために入れない。将来 OCR が他の用途でも要るなら再検討する
- **全件を LLM に読ませる**: 決定論的に読める案件まで費用と不確実性を払うことになる
- **読めない案件を捨てる**: 参加できるかもしれない案件を黙って落とすのが一番悪い
