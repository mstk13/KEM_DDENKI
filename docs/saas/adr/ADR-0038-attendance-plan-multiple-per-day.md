# ADR-0038: 出社予定を1日に複数件にし、現場ごとの時間帯で1日を分けられるようにする

## ステータス

採用（2026-09-11）

## コンテキスト

出社予定（`AttendPlan`、ADR-0023）は作業員1人・1日1件で、`(company, worker, plan_date)` に一意制約がある。
プロダクトオーナーから次の要望があった（2026-09-11）。

> 一日の中で複数の現場を登録できるようにしたい。その際、現場ごとに何時から何時までいるのかを見られるようにしたい。
> 出社予定をあとから追加できるようにして、1日の時間を分割できるようにしたい。

1日1件のままでは「午前は A 現場、午後は B 現場」を表せず、行き先欄に「A→B」と書くしかない。
その書き方ではタイムラインは1本の帯になり、ホームの現場カードの参加者（ADR-0036）にも一致しない。

## 決定

### 1. 1件＝「1日の中の1つの予定（区分・行き先・時間帯）」にし、一意制約を外す

- 一意制約 `uniq_attend_plan_worker_date` を外し、同じ日の予定をまとめて引くための索引
  `attend_plan_date_worker_idx`（company, plan_date, worker）を置く
- 列は増やさない。今までの1件は、そのまま「その日唯一の予定」として読める
- 1日を分けるときは、同じ日に予定を足す（「＋ 時間を分けて予定を追加」）

### 2. 組み合わせのルール（プロダクトオーナーが決定）

| ルール | 理由 |
|---|---|
| 出張・有休・休み（時刻を持たない区分＝終日）はその日1件だけ | 出張の日に現場にもいる扱いになると、出社人数とホームの参加者が読めなくなる。半休は時刻を持つので「午前 半休＋午後 現場」はできる |
| 2件以上ある日は、どの予定にも開始・終了時刻を入れる | 空欄は「所定どおり」なので、空欄同士は必ず重なる |
| 時間帯を重ねない（境目がちょうど接するのは可）。終了が開始以前（夜間）は 24:00 までとして判定 | 同じ人が同じ時間に2か所にいる予定は作らせない |
| 1人1日 8 件まで | 壊れた送信などで行を大量に作らない歯止め |

ルールと保存は `apps/attendance/entries.py`（`validate_entries` / `save_day_entries`）の1か所に置き、
月表のダイアログ・塗る操作・日別シートのどこから保存しても同じ判定にする。

### 3. 保存は「その日の予定を、渡した並びに置き換える」

id が合う行は更新し、id の無い予定には余っている行を使い回し、残った行は消す。
塗り替えのたびに行を作り直すと、変更履歴（simple-history）が「削除と追加」になって追えなくなるため。
他の人・他の日の id を送られても、その行は書き換えない。

### 4. 画面

| 画面 | 変更 |
|---|---|
| 月表のマス | 1件目（開始の早い順）の区分の1文字＋「+残りの件数」（例: 現+1）。時刻は最初の開始〜最後の終了。全件はツールチップに出す（プロダクトオーナーが決定） |
| 月表のダイアログ | 予定を件数ぶん並べ、「＋ 時間を分けて予定を追加」で足す。保存は新しい `plan_entries`（1人1日ぶんを JSON でまとめて送る） |
| 月表の塗る操作（`plan_set`） | 予定が2件以上の日は塗らずにダイアログを開く（サーバも 409 で断る）。塗ると分けた予定が1件に潰れるため |
| まとめて記入（`plan_fill`） | 上書きのときは、時間で分けてあった日も1件にまとめ直す |
| 日別シート | 1人の予定を件数ぶんの行にし、氏名を縦にまとめる。「＋ 予定を追加」で行を足す。1人でも不正なら誰も保存しない |
| 1日のタイムライン | 予定ごとに帯を並べる。現場ごとに何時から何時までいるかが読める |
| ホームの現場カードの参加者 | 予定ごとに現場名と突き合わせる。午前 A・午後 B なら両方のカードにそれぞれの時間で出る。同じ現場へ2回行くなら時間を並べて1人にまとめる |

出社人数・出社日数は、これまでどおり「人」「日」で数える（2件あっても1人・1日）。

日別シートは1人に同じ名前の欄が行の数だけ並ぶので、サーバは `getlist` で行ごとに揃えて読む。
使わない欄を `disabled` にすると送信されずに並びがずれるため、`readonly` にしている。

## 捨てた選択肢

- **1件の予定に「時間帯の明細」を子テーブルで持つ**: 時間帯ごとに区分や行き先が違う（午前 半休・午後 現場）ことを
  素直に表せない。テーブルが増え、ホームの参加者の突き合わせも子テーブル単位に作り直しになる
- **行き先欄に「A 8-12／B 13-17」と書く約束にする**: 画面は変わらないが、タイムラインもホームも読めない
- **時間の重なりを許す**: 「現場 8-17」の上に「打合せ 10-11」を重ねたい場面はありうるが、
  同じ時間に2か所にいる予定がタイムラインとホームで読めなくなる。重ねたい用事は行き先・メモに書く

## 影響

- マイグレーション `attendance/0005_attendplan_multiple_per_day`: 一意制約の削除・索引の追加・並び順の変更。
  列の追加・削除は無い（制約を緩めるだけの expand）
- **前の版へ戻すときの注意**: 2件以上の日ができたあとに戻すと、一意制約を付け直すマイグレーションが失敗し、
  前の版の `get_or_create` も複数行で失敗する。戻す前に、2件以上の日を1件にまとめる必要がある
- 追加: `apps/attendance/entries.py`、`attendance:plan_entries`（`/attendance/plans/entries/`）
- 変更: `apps/attendance/models.py`・`plans.py`・`views.py`・`urls.py`、`apps/schedules/services.py`（参加者）、
  `templates/attendance/plan_board.html`・`plan_day.html`、`static/css/style.css`
