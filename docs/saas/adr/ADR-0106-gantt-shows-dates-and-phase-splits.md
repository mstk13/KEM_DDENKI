# ADR-0106: ガントを「押さなくても読める」図にする

## ステータス

採用（2026-09-19）

## コンテキスト

プロダクトオーナーの依頼（2026-09-19）:

> 現場詳細のガントチャートでは各日程ごとにいつからいつまでで何をするのかを見れるようにして下さい。
> また、ホームのガントチャートでは線で区切って工程が何日で区切れるかを見れるようにしてください。

今の作りを確かめた。どちらも **frappe-gantt 0.6.1**（ADR-0032）で、
情報がバーの中に出ていない。

| 画面 | バーに出ている中身 | 日付・日数 |
|---|---|---|
| 現場詳細（工期） | 工程名だけ | **押したときのポップアップだけ** |
| ホーム | 現場名だけ（現場1本） | **同上。工程の区切りは出ない** |

**押さないと読めない図は、図として機能していない。** 印刷しても、
スマホで眺めても、いつ何をするのかが分からない。
ホームに至っては現場の工期が1本の帯で、その中がどう割れているのかが出ない。

## 決定

### 1. 現場詳細のバーに、期間と日数を書く

バーの文字を `工程名  9/1〜9/5（5日）` にする。

**年は出さない。** 同じ年の工事がほとんどで、年まで入れるとバーの横に収まらない。
年をまたぐ工程は、押したときのポップアップに西暦で出る。

期日1日のマイルストーンは `◆ 中間検査（9/1）` とする。
**同じ日に始まって終わるものに「〜」を付けると、かえって読みにくい。**

ポップアップには工程の**メモ**も出す。「何をするのか」は工程名だけでは
足りないことがあり（「施工」だけでは分からない）、メモにその中身が書かれている。

### 2. ホームのバーを、工程の境目で区切る

現場1本のバーの上に、**工程の境目の線**と**その工程が何日か**を重ねて描く。

```
┌──────┬────────────┬──────┐
│仮設 7日│ 配線工事 20日 │試験 12日│
└──────┴────────────┴──────┘
```

frappe-gantt は **1タスク1バーで、1本を塗り分ける仕組みを持たない**
（積算案件の一覧で同じ壁に当たり、あちらは自前の描画にした。ADR-0078）。
ここでは frappe-gantt を置き換えず、**描画のあとから線と文字を重ねる**。

位置は、バーの左右を `task.start`〜`task.end` に対応させた比で出す。
**目盛りは時間に比例して並ぶので、この比がそのまま画面の位置になる。**
frappe-gantt の内部の座標計算に立ち入らないので、表示の切り替え（日／週／月）でも
同じ処理で描き直せる。

狭いところに文字を書くと重なって読めないので、幅で出し分ける。

| 区間の幅 | 出すもの |
|---|---|
| 76px 以上 | `仮設 7日` |
| 26px 以上 | `7日` |
| それ未満 | 何も出さない（線だけ） |

### 3. 区切りは開始日順に並べ、日付の無い工程は渡さない

表示順（`sort_order`）が実際の日付と食い違っていることがある。
**図は日付の順に読むもの**なので、区切りは開始日で並べ直す。

日付の入っていない工程は区切れないので渡さない。
その工程は現場詳細の一覧には出ているので、消えたわけではない。

**重なっている工程はそのまま渡す。** 重なりを潰すと工程が1つ消えたように見える。
画面では線が近づくだけで、読めなくはならない。

### 4. 工期日数は両端を含めて数える

1日工事は1日。`(終了日 - 開始日).days + 1`。既にある比較表と同じ数え方に揃える。

## 捨てた選択肢

- **ホームのガントを工程単位（`mode="phase"`）にする**: 現場ごとに行が増えて
  縦に伸びる。ホームは「どの現場がいつ終わるか」を一目で見る場所で、
  **工程を1本ずつ並べると、その一目が失われる**
- **ホームも自前の描画に置き換える（ADR-0078 のやり方）**: 日／週／月の切り替えと
  当日そろえ（ADR-0072）を作り直すことになる。**得られるものに対して壊す範囲が広い**
- **frappe-gantt の内部座標（`gantt.dates` / `column_width`）を読んで位置を出す**:
  ライブラリの内部に依存する。バーの矩形と日付の比なら、外から見える情報だけで足りる
- **バーの文字に工程の内訳まで詰める**: 5工程あると1行に収まらない。
  バーには日数だけを書き、内訳はポップアップで読む
- **日付を「2026/9/1〜2026/9/5」と西暦で書く**: バーの横幅を食い、
  ほとんどの工事で同じ年が並ぶだけになる
- **区切りの線を工程の色で塗り分ける**: 現場ごとの色（`gantt-site-N`）と
  ぶつかって、どちらの意味の色か分からなくなる。線は白い破線に統一する

## 影響

### モデル・マイグレーション

**無し。** 画面に渡す中身と描き方だけの変更。

### 変わる画面

| 場所 | 変わり方 |
|---|---|
| 工期管理 > 現場詳細 | バーに `工程名 9/1〜9/5（5日）`。ポップアップにメモと日数 |
| ホーム | 現場のバーが工程の境目で区切られ、各区間に日数が出る。ポップアップに工程の内訳 |
| 工期管理（比較） | ホームと同じ図なので同様 |

### 確かめ方の限界

**この環境では frappe-gantt を読み込めない**（CDN 配信で、送信先ポリシーが 403 で遮断する）。
そのため**実際に描画された図では確認していない。**

代わりに、frappe-gantt が描くのと同じ形の SVG を自分で組み、
`drawGanttPhaseDividers` の位置計算だけを確かめた。
3等分の工程で区切り線がバーの 1/3・2/3 の位置に出ること、
2回呼んでも印が重複しないこと（表示の切り替えで呼び直すため）を確認している。

**画面での見え方は、開発環境で確かめてもらう必要がある。**

### テスト

`tests/test_gantt_phase_detail.py`（15件、新規）。
バーの文字、マイルストーンの書き方、メモ、日付の無い工程、
区切りの並び順・日数・色、工期日数の数え方、画面に描画処理が入っていること、テナント越境。
