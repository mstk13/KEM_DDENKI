# ADR-0005: LightGBM によるコスト予測モデルの導入

## ステータス
承認

## コンテキスト
施工中の現場における最終原価の早期予測は、利益管理の最重要課題である。
Phase 0 で構築した AI 基盤（データ収集・ログ記録）を活用し、
完工済み現場の実績データから最終原価を統計的に予測する仕組みが必要になった。

候補として LightGBM、XGBoost、線形回帰、ニューラルネットワークを検討した。

## 決定
LightGBM（Gradient Boosting Decision Tree）を採用する。

選定理由：
1. **軽量・高速**: CPU のみで推論可能。GPU 不要でサーバーコストを抑制できる
2. **説明可能性**: 特徴量重要度を自然に算出でき、予測根拠をユーザーに提示できる
3. **少データでの性能**: テナントごとのデータ量（数十〜数百件）でも過学習しにくいパラメータ調整が容易
4. **依存の軽さ**: lightgbm + scikit-learn + joblib の3パッケージのみ。長期メンテナンスのリスクが低い
5. **段階的改善**: 将来 XGBoost やニューラルネットに差し替え可能な設計（CostPredictor クラスの抽象化）

不採用理由：
- **XGBoost**: LightGBM と同等性能だが、少データでは LightGBM の方がチューニングが容易
- **線形回帰**: 非線形関係（消化ペースの加速など）を捉えられない
- **ニューラルネットワーク**: テナントあたりのデータ量が少なく過学習のリスクが高い。また推論環境が重い

## 結果
- `apps/ai/services/ml_predictor.py` に CostPredictor クラスを実装
- テナントごとにモデルを分離し、`ml_models/{company_pk}_cost_model.joblib` に保存
- 学習データ 5 件未満の場合は学習を拒否し、不正確な予測を防止
- 予測結果は AILog に記録され、フィードバックループで改善可能
- LightGBM のインポート失敗時（CI 等）は graceful に機能を無効化
