# ADR-0073: 公告から読み取った内容を、あとから直せるようにする

## ステータス

採用（2026-09-16）

## コンテキスト

プロダクトオーナーの依頼（2026-09-16）: 自動スクレイピングで案件を取り込むとき、公告 PDF の中身を読んでガントチャートや案件の詳細を作っている。
**その PDF から読み込んだ内容に不備があるときに直せるようにしたい**。

今できること・できないこと:

- 工事概要・参加要件・等級・点数などは、まとめての編集画面から直せる
- **直せないもの**: 重要日程（別表から読んだ項目名・日時）、公告の原文（`summary`）、公開文書の URL
- **直しても消える**: `fetch_announcements --force`（取り直し）が、工事概要・参加要件・重要日程を空にしてから読み直す
- **時刻が落ちる**: 入札期限は日時（17時など）を持つのに、編集画面の欄が `<input type="date">` で、開いて保存すると 0時 になる
- どの値が PDF 由来で、どれを人が直したのかを持っていない（変更履歴を追うしかない）

回答（同日）:

| 項目 | 回答 |
|---|---|
| 直せる範囲 | **日程・締切・本文をすべて** |
| 手直しと取り直し | **手直しを守る**（人が直した項目は取り直しで上書きしない） |
| 直す入口 | **詳細画面の欄ごとに「直す」** |
| AI での読み直し | **付ける**（読み取り結果を見てから、選んだ項目だけ入れる） |

似た仕組みが既にある: ガントの日程の手直し（`schedule_overrides`、ADR-0022）は、公告を取り直しても残る。

## 決定

### 1. 「人が直した」印（`BidProject.corrected_fields`）

- 直した項目の名前を並べて持つ（`["work_outline", "bid_schedule"]` のように）
- 取り込み・取り直しは、この印の付いた項目に触らない
  - `fill_missing_fields`: 空でも埋めない
  - `fill_announcement`: 書き換えない
  - `fetch_announcements --force`: 取り直しの前に空にしない
- 印は**項目ごと**。直していない項目は今までどおり公告から埋まる

### 2. 欄ごとに直す

詳細画面の欄に「直す」を置き、その場で開いて直す（まとめての編集画面も残す）:

| 欄 | 直せるもの |
|---|---|
| 案件情報 | 公告日・**入札期限（日時）**・開札日 |
| 参加資格判定 | 業種・等級（下限・列挙）・点数・資格の機関 |
| 重要日程 | 行ごとに**項目名・日時・補足**。項目名を空にすると行が消え、空の行に入れると足せる |
| 工事概要 | 本文 |
| 参加要件 | 本文 |

- 入札期限は `<input type="datetime-local">` にして、公告から読んだ時刻を落とさない（まとめての編集画面も同じ）
- 重要日程は `bid_schedule` を直接書き換える。`schedule_overrides`（扱い・ガントの位置）はそのまま別に持つ
  - 日程の「中身（いつ・何の手続きか）」と「見せ方（どの段階か）」は別物で、後者は会社の既定とも組み合わさるため

### 3. AI で読み直す

- 工事概要の欄の「AI で読み直す」で、公開文書を Claude に読ませる（ADR-0012 と同じ入口 `announcement_llm.extract_with_llm`）
- **その場では保存しない**。読み取った工事概要・参加要件・必要等級・必要点数を、今の内容と並べて出す
- チェックを入れた項目だけを入れ、入れた項目には手直しの印を付ける（人が見て選んだものなので、取り直しで書き換えない）
- 使えないとき（API キー未設定・月の上限・読める文書が無い）は、その理由を画面に出して終わる

## 捨てた選択肢

- **手直しを別テーブルに持つ**（`schedule_overrides` と同じ形）: 項目が多く、表示のたびに重ね合わせが要る。
  「直した値そのもの」を持てば足りるので、印だけを別に持つ形にした
- **取り直しのたびに、違いを確認する画面を出す**: 取り込みは夜間のバッチで動くので、確認待ちの案件が溜まる
- **AI の読み直しをそのまま保存する**: 読み違いを直すための機能なのに、また読み違いが入る
- **公告の原文（`summary`）も直せるようにする**: 情報源の原文は「取得したまま」に意味がある

## 影響

- マイグレーション `bids/0025_bid_corrected_fields`（null 不可の JSON 列を既定 `[]` で足すだけ）
- 既にある案件は印なし。次に人が直した項目から守られる
- 新しい依存なし。AI は既存の Claude 呼び出し（月間予算の確認つき）を通す
