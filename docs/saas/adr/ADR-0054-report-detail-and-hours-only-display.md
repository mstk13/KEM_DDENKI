# ADR-0054: 日報の詳細画面と、作業時間だけの日報の時間表示

日付: 2026-09-14
状態: 採用

## 背景

1. 日報一覧から 1 件の中身を見るには編集画面を開くしかなく、読むだけでも編集フォームになっていた。
   「一覧の各日報をタップしたら詳細が表示されるように」という要望。
2. 「PDF で作業日報を開くと作業時間と残業時間が入力されていない」という報告。

2 の原因: 日報は開始・終了を入れずに作業時間だけを直接入力できる（日報フォームの作業時間欄、
まとめて書くときの人ごとの作業時間欄）。通常時間・残業時間は `DailyReport.save()` の
`calculate_hours()` が **開始・終了があるときだけ** 計算するので、作業時間だけの日報は
残業 0・通常時間 空のまま保存される。PDF（ADR-0053）の作業時間欄は開始〜終了しか書かず、
残業欄は保存された残業時間しか見ていなかったため、両方とも空欄になっていた。

## 決定

### 時間の表示

- `DailyReport.hours_breakdown()` を足し、表示用の (作業時間, 通常時間, 残業時間) を返す。
  - 開始・終了がある: 保存時の計算値
  - 作業時間だけ: `calculate_hours` と同じ基準（8 時間を超えた分が残業）で作業時間から出す
- PDF の作業時間欄は、開始・終了が無ければ「10 時間」のように時間数を書く。残業欄は
  `hours_breakdown()` の残業を書き、日報がある行で残業が無ければ「0 h」とする（空欄だと未入力に見えるため）。
- **保存値は変えない**（マイグレーション・データ移行なし）。月次サマリの残業合計や AI のデータ収集は
  保存値を合計しているので、作業時間だけの日報の残業はそちらには入らないまま。保存時の計算を
  作業時間だけの日報にも広げると既存データの集計が変わるため、要否は別に決める。

### 詳細画面

- `reports:detail`（`/reports/<pk>/`）。自社の日報だけ（他社は 404）、ログイン必須。
- 作業員・現場・発注先・工程・工種・天候、開始〜終了（日をまたぐときは日付付き）・作業時間・通常時間・残業時間、
  協力会社、作業内容、使用材料、その他、作成者・承認者を出す。作業時間だけの日報は
  「通常・残業は作業時間から計算」と添える。
- ボタン: 一覧に戻る・編集・PDF、承認（承認できる人かつ提出済のときだけ）、削除（削除できるときだけ）。
- 一覧の行全体と日付をリンクにする（行はクリック・Enter で開く。行の中のボタン・リンク・チェックボックスは
  それぞれの動作を優先）。リンクには一覧の URL を `next` で付け、詳細の「一覧に戻る」と「編集」の戻り先で
  絞り込みを保つ。`next` は既存の `_back_url`（同じホストだけ）で検証する。

## 結果

- 一覧から 1 タップで日報を読める。編集・PDF・承認・削除は詳細からも行える
- 作業時間だけで入力した日報も、PDF と詳細に作業時間と残業が出る
