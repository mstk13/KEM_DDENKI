# ADR-0061: 現場の安全書類（KY用紙・安全作業確認書）をアプリで記入し、朝8時に知らせる

## ステータス

採用（2026-09-14）。第1段（記入・PDF・アプリ内の知らせ）。スマホのプッシュ通知は第2段で別に入れる

## コンテキスト

プロダクトオーナーの依頼（2026-09-14）:

- 現場ごとに毎日「安全作業確認書」と「KY用紙」を記入しているので、アプリで現場ごとに記入したい
- フォーマットは会社の Excel「現場ごとの書類一覧.xlsx」の「安全作業確認書」「KY用紙」シート
- 現場詳細の中に、KY と安全作業確認書を記入する機能を置く
- 毎朝、事前に登録されている現場に出る場合は、朝8時ごろに通知を出す

回答（同日）:

| 問い | 回答 |
|---|---|
| 安全作業確認書（新規入場者用・導入教育）はいつ書くか | **現場ごとに1人1回（初めて入るとき）** |
| KY用紙（安全作業指示書）はどう書くか | **現場ごと1日1枚。作業責任者が上半分、参加者がそれぞれ自分の行** |
| 自筆サイン | **スマホの画面に指で書く**（PDF にそのサインを出す） |
| 確認書の住所・緊急連絡先・経験年数・血液型・血圧・視力 | **作業員の登録内容を自動で入れる**（その場で直せる） |
| 通知の出し方 | アプリ内の通知＋スマホのプッシュ通知 |
| 通知する人 | **その日その現場に出る人全員** |
| 記入した用紙 | **指定のフォーマットどおりの PDF も出す** |

今までの `reports.SafetyTemplate`・`SafetyRecord` は、ひな型ファイルを置いて「記入済み」の印を付けるだけで、用紙の中身は書けなかった。

## 決定

### 1. 新しいアプリ `apps.safety`

| モデル | 1件の単位 | 中身 |
|---|---|---|
| `EntryConfirmation`（安全作業確認書） | 現場 × 作業員（1回） | 本人・所属・協力会社・住所・緊急連絡先・経験年数（年・月）・血液型・血圧・視力、感電防止の教育、具合の悪い所、①〜⑦の質問、自筆サイン |
| `KySheet`（KY用紙） | 現場 × 作業日（1枚） | 作業班名・予定人数・作業時間・作業責任者・作業場所と作業内容・安全指示・注意ポイント⑦⑧・危険の行（JSON）・SC-5 の朝礼時確認（JSON）・備考・指導事項・現場巡視指導記録・サイン4か所 |
| `KyParticipant`（KY用紙の参加者の行） | KY用紙 × 作業員 | 健康状態（○△）・不調の症状・検電器（○×－）・氏名の自筆サイン・サインした日時 |

- 様式の文言は `apps/safety/formats.py` に Excel のとおりに置き、画面と PDF で共有する
- 危険の行（5行）と SC-5（6行）は様式で行の数が決まっているので JSON で持つ
- サインは画面の canvas に書いた PNG を data URL の文字列で持つ（`static/js/signature-pad.js`）。
  受け取るときに PNG であること・大きさ（30万文字まで）を確かめる

### 2. 最初の値

- KY用紙: 作業時間は様式の 8:00〜17:30、作業責任者は現場担当者、予定人数はその日の参加者の数。
  同じ現場の前の用紙があれば、作業班名・作業時間・作業責任者・作業内容・安全指示・注意ポイント・危険の行を写す（危険度と作業中確認は写さない）。
  前の用紙が無ければ、様式に初めから書いてある危険（感電・転倒・墜落・物の落下）と低減措置を入れる
- 安全作業確認書: 作業員の登録（ADR-0057・ADR-0059）から住所（郵便番号つき）・電話・緊急連絡先（続柄つき）・血液型・経験年数（起算日から年・月）、
  最新の健康診断から血圧と視力（矯正があれば矯正、無ければ裸眼）。記入した時点の値を書類に残し、あとで登録が変わっても書類は変えない

### 3. 見られる人・書ける人

- KY用紙: ほかの現場の画面と同じ（ログインした同じ会社の人）。参加者の行は、自分のスマホで書いても、1台を回して作業員を選び直して書いてもよい
- 安全作業確認書: 住所・緊急連絡先・健康の値を含むので、`can_view_worker_private`（社長・管理者（Y）・事務員・Developer・本人）が通る人だけが見て書ける。
  ほかの人には、誰が書いたかと記入日だけを出す

### 4. 画面

| 画面 | URL |
|---|---|
| 現場詳細の「安全書類」の欄（今日の KY 用紙の記入人数・まだの人の数） | `/sites/<id>/` |
| 現場の安全書類（今日の参加者と記入済み・これまでの KY 用紙・安全作業確認書の一覧） | `/safety/sites/<id>/` |
| KY用紙（上半分・参加者の一覧・サイン4か所） | `/safety/sites/<id>/ky/<YYYY-MM-DD>/` |
| 自分の行を書く | `/safety/sites/<id>/ky/<YYYY-MM-DD>/sign/` |
| 指導事項・確認・作業完了報告・現場巡視指導記録のサイン | `/safety/ky/<id>/signoff/<kind>/` |
| 安全作業確認書を書く・見る・直す | `/safety/sites/<id>/entry/new/`・`/safety/entry/<id>/`・`/safety/entry/<id>/edit/` |
| PDF | `/safety/ky/<id>/pdf/`・`/safety/entry/<id>/pdf/` |

KY用紙・自分の行・安全作業確認書は、圏外でも保存して電波が戻ったら送る（ADR-0048 の対象に追加）。

### 5. PDF（`apps/safety/pdf.py`）

- Excel のシートと同じ並び・同じ文言で、A4 縦1枚に出す。日本語フォントと表の枠は日報の PDF（ADR-0053）と同じもの
- KY用紙: 危険度は「大・中・小」を書いて選んだものを赤い丸で囲む。参加者は左右2列×10行（20人）、21人目からは次の用紙に参加者の欄を続ける
- 安全作業確認書: 答えを選ぶ質問は、選んだ答えを赤い下線で示す。サインは氏名の横に描く

### 6. 朝の知らせ（第1段はアプリ内の通知）

- `python manage.py send_safety_reminders`。`scripts/scheduler.sh` が毎日 **08:00〜12:00** に1回実行する
  （昼を過ぎてから再起動などで走ると朝の知らせにならないので、12:00 までに限る）
- 対象の現場: 受注済・施工中
- 宛先: その日の参加者（ホームの現場カードと同じ判定 `schedules.services.site_members_on_day`。
  出社予定の行き先がその現場の人と、配置されている人。予定で現場にいない人は除く）のうち、ログインのアカウントがある人
- 内容: 「【現場名】今日のKY用紙を記入してください」。その日の KY 用紙へのリンク。安全作業確認書がまだの人には、それもあわせて書く
- 同じ現場・同じ日の用紙・同じ人には1回だけ（URL に日付が入っているので、それで重ねない）
- 通知の種類に「安全書類」を足した（`Notification.Module.SAFETY`）

## 第2段（別の PR）: スマホのプッシュ通知

- Web Push（`pywebpush`）で、アプリを開いていなくてもスマホに朝の知らせを届ける。新しい依存になるので、その PR で ADR を足す
- 送るための鍵（VAPID）をサーバーの `.env` に置く必要があり、`docker-compose.yml` の web と cron の両方に渡す
- iPhone はホーム画面に追加したアプリ（iOS 16.4 以降）で、最初に1回「通知を許可」が要る

## 捨てた選択肢

- **KY用紙を1人1枚ずつにする**: 様式は1枚に作業責任者の指示と参加者全員の行が並ぶ形。1人1枚にすると紙の用紙と合わない
- **安全作業確認書を毎日書く**: 様式が「新規入場者用（導入教育）」で、初めて入るときの書類
- **サインをボタンでの確認にする**: 提出先に紙と同じ形で出すため、手書きのサインを残す
- **今までの `SafetyTemplate`・`SafetyRecord` を作り替える**: 今のデータと画面はそのまま残し、使われなくなったら別に片付ける（expand/contract）
