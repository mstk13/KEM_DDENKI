KEM_DDENKI 開発者マップ

ケンモチ電機の業務管理システム（Django 5.2 / Python 3.12）の全体像を、図で1枚に収めたページです。 「何がどこにあり、どう繋がっていて、触ったら何が動くのか」を掴むことを目的にしています。

1. 30秒で掴む

電気工事会社の業務を 現場（Site）を軸に一本化 した社内SaaSです。 入札で案件を取り、現場になり、日報が積み上がり、原価に落ちる ── この一本の流れが背骨で、 他のモジュールはすべてこの背骨のどこかに接続しています。

設計の芯にある3つのルール

ルールなぜ
ロジックは services.py ビューは薄く保つ。将来 DRF → Next.js に移すとき、ビューを捨てても業務ロジックが残るように。
業種名をコードに書かない 「電気工事」を分岐条件にしない。業種差は WorkType マスタのデータで表現する。他社に売るときの分岐爆発を避けるため。
金額は Decimal のみ float 禁止。原価・予実は 工種 × 原価区分 の粒度を崩さない。

3. リクエストが通る道

ログイン済みの利用者が画面を1枚開くまでに、必ず2つのミドルウェアを通ります。 ここを理解していないと「なぜ他社のデータが見えないのか」「なぜ404になるのか」が分かりません。

覚えておく2つのマネージャ

呼び方ふるまい使いどころ
Model.objects contextvar の company で自動フィルタ 原則こちら。画面から来る処理はすべて
Model.unscoped フィルタしない（全テナント） テナントコンテキスト未設定の経路、バッチ、越境集計。使うなら company= を明示し、理由をコメントに書く

ミドルウェアの免除パス: /, /admin/, /login/, /logout/, /health/, /static/, /media/ （apps/core/middleware.py）。

5. データモデル

82モデルすべては載せません。Site を中心にした主要な結線だけを示します。 全テーブルが company_id を持ち、ほぼ全モデルに django-simple-history の履歴テーブルが付きます。

新しいモデルを足すときの決まり：TenantModel を継承し、 HistoricalRecords() を付け、admin 登録・テナント越境テスト・マイグレーションを 同じ PR に入れる。

6. 業務の本流

入札で取った案件が、現場になり、日報が積み上がり、原価に落ちるまで。 この図がこのシステムの背骨です。

日報の承認が原価を作る

ここが「入力が会計に変わる」唯一の瞬間なので、触るときは慎重に。 

# apps/reports/services.py
def approve_report(report, approved_by):
    """日報を承認し、労務費を計上する。"""
    report.status = DailyReport.Status.APPROVED
    report.approved_by = approved_by
    report.approved_at = timezone.now()
    report.save()
    create_labor_cost_from_report(report)   # ← CostTransaction が生まれる
    return report

原価データの訂正は 行を消さず create_reversal() で逆仕訳を立てます （CostTransaction.SourceType.REVERSAL）。監査証跡を壊さないためです。

日報は4種別ある

種別誰が書くか
electrician 電工現場作業員。既定値
management 管理現場管理
office 事務社員番号 G/S/A/P の人。1枚に複数現場を書ける
it IT開発担当

8. 見積ファイル取込

ライデン（積算ソフト）が書き出す Excel / CSV、または見積書 PDF から現場の数値を起こす経路です。 入口は2つあり、目的が違います。

読み取りの方針

方針理由
列位置ではなくラベル名で探すライデンの版や書き出し方で列の並びが変わるため
読めなければ None のまま返す推測で埋めるより空欄のほうが安全。確認画面で人が入れる
値は 同セル → 右 → 下 の順に探す「見積番号：12345」も「ラベル / 値が隣接」も「見出しの下」も実在するため
Excel は全シートを見る表紙に見出し・別シートに明細、という作りが多い
得意先は自動作成しない表記ゆれで重複マスタが増えるほうが後で困る。引き当てられなければ人に選ばせる
既存現場への反映は既定で空欄だけ現場担当が直した値を取り込みで黙って上書きしないため。備考は置き換えず追記

.xls（旧形式）は openpyxl が読めないため、拡張子の時点で 「.xlsx で保存し直してください」と案内して弾いています。

10. ログインと権限

Django 標準のログインではありません。社員番号ベースです。 superuser を作っただけでは画面にログインできません（Worker レコードが要ります）。 テナントは KEMMOCHI_DENKI。

権限は2系統ある

系統効き方実装
アプリ権限
（URL単位）		 作業員ごとに触れるモジュールを制限。allowed_apps が空なら制限なし AppPermissionMiddleware
ロール権限
（機能単位）		 ロール × モジュールで R/W/A。原価は別途 CostAccessGrant で個別付与 permissions/services.py

管理者の抜け道: is_superuser、または社員番号が Y で始まる Worker は アプリ権限チェックを素通りします。

12. push から反映まで

autodeploy の実体は ~/kem-ops/autodeploy.sh（リポジトリ外）です。 正はリポジトリの tools/autodeploy/autodeploy.sh で、実行のたびに常設コピーへ同期されます。 リポジトリ内を直接叩く構成にすると、巻き戻し時にスクリプトごと消えて停止します（実際に起きました）。

設定 ~/kem-ops/autodeploy.conf / ログ ~/kem-ops/autodeploy.log。

テストの回し方

web コンテナに pytest と ruff は入っていません。 docker compose exec web python -m pytest は No module named pytest になります （Dockerfile は本体依存しか入れず、両者は pyproject.toml の dev extras にあるため）。 使い捨てコンテナで回してください。

# PowerShell から（Git Bash だとパスが C:/Program Files/Git/app に化けて失敗します）
docker run --rm --entrypoint sh `
  -v "${env:USERPROFILE}\projects\KEM_DDENKI_work\saas:/app" -w /app `
  -e USE_SQLITE=true -e PYTHONDONTWRITEBYTECODE=1 kemdev-web `
  -c "pip install -q pytest pytest-django ruff; ruff check .; \
      python manage.py collectstatic --noinput >/dev/null; \
      python -m pytest tests/ -q"
  • --entrypoint sh は必須。付けないと entrypoint.sh が migrate と collectstatic を流してサーバーを起動してしまい、テストまで進みません。
  • collectstatic を先に流さないと「Missing staticfiles manifest entry」でテンプレート描画テストが落ちます。
  • 全体で約2分。
  • 同じ形で KEM_DDENKI_dev\saas をマウントすると素の origin/developer を検証できます。自分の変更が原因か上流由来かの切り分けに使えます。

main直接コミット禁止。PR + CI green + レビュー1名。本番へ自動反映

14. 踏んだ落とし穴

すべて実際に起きたものです。同じ穴を掘り直さないために。

症状原因と対処
編集した内容が消える KEM_DDENKI / KEM_DDENKI_dev で編集した。自動デプロイが2分おきに reset --hard する。_work で編集する
superuser を作ったのにログインできない ログインは社員番号ベース。Worker レコードが要る
自動デプロイが止まった リポジトリ内のスクリプトを直接叩く構成にして、巻き戻しでスクリプトごと消えた。常設コピー ~/kem-ops/ から動かす
自動デプロイが長時間ロックを保持 GitHub トークン失効で git fetch が入力待ちに。現在は待たずに失敗させて WARN を出す（2026-08-10 に38分ロックした）
No module named pytest ランタイムイメージに dev 依存は入っていない。使い捨てコンテナで入れて回す
「Missing staticfiles manifest entry」でテストが落ちる collectstatic を先に流していない
自動生成コミットが壊れている モデルを変えてマイグレーションを同梱し忘れている。makemigrations --check --dry-run を必ず流す
Windows でコンテナが起動しない 改行コードが CRLF。entrypoint.sh を Linux が実行できない。LF に固定する
Bash から docker run -v "$PWD/..." が失敗 Git Bash がパスを C:/Program Files/Git/app に変換する。PowerShell から実行する
Docker のイメージ・ボリュームが消えた 2026-08-08 に発生（pgdata 消失・バックアップ無し）。以後は毎日 12:30 に D:\backup\kem_ddenki\ へ自動バックアップ

docker compose logs web
  → ~/kem-ops/autodeploy.log

      → Worker / Position
