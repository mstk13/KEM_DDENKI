<h1 align="center">KEM_DDENKI — ケンモチ電機 業務管理システム</h1>

電気工事の業務フローを一気通貫でカバーする統合Webアプリケーション。  
日報・原価・材料・入札・積算・工期・人材・営業・取引先・開発管理の **17モジュール** を1つのプラットフォームで提供します。

**まず読むページ**

| 立場 | ページ |
|------|--------|
| 現場・事務で**使う**人 | この下の [アクセス方法](#アクセス方法) |
| **開発する**人 | [開発者マップ](index.html)（全体像を図で1枚） → [開発者ガイド](docs/developer_guide.md)（手順） |
| サーバーを**管理する**人 | [サーバー運用ガイド](docs/server_operations.md) |

> **開発者マップ** は `index.html` をブラウザで開いてください。GitHub 上ではHTMLのソースが表示されるだけなので、
> `python -m http.server` でリポジトリ直下を配信して `http://localhost:8000/index.html` を開くのが確実です。

## 技術スタック

| レイヤー | 技術 | 用途 |
|---------|------|------|
| **Web フレームワーク** | Django 5.2 LTS / Python 3.12 | テンプレートベースのフルスタック |

| **AI — LLM** | Claude API (Haiku / Sonnet) | PDF解析・コスト分析・工程提案 |
| **AI — ML** | LightGBM / scikit-learn | コスト予測モデル |
| **AI — Embedding** | bge-m3 (1,024次元) | 積算品目の名寄せ（類似度マッチング） |
| **ネットワーク** | Tailscale Serve | HTTPS終端・VPN内限定アクセス |
| **コンテナ** | Docker Compose | db / redis / web / cron の4サービス |
| **CI/CD** | GitHub Actions + 自動デプロイ | テスト・リント・2分おき自動反映 |
| **PWA** | manifest.json + Service Worker | スマホ・PCのホーム画面から起動 |

## 📶 圏外で入力したとき

資格の登録・健康診断の登録・納品の記録・現場写真の登録・KY用紙・安全作業確認書は、**圏外でも入力して保存できます**（写真・書類・サインを含む）。電波が戻ったら自動で送ります。

1. 電波のあるときに、アプリを**一度開いておく**（どの画面でもかまいません）
   - これで、圏外でアプリを開いても「**📷 現場写真を撮る**」と「未送信の入力」が使えます。圏外でアプリを開くと、ホームの代わりに「未送信の入力」が開くので、そこの「📷 現場写真を撮る」から登録してください
   - 資格・健康診断・納品の画面は、電波のあるときにその画面を一度開いておくと、圏外でも開けます
2. 圏外で入力して「保存」を押すと、この端末に保存され「未送信の入力」画面に移ります。上部に **未送信 N** が出ます
3. 電波が戻る・アプリを開くと、自動で送ります。送れたら「送信しました」と出て、端末からは消えます

- 送れなかった入力は、上部の **未送信 N** を押すと理由と一緒に見られます（ログインし直す・入力を直す）
- **端末には必ず画面ロックを設定してください**。送り終えるまで、入力（健康診断の書類を含む）が端末の中にあります
- ログアウトすると、未送信の入力も端末から消えます（未送信があれば確認が出ます）
- `https://…ts.net` の URL で開いてください。IP を直接打つ `http://100.76.219.49:8000/` では、圏外で画面を開けません

## 📷 現場写真を登録する

現地調査や施工状況の写真を、**どこの（撮影場所）・どのような（種類）写真か**と一緒に現場ごとに残せます。

1. **ホーム**の「**📷 現場写真を撮る**」（施工中の現場カードの「📷 写真を撮る」なら、その現場を選んだ状態で開きます）
   - 現場詳細の下の「**現場写真**」→「**+ 写真を登録**」からも登録できます
2. **現場**を選ぶ
3. 「写真」で撮影するか、写真を選ぶ（**まとめて 20 枚まで**）
4. **種類**（現地調査・施工前・施工中・施工後・その他）と **撮影場所**（例: 2F 東側 分電盤）を入れて「登録する」

- 写真は**撮影日ごとに自動で分けて**並びます。日付の見出しを押すか、一覧の「すべての日」を切り替えると、その日の写真だけを見られます
- 撮影日を空欄にすると、写真に記録された撮影日を使います（読めなければ今日）
- 撮影場所は、その現場で前に使った場所が候補に出ます
- 「すべて見る」で、種類や撮影場所・メモの文字で絞り込めます。写真を押すと元の大きさで開きます
- 一覧の「編集」で種類・撮影場所・撮影日・メモを直せます。削除すると写真のファイルも消えます
- 圏外でも登録できます（上の「圏外で入力したとき」）。電波のあるときにアプリを一度開いておけば、圏外でアプリを開いても「未送信の入力」→「📷 現場写真を撮る」から登録できます（どの現場の写真も撮れます）

## 📁 提出書類を管理する

現場ごとに**提出する書類のリスト**があり、書類ごとに **PDF と Excel のファイル**を置いて、提出の状況を記録できます。

1. 現場詳細の「**提出書類**」→「**書類のリストを開く**」
   - 最初は、会社の「現場ごとの書類一覧.xlsx」をもとにした **24 種類**が、着工時・施工中・完成時・その他に分かれて出ます
2. 書類名を押す
3. 「ファイル」で PDF（.pdf）か Excel（.xlsx・.xls）を選び「**ファイルを登録**」（まとめて 10 件まで、1件 50MB まで）
4. 「提出の状況」で **未作成・作成済み・提出済み・不要** を選び、提出日とメモを入れて「保存する」
   - ファイルを置くと「作成済み」になります。「提出済み」で提出日が空欄なら今日になります

- **リストに無い書類**は、書類のリストの下の「**+ リストに無い書類を足す**」で名前と時期を入れて足します。「**次の現場からも最初のリストに入れる**」にチェックすると、これから開く現場のリストにも出ます
- この現場で**要らない書類**は、状況を「**不要**」にしてください（「提出済み N / M」の数に入りません）。足した書類は削除もできます
- 同じ書類にファイルを何件でも置けます（PDF と Excel の両方、差し替え前の版など）。新しいものが上に並び、要らないものは「削除」で消せます
- PDF は押すと画面で開き、Excel はダウンロードされます。見られるのは同じ会社のログインした人だけです
- 会社の最初のリストの名前・並び順・入れる／外すは、管理画面（提出書類の最初のリスト）で変えます。変えても、もう開いた現場のリストは変わりません

## 📄 入札案件の読み取りを直す

自動で取り込んだ入札案件は、**公告 PDF を読み取って**工事概要・参加要件・重要日程・入札期限を入れています。読み違いがあれば、案件の詳細画面で直せます。

- 値をタップするとその場で直せます。工事概要・参加要件は見出しの「**この欄を直す**」から直します
- **直した項目は、公告を取り込み直しても書き換わりません**（工事概要・参加要件には「**手直しあり**」と出ます）
- 重要日程の日付は、表の日付をタップするか、ガントのバーを動かして直します
- **入札期限**は時刻まで入れられます（17時まで、など）。編集画面で保存しても時刻は消えません
- 工事概要の欄の「**AI で読み直す**」を押すと、公告 PDF を AI が読み直します。読み取った内容を今の内容と並べて出すので、**入れる項目にチェックを入れて**「これで直す」を押してください（押すまで保存されません）
- AI の読み取りは目安です。入れる前に公告の原本と見比べてください

## 🏢 自社情報（会社の書類）

経営規模等評価結果通知書（経審）・許可証・証明書など、**会社そのものの書類**をしまっておく場所です。サイドバーの「**開発・自社情報**」→「**自社情報**」で開きます。

1. 「**+ 書類を登録**」で、書類の種類を選び、PDF か Excel（.xlsx・.xls）を選ぶ
2. 発行日と、更新が必要なら**更新日**を入れる
3. ファイルを開いて中身を確かめ、「**中身を確認しました**」にチェックを入れて登録する
4. 書類を開いて「**AI で読み取る**」を押すと、何が書かれているか（書類の名前・番号・評点・金額など）と要約が出ます

- 一覧に無い書類は、種類で「**一覧に無い書類**」を選んで名前を付けると、会社の一覧にも足せます
- 同じ種類を入れ直すと、前の書類は「**前の版**」として残ります（経審のように毎年出るもの）
- **更新日を入れた書類**は、更新日の **3か月前・1か月前・2週間前**と当日・過ぎた日に通知が届きます
- **建設業許可**（業種・許可番号・有効期限）も同じ画面に一覧で出ます。登録・編集は「入札参加資格」の画面です
- AI が読み取った日付は、空欄のときだけ入ります。**必ず原本と見比べて**、違っていれば直してください
- 見られるのは**社長・管理者・事務員**だけです（売上や評点が含まれるため）

## 📋 安全書類（KY用紙・安全作業確認書）

現場ごとの **KY用紙（安全作業指示書）** と **安全作業確認書（新規入場者用）** を、スマホで記入して PDF で出せます。様式は会社の「現場ごとの書類一覧.xlsx」と同じです。

**毎朝 8 時ごろ**、その日その現場に出る人（出社予定の行き先がその現場の人と、配置されている人）に「今日のKY用紙を記入してください」と通知が届きます。通知を押すと、その日の KY 用紙が開きます。

### KY用紙（現場ごとに1日1枚）

1. 現場詳細の「**安全書類**」→「**今日の KY 用紙に記入**」（または通知から開く）
2. **作業責任者**は「KY 用紙を開く」で、作業班名・作業内容・安全指示・予想される危険（大・中・小）と低減措置・SC-5 の確認を書いて「KY 用紙を保存」
   - 前の日の用紙から、作業内容や危険の行が最初から入っています（危険度と確認は毎日選び直す）
3. **参加者**はそれぞれ「**自分の行を書く**」で、健康状態（○・△）・検電器（○・×・－）を選び、枠の中に**指でサイン**して「記入する」
   - 1台のスマホを回して書くときは、作業員を選び直してから書く
4. 現場代理人・作業責任者は、KY 用紙の下の「サイン」から、指導事項・確認・作業完了報告・現場巡視指導記録にサインする
5. 「**PDF**」で、様式どおりの用紙を出せます（参加者が 20 人を超えたら次の用紙に続きます）

### 安全作業確認書（現場ごとに1人1回・初めて入るとき）

1. 現場詳細の「**安全書類**」→「**自分の確認書を書く**」
2. 住所・緊急連絡先・経験年数・血液型・血圧・視力は、**作業員の登録内容から最初に入っています**（違っていたらその場で直す。登録は変わりません）
3. 質問に答えて、**指でサイン**して「登録する」
4. 「**PDF**」で様式どおりの用紙を出せます

- 安全作業確認書は住所や健康の値を含むので、**見て書けるのは管理者・事務員・本人だけ**です
- どちらも圏外で保存でき、電波が戻ったら自動で送ります（上の「圏外で入力したとき」）
- 朝の知らせは、スマホで通知を受け取る設定にしておくと、アプリを開いていなくても届きます（下の「スマホに通知を受け取る」）

## 🔔 スマホに通知を受け取る

アプリを開いていなくても、ベルに届く通知（朝の KY の知らせ・資格の期限など）を**スマホの通知**で受け取れます。受け取りは**端末ごと**にオンにします。

1. 通知の画面（右上の 🔔）の「**📱 スマホへの通知**」→「**この端末で通知を受け取る**」（ホームの案内からも押せます）
2. 「通知を許可しますか？」と聞かれたら「**許可**」
3. 「**テスト通知を送る**」で、届くか確かめる

- **iPhone・iPad** は、Safari の共有ボタン →「**ホーム画面に追加**」をして、**ホーム画面のアプリから開いて**からオンにしてください（iOS 16.4 以降）。Safari のままでは受け取れません
- 通知を押すと、その知らせの画面が開きます（既読になります）
- 1分ほど遅れて届くことがあります。溜まっていたときは「新しい通知が N 件あります」の1通にまとめます
- やめるときは同じ欄の「この端末では受け取らない」。**ログアウトすると、その端末では受け取らなくなります**（次にログインしたら、もう一度オンにしてください）
- 「ブロックされています」と出たら、端末の設定でこのアプリ（ブラウザ）の通知を許可してから、画面を開き直してください
- 「まだ使えません」と出るときは、サーバーに通知用の鍵が設定されていません（管理者向けの手順: `docs/saas/adr/ADR-0062-web-push-notifications.md`）

## つながらないとき

| 症状 | 原因と対処 |
|------|-----------|
| **`http://100.76.219.49:8000/` なら開けるのに、名前のURLだと開けない** | ブラウザの**セキュア DNS** が原因です。下の「セキュア DNS を切る」を実行してください |
| 「このサイトにアクセスできません」<br>`DNS_PROBE_FINISHED_NXDOMAIN` | 名前を解決できていません。同上 |
| ページが開かない・タイムアウトする | Tailscale がオフになっています。Tailscale アプリを開いて接続状態にしてください |
| 「この接続ではプライバシーが保護されません」 | URL を打ち間違えています。`https://` から始まっているか確認してください |
| URLの末尾に `）` などが混ざっている | 貼り付け時に余計な文字が入っています。アドレスバーを見直してください |
| 「この社員番号は登録されていません」 | まだ作業員として登録されていません。管理者に依頼してください |
| ログイン後に真っ白 / 画面が崩れる | ブラウザの再読み込み（PC は Ctrl+F5）を試してください |
| 夜間や休日につながらない | サーバーPCの電源が落ちている可能性があります。管理者に連絡してください |

### セキュア DNS を切る

アプリのURL（`…ts.net`）は Tailscale の中にしか存在しない名前で、**外部のDNSサーバーには登録されていません**。
ブラウザの「セキュア DNS」が有効だと、ブラウザはパソコンの名前解決を飛び越えて外部のDNSに直接
問い合わせに行くため、この名前が見つからずアクセスに失敗します。

一度切れば、その端末では以後ずっと名前でアクセスできます。

| ブラウザ | 手順 |
|---------|------|
| Chrome | アドレスバーに `chrome://settings/security` → 「**セキュア DNS を使用する**」を**オフ** |
| Edge | アドレスバーに `edge://settings/privacy` → 「**セキュア DNS を使用して…**」を**オフ** |
| Safari (iPhone/Mac) | 既定では影響しません。設定変更は不要です |

切りたくない場合は、IP指定のURL `http://100.76.219.49:8000/` を使ってください。
どちらも同じアプリで、通信は Tailscale により暗号化されています。

## クイックスタート

### 前提条件

- [Git](https://git-scm.com/)
- [Tailscale](https://tailscale.com/download)（開発環境・本番を開くのに必要。共有アカウント **kec.apps.network@gmail.com** で Google ログイン → [Tailscale に登録する](#tailscale-に登録する)）
- [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Windows / Mac）または Docker Engine + Docker Compose（Linux）
- Python 3.12+（Docker外で開発する場合）

### 1. クローン & 起動

```bash
git clone https://github.com/mstk13/KEM_DDENKI.git
cd KEM_DDENKI/saas

# 環境変数を設定
cp .env.example .env
# .env を編集: DJANGO_SECRET_KEY, DB_PASSWORD, ANTHROPIC_API_KEY 等を設定

# Docker で起動（PostgreSQL + Redis + Django + cron）
docker compose up -d

# マイグレーション実行
docker compose exec web python manage.py migrate

# 管理者アカウント作成
docker compose exec web python manage.py createsuperuser

# Playwright（入札スクレイパー用）のブラウザインストール
docker compose exec web python -m playwright install --with-deps chromium

# ブラウザで開く → http://localhost:8000
```

### 2. Docker外で開発する場合

```bash
cd KEM_DDENKI/saas

# PostgreSQL + Redis だけ Docker で起動
docker compose up -d db redis

# Python 仮想環境
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

# マイグレーション
python manage.py migrate

# 開発サーバー起動
python manage.py runserver
# → http://localhost:8000
```

### 3. 本番デプロイ

**通常は手作業不要です。** `main` にマージすれば、サーバーPCが自動で取り込みます（次項）。

サーバーを新しく立てる場合の手順は [docs/server_operations.md](docs/server_operations.md) を参照してください。

### 4. push したら自動でサーバーに反映される仕組み

サーバーPCが2分おきに GitHub を確認し、更新があれば自分で取り込んで再起動します。
開発者側の操作は **push するだけ** です。

```
developer に push  →  （最大2分）→  開発環境 https://…ts.net:8443/ に反映
main   にマージ    →  （最大2分）→  本番     https://…ts.net/       に反映
```

GitHub からサーバーへ届く必要がないため（サーバー→GitHub の一方向のみ）、
社内PCが NAT の内側にあってもそのまま動きます。Webhook の設定も外部公開も不要です。

- 仕組みと運用: [docs/server_operations.md](docs/server_operations.md)
- スクリプト: [tools/autodeploy/autodeploy.sh](tools/autodeploy/autodeploy.sh)

## 設計原則

| 原則 | 説明 |
|------|------|
| **services.py にロジック集約** | ビューは薄く保ち、将来の Django REST Framework → Next.js 移行に備える |
| **マルチテナント** | TenantModel ベースで会社単位のデータ分離。全テーブルに `company_id` |

| **ロールベース権限** | 社長/役員/現場担当/事務/協力会社/開発者の6ロール × モジュール別 R/W/A |

| **金額は Decimal のみ** | float 禁止。丸め誤差で原価計算が狂うことを構造的に防ぐ |
| **expand/contract マイグレーション** | 破壊的変更を単一リリースで行わない |

```
 └─────────┘  └─────────┘  └──────┘ └──────┘ └────────┘ └──────┘
       ↑                                          │
  cron が2日に1回                        承認→原価自動仕訳
  自動実行
```

各モジュールは独立して使えますが、上の流れで連携すると手作業が大幅に減ります。
落札した案件は自動で現場として登録され、日報の承認は原価トランザクションを自動生成します。

## 自動化・定期タスク

| タスク | スケジュール | 内容 |
|--------|------------|------|
| 入札案件スクレイピング | 2日に1回 朝7時 | i-ppi.jp + 個別サイトから新着案件を取得 |
| 書類アラート送信 | 毎日 朝8時 | 資格期限・健診期限・証明書未提出を通知 |
| 自動デプロイ | 2分おき | GitHub の変更を検知して本番/開発に反映 |
| 日次バックアップ | 毎日 12:30 | PostgreSQL のフルバックアップ |

定期タスクは Docker の `cron` コンテナで実行されます（`docker compose logs cron` で確認可能）。
