# 日報管理（reports）仕様書

バージョン: 1.0
作成日: 2026-08-02
ステータス: ドラフト

---

## 1. 概要

現場の作業員が日々の作業内容・時間・使用材料を記録するアプリ。
作業員本人またはスマホで入力が難しい場合は事務員が代理入力する。
勤怠管理・原価計算・工期進捗の元データとなる。

### 1.1 対象ユーザー

| ロール | 使い方 |
|---|---|
| **作業員** | 自分の日報を入力（スマホ or PC） |
| **事務員** | 作業員の代理入力、一覧確認 |
| **職長** | 現場全体の日報確認、協力会社の日報管理 |
| **社長・役員** | 現場ごとの工数・進捗確認、勤怠集計の閲覧 |

---

## 2. データモデル

### 2.1 DailyReport（日報ヘッダー）

1日・1現場に対して1つの日報レコード。

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| site | FK → Site | ○ | 現場 |
| report_date | DateField | ○ | 作業日 |
| weather | CharField(10) | | 天候（晴/曇/雨/雪/台風） |
| status | CharField(20) | ○ | 下書き / 提出済 / 確認済 |
| memo | TextField | | その他（自由記述） |
| created_by | FK → User | | 入力者（代理入力の場合は事務員） |

### 2.2 DailyReportEntry（作業員別の作業記録）

1つの日報に複数の作業員の記録が紐づく。

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| report | FK → DailyReport | ○ | 日報 |
| worker | FK → Worker | ○ | 作業員 |
| work_type | FK → WorkType | | 工種 |
| work_content | TextField | ○ | 作業内容 |
| start_time | TimeField | ○ | 作業開始時刻 |
| end_time | TimeField | ○ | 作業終了時刻 |
| break_minutes | IntegerField | | 休憩時間（分）デフォルト60 |
| overtime_hours | Decimal(4,1) | | 残業時間（自動計算） |
| note | TextField | | その他 |

**自動計算ロジック:**
- 実作業時間 = (end_time - start_time) - break_minutes
- 通常時間 = min(実作業時間, 8.0h)
- 残業時間 = max(実作業時間 - 8.0h, 0)

### 2.3 DailyReportSubcontractor（協力会社の作業記録）

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| report | FK → DailyReport | ○ | 日報 |
| subcontractor | FK → SiteSubcontractor | | 現場の協力会社（任意） |
| company_name | CharField(200) | ○ | 会社名（自由入力可） |
| headcount | IntegerField | ○ | 人数 |
| work_content | TextField | | 作業内容 |
| note | TextField | | その他 |

### 2.4 DailyReportMaterial（使用材料の記録）

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| report | FK → DailyReport | ○ | 日報 |
| material_name | CharField(200) | ○ | 材料名 |
| quantity | Decimal(10,2) | | 使用量 |
| unit | CharField(20) | | 単位（m, 個, 本 など） |
| note | TextField | | その他 |

### 2.5 SafetyDocument（安全書類の提出管理）

現場ごとに初日に作成する安全書類（KY活動表など）の提出状況を管理。

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| site | FK → Site | ○ | 現場 |
| worker | FK → Worker | ○ | 作業員 |
| document_type | CharField(50) | ○ | KY活動表 / 新規入場者教育 / 作業手順書 / その他 |
| submitted_date | DateField | | 提出日（NULL=未提出） |
| required | BooleanField | ○ | 提出必須かどうか |

**アラート:** 現場に配属されている作業員で `submitted_date` が NULL のものがあれば、
日報入力画面やダッシュボードに警告を表示する。

## 4. 安全書類アラート

### 4.1 アラート表示箇所

- **日報入力画面の上部** — 入力中の現場で未提出者がいれば警告バナー
- **ダッシュボード** — 全現場の未提出件数をバッジ表示
- **現場詳細画面** — 日報タブに未提出者の一覧

### 4.2 アラートのルール

- 現場に配属されている全作業員が対象
- 必須書類（`required=True`）で `submitted_date` が NULL のものを検出
- 書類の種類は現場ごとにカスタマイズ可能

## 5. 勤怠管理との連携

### 5.1 自動集計される項目

| 項目 | 計算元 |
|---|---|
| 出勤日数 | DailyReportEntry がある日数をカウント |
| 総作業時間 | start_time〜end_time - break_minutes の合計 |
| 通常時間 | 8.0h × 出勤日数（上限） |
| 残業時間 | 総作業時間 - 通常時間 |
| 延べ人工 | 1日8h = 1人工として計算 |

### 5.2 給与計算への連携

- 月別の作業員ごとの勤怠サマリーを CSV エクスポート可能
- エクスポート項目: 作業員名、出勤日数、総時間、通常時間、残業時間

## 6. AI読み取り機能

### 6.1 対応する入力

- **写真**: 手書きの日報用紙を撮影 → AIが作業員名・時間・作業内容を抽出
- **テキスト**: LINEやメールの文面を貼り付け → 日報データに変換

### 6.2 処理フロー

1. ファイル or テキストをアップロード
2. Claude API で解析 → JSON形式で作業データを抽出
3. 結果をフォームにプリフィル（自動入力）
4. ユーザーが確認・修正して保存

## 7. 現場管理（sites）との連携

### 7.1 現場詳細の「日報」タブから

- ガントチャート上の日付クリック → その日の日報を表示
- 前日/翌日のナビゲーション
- 日報が無い日は「日報未入力」と表示、入力画面へのリンク

### 7.2 日報入力時

- 現場を選択すると、その現場に配置されている作業員がプルダウンに表示
- 前日の日報データをコピーして入力を効率化するボタン

## 8. 技術メモ

### 8.1 モデル変更

- 既存の `DailyReport` を拡張（`weather`, `memo` 追加）
- `DailyReportEntry` を新規作成（作業員別の開始/終了時刻＋作業内容）
- `DailyReportSubcontractor` を新規作成（協力会社の記録）
- `DailyReportMaterial` を拡張（材料名＋数量＋単位）
- `SafetyDocument` を新規作成（安全書類の提出管理）

### 8.2 レスポンシブ対応

- スマホ: 1カラムレイアウト、カード形式の入力行
- PC: テーブル形式の入力行
- 時刻入力: `<input type="time">` でネイティブ picker を使用

### 8.3 権限

| 項目 | 作業員 | 事務 | 職長 | 社長・役員 |

| 日報一覧・詳細 | 自分のみ | ○ | 担当現場 | ○ |
| 月別集計 | | ○ | ○ | ○ |
