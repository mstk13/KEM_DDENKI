# ADR-0006: 出社予定を勤怠実績と別モデルにする

## ステータス

承認

## コンテキスト

勤怠モジュールは実績しか持っていない。

- `AttendReport` … 1日1現場の勤怠日報（ヘッダ）
- `AttendEntry` … 作業員ごとの出退勤・早出・残業（実績）
- `AttendSettings` … 所定時間などの計算設定

一方で必要なのは「来週・来月、誰がどの日に出るか」の**予定**である。
人繰りと現場配置を先に決めるには、実績が入る前の段階で日付ごとの
在席見込みが一覧で見えなければならない。

隣接する既存モデルとして `schedules.Assignment`（作業員の現場配置期間）があるが、
これは「どの現場に何日から何日まで付くか」であり、
「その日に会社に出るのか、休むのか、直行なのか」は表せない。

## 決定

### 1. `attendance.AttendPlan` を新設し、実績と分離する

作業員1人・1日ぶんで1件。`(company, worker, plan_date)` に一意制約を置く。

同じ行に予定と実績を持たせると、

- 予定のまま実績が入っていない日
- 予定どおり休んだ日

の区別が付かなくなる。実績は日報から後で入るので、確定値がどちらか
分からない表を作らない。

### 2. 予定が無い日は行を作らない

未定はマスを空にして表す。月の全マスに行を作ると、
人数 × 日数ぶんの空行が毎月増えるだけで、読み取れる情報は増えない。

### 3. 時刻は「空＝所定どおり」にし、所定の値をコピーしない

`start_time` / `end_time` は null 許容で、空なら `AttendSettings` の
`standard_start` / `standard_end`（所定時間）どおりとして扱う。
登録時に所定の値をコピーして入れると、あとで所定時間を変えたときに
過去の予定まで書き換わってしまう。画面には既定値として表示するだけで、
DBには「指定なし」を残す。

終了が開始より早い組み合わせは弾かない。夜間工事で日をまたぐ予定があるため。

### 4. 区分は TextChoices で持ち、稼働判定を1箇所に置く

出社／現場／直行直帰／在宅／出張／有休／半休／休み の8種。
このうち `AttendPlan.WORKING_KINDS`（出社・現場・直行直帰・出張）だけを
「その日に稼働する」とみなし、日ごとの出社人数に数える。
画面の凡例もこの定数から組み立て、コードと表示が食い違わないようにする。

### 5. 画面は月グリッドと日シートの2枚。向きを変えて同じデータを編集する

**月グリッド**（`/attendance/plans/`）は「行＝作業員 × 列＝日」。
個人ごとのページに分けると、知りたいこと（その日に何人出るか、
誰が抜けるか）が一覧で見えない。

**日シート**（`/attendance/plans/day/`）は1日を固定して全員を縦に並べる。
月グリッドだけだと、1日ぶんを全員に入れるのに列を目で追うことになり、
「明日は誰がどこへ行くか」を朝礼前に埋める用途に合わない。
逆に日シートだけだと、1人の月の偏り（出張が続く等）が見えない。両方要る。

日シートは1画面＝1フォームで、保存ボタン1回で全員ぶんを upsert / delete する。
マスごとに即保存する月グリッドと違い、こちらは「全員を見ながら決める」画面なので、
途中の状態を保存させない方が使い方に合う。区分を選ぶと行の色と出社人数は
その場で変わるが、DBには保存を押すまで反映しない。

POST の作業員PKは信用せず、自社の在籍者リストを回して突き合わせる。
他社のPKを混ぜて送られても触れない。

月グリッドの入力は3通り。

- **塗る** … 区分パレットで区分を選び、マスをクリック（`plan_set`）。
  同じ区分をもう一度クリックすると消える
- **詳細** … マスをダブルクリックでダイアログ。区分・開始/終了時刻・メモ・削除
- **まとめて記入** … 対象者（1人 or 全員）× 対象日（平日／毎日／曜日）を指定して
  一括で記入・削除（`plan_fill`）
- **日ごと削除** … 日付ヘッダの × でその日を全員ぶん削除（`plan_clear_day`）

日付ヘッダの数字は日シートへのリンクにしてある。
「この日を全員ぶん埋めたい」と思った場所からそのまま移れる。

出社予定は「毎週火曜は現場」のように**曜日で決まる**ことが多い。
そこで一括の対象日に平日・毎日と並べて曜日そのもの（`"0"`〜`"6"` ＝ 月〜日）を
置き、まず曜日単位で埋めてから違う日だけ塗り替える手順にしている。

塗る操作では既存の時刻とメモを引き継ぐ。区分だけ変えたいことのほうが多く、
毎回時刻を入れ直させるとダイアログを開く手間と変わらなくなる。

## 理由

- **一意制約** … 同じ日を二重登録すると出社人数が二重に数えられる。
  塗り替えは常に upsert とし、行が増えないことをDBで保証する。
- **出社人数の再計算を画面側で行う** … 1マス塗るたびに月ぶんを
  サーバで数え直すのは無駄。保存の応答は1マスぶんの結果だけ返し、
  列と行の合計はブラウザで数え直す。
- **稼働区分を定数に集約** … 「在宅は出社人数に入るのか」は運用で揺れる。
  判定を `WORKING_KINDS` 1箇所に置き、変更が集計・凡例の両方に効くようにする。

## 影響

- マイグレーション `attendance/0002_historicalattendplan_attendplan`
  および `attendance/0003_attendplan_end_time_attendplan_start_time_and_more`
- サイドバー「勤怠」グループの先頭に「出社予定」を追加
  （既存項目の並びは変えていない）
- 新規依存なし。
