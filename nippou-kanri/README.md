# 作業日報 自動抽出・勤怠管理システム

作業日報のテキストを貼り付けるだけで、**日付 / 現場名 / 社員名 / 出退勤時刻 / 休憩** を
自動抽出して一覧管理し、社員ごとの **早朝出勤時間・通常勤務時間・残業時間** を自動集計する
Streamlit アプリです。

`mstk13/KEM_DDENKI` の `作業日報` と同じレイアウト構成
(`config.py` / `database.py` / `app.py` / `seed.py` + `.streamlit/`)を踏襲しています。

---

## 3. 自動抽出の対応フォーマット

```text
2026/07/21(火) 現場: A様邸 新築工事
作業内容: 1F配線工事、分電盤取付
田中 太郎 7:30〜19:00 休憩60分
佐藤 花子 出勤 8:00 退勤 17:00
備考: 材料追加発注あり
---
7月22日 現場:B工場 改修工事
作業員: 田中 太郎、鈴木 一郎
8:00-20:30 休憩1時間
```

吸収できる表記ゆれ:

- **日付** … `2026/07/21` `2026-7-21` `2026年7月21日` `7月22日` `7/22` `令和8年7月21日`
- **時刻** … `7:30` `07:30` `7時30分` `7時` / 区切りは `~` `〜` `-` `–` `から`
- **時刻ラベル** … `出勤/始業/開始/IN`、`退勤/終業/終了/OUT`
- **休憩** … `休憩60分` `休憩1時間` `休憩 1.0` `休憩なし`(未記載なら設定の既定値を適用)
- **氏名** … 行頭の `・` `1.` などの飾り、`さん/君/氏`、`(職長)` 等を除去。
  `作業員: A、B、C` のように複数名をまとめて書いた場合は人数分の行に展開
- **区切り** … 空行 または `---` `===` `■■■` / 行頭の日付でも日報が切り替わります

抽出後は表(データエディタ)で自由に修正でき、そのまま登録できます。
日付と社員名が空の行はスキップされ、時刻が欠けている行は警告を表示します。
同じ「日付 × 現場」の日報が既にある場合は追記(重複作成の防止)。

## 4. 勤怠の計算ロジック(⚙️ 設定で変更可)

| 設定項目 | 既定値 | 意味 |
|---|---|---|
| 規定始業時刻 | `08:00` | 手入力時の初期値 |
| 規定終業時刻 | `17:00` | これ以降の実働を残業とする境界 |
| 早朝出勤の境界時刻 | `08:00` | これより前の実働を「早朝出勤時間」として集計 |
| 所定労働時間 | `8.0 h` | 通常勤務時間の上限。超過分は残業へ |
| 既定の休憩時間 | `60 分` | 日報に休憩の記載が無い場合に適用 |
| 時刻の丸め単位 | `0 分` | 0=丸めなし。始業は繰り上げ・終業は切り捨て |
| 残業の判定方式 | 時刻基準 | 時刻基準 / 実働基準(所定超過分のみ残業)を選択 |
| 未登録社員の自動登録 | ON | 日報に出た未登録の氏名を社員マスタへ自動追加 |

**区分の定義**

- **早朝出勤時間** = 早朝境界時刻より前の実働
- **通常勤務時間** = 早朝境界 〜 規定終業時刻の実働(所定労働時間が上限)
- **残業時間** = 規定終業時刻以降の実働 ＋ 通常帯の所定超過分
- 休憩は **通常帯 → 残業帯 → 早朝帯** の順に控除
- 日跨ぎ勤務(例 `22:00〜06:00`)にも対応

計算例(既定設定、休憩60分):

| 出勤 | 退勤 | 早朝 | 通常 | 残業 | 合計 |
|---|---|---|---|---|---|
| 06:00 | 20:30 | 2.00 | 8.00 | 3.50 | 13.50 |
| 08:00 | 17:00 | 0.00 | 8.00 | 0.00 | 8.00 |
| 08:00 | 16:00 | 0.00 | 7.00 | 0.00 | 7.00 |
| 22:00 | 06:00 | 6.00 | 0.00 | 1.00 | 7.00 |

> 規定時間を変更したら、⚙️ 設定の **「🔄 全件を再計算する」** で過去データにも反映できます。

## 5. ファイル構成

```
nippou-kanri/
├── app.py             Streamlit UI(6画面)
├── config.py          設定の既定値 + 勤怠の区分計算ロジック
├── database.py        SQLite スキーマと CRUD・集計・再計算
├── extractor.py       日報テキストの自動抽出エンジン
├── seed.py            デモデータ投入
├── requirements.txt
├── .env.example
├── .streamlit/config.toml
└── ../data/nippou_kanri.db  SQLite(data/フォルダに自動生成)
```

### テーブル

| テーブル | 役割 |
|---|---|
| `employees` | 社員マスタ(コード・氏名・カナ・部署・役職・在籍) |
| `reports` | 日報ヘッダ(日付・現場・作業内容・備考・ステータス・抽出元テキスト) |
| `entries` | 社員別の勤怠明細(出退勤・休憩・早朝/通常/残業/合計 の分数) |
| `settings` | 規定時間などの運用設定(key-value) |

時間は分単位の整数で保存し、画面では時間(h)に換算して表示します。

## 7. 別アプリ(作業日報)との連携

`KEM_DDENKI/sagyo-nippou` は独立した DB（`data/sagyo_nippou.db`）を持つため、そちらで日報を登録しても
このアプリには**自動では反映されません**。🔄 別アプリ連携 画面で取り込みます。

| 向こう(作業日報) | こちら(作業日報管理) |
|---|---|
| `reports.report_date` | `reports.report_date` |
| `sites.name` | `reports.site_name` |
| `reports.work_content` | `reports.work_content` |
| `reports.manager` | `reports.note`(現場代理人/責任者) |
| `report_workers.worker_name / start_time / end_time` | `entries` の1行 |
| `workers`(作業員マスタ) | `employees`(社員マスタ) |

- **重複しません**: 元の日報 ID を `reports.source_key`(`sagyo:report:12`)に記録し、
  2回目以降の取り込みは上書き更新になります。
- **取込元には書き込みません**(読み取り専用で接続)。
- 向こうは休憩時間を保持していないため、取り込み時に指定した休憩(既定 60 分)を
  一律で控除し、**このアプリの規定時間ルールで早朝/通常/残業を計算し直します**。
- 取り込んだデータだけを後から削除することもできます(手入力分は残ります)。

コマンドラインからも実行でき、タスクスケジューラに登録すれば自動同期になります。

```powershell
py -3 importer.py                        # 全期間
py -3 importer.py 2026-07-01 2026-07-31  # 期間指定
```
